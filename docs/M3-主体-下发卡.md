  runGrowth = { startAtk: player.atk, startLevel: player.level };  // 在 recalcEquip 之后记录

getRunGrowth: function () {

## 1.4 「下一突破」的算法（不许写死 2450 之外的第二个常量）

```js
var need = 0;
for (var lv = 1; lv <= 10; lv++) need += Battle.expToNext(lv);   // = 150 + 2100 + 200 = 2450
var have = Player.exp;
for (var lv2 = 1; lv2 < Player.level; lv2++) have += Battle.expToNext(lv2);
```

- `Player.level < 11`：`还差 (need - have)`；若 `have >= need` 但未到 11（理论上不可能），显示 `可突破`。
- `Player.level >= 11`：`已突破：攻击 +9 · 防御 +4 · 生命 +20`（读 `GROWTH.milestones[11]`，不写死 9/4/20 之外的第二份）。

**代价（写清，不粉饰）**：低攻/低练度路线失去了“回合数保证”，只剩龙威的固定节奏兜底；如果将来要恢复比值判据，必须**同时**改龙血与龙威，不允许只调阈值或只把 d66 改回活值。
