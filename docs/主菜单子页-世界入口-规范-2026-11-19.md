## 实测修订（2026-11-20）

> 本节由 D-129 文档对账追加，**正文数字一律未改**；只记录「规格原文 → 实测 → 最终落地 → 为什么」，作为 D-128 执行端与 `preflight/verify_d128.html` 的口径对照。
> 实测环境：Edge headless；视口 320×568 / 390×844 / 960×540 / 1024×640 / 1280×800；素材就绪、`R._menuNoAnim=true` 的稳态帧；绘制调用由 28 个 Canvas 2D 方法计数器统计，文字层参与计数。

**1. §2.1 / §5 改前预算 110 / 45 / 22 / 50，改后估算 122 / 59 / 30 / 66，每页新增 ≤20**
- 实测：960×540 稳态帧改前 **602 / 216 / 209 / 232**（玩法说明 / 设置 / 确认 / 关于）；改后 **120 / 112 / 87 / 107**，增量 **−482 / −104 / −122 / −125**；五档最大 144（1280×800 玩法说明）。
- 落地：验证页以改前实测常量为负例（四页全部 >214），正例按「每帧 ≤214 且不高于改前 +20」判定。
- 为什么：旧实现每帧按格重画——共享背景网格 188 次 `stroke`、竖井 338 次 `drawImage`，规格的估算只算了新增构件，没算既有底图。把网格改为 47 次 1px `fillRect`、竖井改为静态烘焙后，整帧值下降；「新增 ≤20」在改前已超 214 的前提下不再是独立红线。

**2. §5「不得新增离屏画布」**
- 实测：新增 1 块 `shaftCache`（玩法说明竖井静态烘焙），另沿用既有 `menuSceneCache`。
- 落地：保留该缓存；烘焙只含岩壁 / 地面 / 暗缝等图形，F1–F5 刻度与 BOSS 文字仍每帧直绘。
- 为什么：不砍剖面、不改画面的前提下，只有烘焙能把 960×540 的 602 次调用压到 214 以下。像素等价与静止帧稳定分别由 M7、M8 验证。

**3. §2.1 / §4 / §8 紧凑档「底部 48px 龙」；§5「所有精灵必须 24×24 原生」**
- 实测：`dragon_idle_anim_f0` 原生 **72×72**；48px 需要 0.67×。
- 落地：**72×72 1×**，紧凑档竖井替身整块约 **226px**。
- 为什么：0.67× 违反 M8 的整数倍硬线；226px 仍落在 960×540 的约 392px 可用高内，不必再砍。

**4. §2.3「skull 16×16」**
- 实测：`skull` 素材原生 **24×24**。
- 落地：**24×24 1×**，放在标题左侧 `(x+16, y+18)`。
- 为什么：16×16 需要 0.67×；24×24 正好满足 M2 的「≥24×24 实物锚」。

**5. §2.4 / §6 M9「t1_wall_mid」**
- 实测：素材名是 **`wall_mid`**，素材表里没有 `t1_wall_mid`。
- 落地：`wall_mid` 24×24 ×2 + `t1_dc_rubble` 1×。
- 为什么：`Sprites.get('t1_wall_mid')` 取不到图会静默失败，M9 的墙脚与实物锚都不成立。

**6. §6 M3 负例「回放现状关于页（无高度钳制）→ 960×540 底边越界」**
- 实测：改前关于页在 960×540 底边**没有越界**，原负例不会红。
- 落地：负例换成「旧口径自然高 + 多两行内容、无底部钳制」的复刻矩形，960×540 底边必越界。
- 为什么：原负例前提在当前代码不成立；换的是夹具，不是放宽断言。

**7. §6 M5 负例「行高仍 54 → 第 6 行被裁」**
- 实测：960×520、6 行、行高 54 时卡高 410 < 504 可用高，6 行**仍全可见**。
- 落地：负例换成「卡高按 5 行算（66+5×54+20）、实际画 6 行 54 高」→ 第 6 行被裁。
- 为什么：同第 6 条，原前提不成立。

**8. §6 M6 负例「设置页每行加火把 +6 与整行描边 +12 → 超增量」**
- 实测：改后设置 112，加 18 后 130，仍 ≤214 且低于改前 216，**不会红**。
- 落地：负例改用「改前实测 602 / 216 / 209 / 232 全部 >214」。
- 为什么：原负例在整帧口径下不再越线。

**9. §2.1「页头带高 62」；§4 compact「62→54」**
- 实测：`bodyTop = y+66`；compact `y+58`。
- 落地：**66 / 58**（标题仍在 `y+42`，compact 只把正文上提 8px）。
- 为什么：kicker 10px 在 `y+18`、标题 22px 基线 `y+42`、分隔线 `y+52`，62 会把正文压到分隔线上；字号阶梯未动。

**10. §2.1「火把 24×24 ×2（48×48）」**
- 实测：**24×24 1×**，位置 `(x+16, y+18)`。
- 落地：1×。
- 为什么：48×48 会压住 kicker / 标题带；实物锚只要求 ≥24×24，M8 允许 1×。

**11. §2.3 确认页几何「按钮 170×34 / 窄档 104×34；封蜡缺口 6×8；石板底 6px」**
- 实测：按钮高 **36（compact 32）**、宽 `min(170, (cardW−88)/2)`；封蜡缺口 **6×5**；按钮底暗面 **3px**。
- 落地：按实测；960×540 为 **170×32**，320 档为 96×32，390 档为 131×32。
- 为什么：34 与 §4「按钮区 40→32」冲突；8 高缺口会切到标题带；6px 石底在 32 高按钮上占比过大。

**12. §5「每帧新增 drawImage：关于 +2，其余 +0–2」**
- 实测：关于 **+3**（2×`wall_mid` + `rubble`）、设置 **+2**、确认 **+1**、玩法说明紧凑档 **+9**（3 装饰 + 5 层徽 + 72×72 龙）。
- 落地：按实测；M8 只约束整数倍与整数坐标，不限制张数。
- 为什么：§2.4 自身已列 `rubble`，§4 compact 又要求五徽 + 龙，原「+0–2」与规格内部冲突。

**13. §4 mid「竖井宽度缩到 ≥240，否则隐藏」**
- 实测：竖井只在 `cardW ≥ 840`（W≥864）且 `H≥620` 时出现；其余单一列、不出图。
- 落地：按实测断点。
- 为什么：档位只认 `_menuTier`；mid 半宽竖井会把正文列压到 300 以下，且没有对应判据。

**14. §4 compact「上下留白 20→10」**
- 实测：玩法说明卡 `y=24`、`cardH=H−48`（上下各 24）。
- 落地：**24**。
- 为什么：收到 10 只多 28px，却让页头 / 提示贴边；竖井替身已按 226px 放进可用高，无需再挤。M3 只要求 ≥8。

**15. §2.1「正文列宽 ≤46%，文字宽 ≤420」**
- 实测：卡宽 880 时正文列 420px = **47.7%**（起点 x+52，右缘 x+472）。
- 落地：以 **420px** 绝对上限为准。
- 为什么：46% 与 420 在 880 卡宽下不能同时成立；同句给出的绝对上限更可执行。

**16. §2.2 / §3「值切换 80ms 2px 位移、选中迁移 90ms、滚动 120ms 缓出」**
- 实测：**只实现了 100ms 落位**；值切换、选中迁移、滚动均为单帧生效。
- 落地：按实测口径记录，未补写这三段动效。
- 为什么：D-128 的硬判据是「静止两帧同哈希、无循环动效」（M7）与「单次动效 ≤120ms」；补 80/90/120ms 会引入额外时钟分支，本卡未做。若封版要求补齐，应另开卡。

## 0 先纠正一个事实：真正的四个子页

主菜单（`Main.shouldShowMenu()` 为真时由 `drawMainMenu()` 绘制）只有四个子页。你括号里猜的「武器/图鉴/任务/装备」不在这里——那是游戏内 **M 面板**（`modal.js` 的 quests 四页：任务 / 怪物图鉴 / 物品图鉴 / 系统），本次不覆盖。

| 页面 | 进入方式 | 状态值 | 渲染入口 | 内容来源 |
|---|---|---|---|---|
| **玩法说明** | 主菜单第 3 项 | `menu.page = 'help'` | `_drawMenuHelp`（`render.js:5298`）、`_drawHelpSection`（`5397`） | `main.js` 的 `HELP` 数组，8 组 `01–08` |
| **设置** | 主菜单第 4 项 | `'settings'` | `_drawMenuSettings`（`5498`）+ `_drawSettingsRows`（`4459`） | `_settingsRows()`（`main.js:1115`），当前 5 行；§19 落地音乐开关后 6 行 |
| **确认** | 新游戏覆盖 / 删除存档 | `'confirmNew'` / `'confirmClear'` | `_drawMenuConfirm`（`5525`）+ `_drawConfirmPanel`（`4523`） | `confirmData()`（`main.js:145` 起），两种文案 |
| **关于** | 主菜单第 5 项 | `'about'` | `_drawMenuAbout`（`5642`） | 页内静态表 5 行 + 门徽 |

**「卡片当皮肤」的根因是代码结构，不是配色**：四页全部调同一个 `_menuPageCard(x,y,w,h,kicker,title,right,danger)`（`render.js:5106`），这个函数只提供「底 `#07080e` + 1px 边 `#3a3340` + 金色分隔线 + mono kicker + 雅黑标题」。四页的差别只剩标题字符串，所以缩略图不可分。

**现存的另外三个硬问题**：

1. `_drawSettingsRows` 只按 `rowH` 排，没有高度钳制；`_drawMenuAbout` 的 `cardH` 由内容自然撑开，`H<620` 时没有回退分支，卡片可能越出视口底边（`y = max(16, (H−cardH)/2−8)`，下半截不设限）。
2. 玩法说明的五层竖井只在 `cardW ≥ 840` 时出现（`split`），960×540 恰好被砍掉——「剖面图」这个最强的意象在最常用的桌面档消失。
3. 四页都没有「实物」：第一眼全是文字，没有一件能被认出来的东西。

## 1 共用前提（四条，防止又变成四套皮肤）

### 1.1 一个介质，不是一张卡

四页共用**同一套「介质」边缘**，但介质里的「实物」各页不同。介质 = 下列五件事，全部纯矩形 / 既有素材，无新贴图：

| 介质构件 | 参数 | 来源 |
|---|---|---|
| 底 | `#0a0b12`（比现状 `#07080e` 抬 1 级，给纹理留一点余量） | 既有深色系 |
| 沿口 | 1px `#2b2440` | §16.2 第 1 条（地图沿口同色） |
| 接触阴影 | 4px `#040407`，只在介质外侧下、右 | §16.2 第 2 条 |
| 石钉 | 4×4 纯矩形，`#3a3340` + 1px 左上受光 `rgba(178,158,220,0.10)` | §17「只加深」规则 |
| 暗角 | 沿用 `_menuVignette`（`5141`） | 现状 |

**禁止**：整页铺 `t1_wall_*` / 岩壁 480 贴图。§16 的岩框语义是「地图之外」，铺到菜单会读成一张地图（见 §7.2）。

### 1.2 每页必须有一个实物锚

「实物锚」定义：一块 ≥ 24×24、非文字、可被单独裁出来的图形，位于标题水平带附近（距离标题基线 ≤ 48px），且不遮挡标题。

- 允许：`drawImage` 既有 24×24 / 48×48 / 16×16 精灵（整数倍）；允许纯矩形拼出的门徽（现状关于页已有）。
- 不允许：新绘制一整套插画、用文字冒充实物锚。

### 1.3 借用表：只用 §14–§18 已有的语言

| 既有规范 | 本规格怎么用 | 明确不用 |
|---|---|---|
| §14 读数分工 | 菜单页不引入任何「测量读数」；设置页右端的值是设置值，不加 `ATK` 式读数带 | 不把菜单变成仪表盘 |
| §15 四类统一语法 | 只沿用「一个类别一个色、同类同色」：危险 `#ff9b6b`、确认 `#ffcf6e`、导航 `#9bbbf4` | 菜单没有格子，不画格内类别内框 |
| §16 岩框 | 只取「沿口 1px + 4px 接触阴影」两层，用于介质外缘 | 不搬 480×480 岩壁贴图、不做向内 150px 收光 |
| §17 砌筑 / 土地 | 只取「正交砌缝 = 人造石」与「45° 刮痕 = 被踩过的软质」两种方向语言，用在 ≤12px 的边条上 | 不铺满、不改变方向语言的分工 |
| §18 窄档 | 词写完整（「画面缩放」不缩成「缩放」）；字号阶梯不动 | 不用 9px 以下正文、不靠缩字硬塞 |
| §19（音乐规格） | 设置页可能新增「音乐」开关行，本规格按 **5–6 行**设计 | 不新增第二条滑块 |

### 1.4 断点与 `_menuLayout` 的对应关系

子页**不复用 `_menuLayout` 的坐标**——那是首屏「场景 + 右栏菜单」的布局，硬套会把子页挤成右栏。

只抽一个纯函数共用断点：

```js
// render.js，与 _menuLayout 同文件
_menuTier: function (W, H) {
  return {
    tier: (W >= 900) ? 'wide' : ((W >= 480) ? 'mid' : 'narrow'),
    compact: H < 620
  };
}
```

- `_menuLayout` 内部的 `tier` / `compact` 两行改为调用它，**输出必须逐字段不变**（用 `preflight/verify_d93.html`、`preflight/verify_d60.html` 回归；这两页断言了首屏布局坐标）。
- 四个子页全部改用 `_menuTier(W,H)`，从而与首屏共享同一套断点，不再各写 `W<420` / `cardW>=840` 之类的第二套阈值。
- 现状里 `narrow = W < 420` 的写法保留为「子页内部排版微调」，但**档位判定只认 `_menuTier`**。

## 2 逐页视觉叙事与绘制规格

### 2.1 玩法说明 —— 石壁上的地牢剖面图

**一句话**：玩家看到的是一张钉在石壁上的地牢剖面图，左边是刻在图纸上的操作条目，右边是一条一直通到龙巢的竖井。

**意象与素材**（全部既有）：

| 构件 | 实现 |
|---|---|
| 图纸 | 介质底 `#0a0b12` + 顶部一条 1px 金色分割（现状保留） |
| 石钉 | 4 颗 4×4，钉在图纸四角内侧 8px |
| 照明 | `t1_dc_torch` 24×24 × **2**（48×48），放在介质左上外侧，不压文字 |
| 边缘杂物 | `t1_dc_chain` 1×（24×24）贴右侧沿口；`t1_dc_rubble` 1× 贴左下角 |
| 竖井 | 沿用 `_drawHelpSection`：`t1_*`–`t5_*` 岩壁/地面 1×、F5 地面 2×、`dragon_idle_anim_f0` 1× |

**分区与图层顺序**（宽档 W≥900）：

1. 背景网格 + 暗角（现状 `4597–4609` / `5141`）
2. 介质底 → 沿口 → 接触阴影（下、右）
3. 石钉 ×4、火把、铁链、碎屑
4. 页头带（高 62）：kicker `CODEX / CONTROLS`、标题「玩法说明」、右端 `01–08`
5. 正文列（左，宽 ≤ 46%，文字宽 ≤ 420）：8 组，组号 mono 11、标题 14 粗、正文 13
6. 竖井（右，宽 ≥ 300）
7. 滚动条（2px，仅需滚动时）
8. 底部提示（11px mono）

**动效**：进入 100ms「落位」——整块介质从 `y−2` 落到 `y`，沿口 alpha `0.6 → 1`；滚动 120ms 缓出；**无循环动效**。

**接入点**：`_drawMenuHelp`（5298）保留文字排版，把 `_menuPageCard` 调用换成介质绘制 + 页头带；`_drawHelpSection` 签名不变。

**预算（估算，直绘口径）**：结构 8 + 文字约 58 + 竖井约 48 + 装饰 6 ≈ **120**；改前约 110。上限 214，余量充足。

### 2.2 设置 —— 石壁上的机关阀盘

**一句话**：玩家面对的不是一列设置项，而是一块嵌在石壁里的机关面板：每行是一个刻槽，右端是一个可以拨动的阀值。

**意象与素材**：

| 构件 | 实现 |
|---|---|
| 竖向石缝 | 2px 深色缝 `#05060a` + 1px 左侧受光 `rgba(178,158,220,0.08)`，从页头贯穿到页脚（§17 F1 的正交砌缝语言，只用一条） |
| 刻槽 | 每行左端 3px 槽，选中时槽底亮到 `rgba(255,207,110,0.22)`，不整行铺色 |
| 阀值 | 右端 78×18 直角框（1px `#3a3340`），值是 mono 12；选中时框线换 `#ffcf6e` |
| 照明 | `t1_dc_torch` 1×（24×24）放在介质左上外侧 |
| 底部碎屑 | `t1_dc_rubble` 1× 贴左下 |

**分区与图层顺序**：

1. 背景网格 + 暗角
2. 介质 + 沿口 + 接触阴影
3. 竖向石缝（2px）
4. 每行：刻槽 → 行标签（15px）→ 说明（10px，仅选中行显示）→ 阀值框 + 值（mono 12）
5. 页头带（kicker `SYSTEM`、标题「设置」）
6. 卡外底部提示（11px mono，现状保留）

**关键改动**：**删掉整行填充式选中**（现状 `4481–4485` 填充 + 2px 描边），改为「左槽提亮 + 行底 1px 刻线」；全页只保留阀值框这一处矩形焦点，避免「卡中卡 + 选中框」两层。

**动效**：切换值时阀值文字 80ms 内横向 2px 位移（整数像素）；选中迁移 90ms 内槽底 alpha `0.10 → 0.22`。

**接入点**：`_drawSettingsRows`（4459）改造；`_drawMenuSettings`（5498）只换介质与页头，`_drawSettingsRows` 仍被暂停页复用（`drawPause:5589`），因此新样式通过参数 `style: 'menu' | 'pause'` 分流，**暂停页保持现状**。

**预算**：结构 8 + 6 行 × 7 + 提示 1 ≈ **51**；改前约 45。

### 2.3 确认 —— 石桌上的判决石板

**一句话**：玩家看到的是一块压在石桌上的判决石板，危险动作用凿刻的字写在石面，两块压石是「取消」与「执行」。

**意象与素材**：

| 构件 | 实现 |
|---|---|
| 石板厚度 | 底边 6px `#05060a` + 外侧 4px 接触阴影，制造「放在桌上」的厚度 |
| 凿刻 | 正文 13px 保持 `#cfcfcf`；危险词用 `#ff9b6b`（现状保留） |
| 封蜡条 | 顶部 3px `#ff9b6b`（现状），两端各加 6×8 的缺口（纯矩形），读成封条而不是进度条 |
| 压石按钮 | 170×34（窄档 104×34）：底 3px 暗边 + 1px `#3a3340` 边；焦点换 2px `#ffcf6e` |
| 骨饰 | `skull` 16×16 × 1，放在标题左侧 8px 处 |

**图层顺序**：背景 → 介质 → 石板厚度 → 封蜡条 → 标题 + 骨饰 → 正文行 → 压石按钮 → 提示。

**动效**：进入 100ms 落位；危险条不做呼吸、不做闪烁。

**接入点**：`_drawMenuConfirm`（5525）换介质；`_drawConfirmPanel`（4523）只加 `style:'menu'` 分支，暂停页确认（`5597`）不受影响。

**预算**：结构 10 + 标题 2 + 正文 4 + 按钮 8 + 提示 1 ≈ **25**；改前约 22。

### 2.4 关于 —— 门楣铭牌

**一句话**：玩家看到的是入口门楣上的一块铭牌：左侧是那扇门，下面是刻着操作方式的铭文，铭牌底部砌在墙里。

**意象与素材**：

| 构件 | 实现 |
|---|---|
| 门徽 | 保留现状 48×48 纯绘制门（`5694–5713`），不换贴图 |
| 铆钉 | 4 颗 4×4，钉在铭牌四角内侧 8px |
| 墙脚 | 卡片底 24px 内铺 `t1_wall_mid` 24×24 × **2**（48×48 裁切），只允许这一条；上方压 1px `#2b2440` 收口 |
| 浮尘 | `t1_dc_rubble` 1×，贴在墙脚左上 |

**关键改动**：墙脚是「铭牌嵌进墙」的唯一证据；**除这 24px，卡片其余区域不得出现任何地块贴图**（见 §6 判据 M9）。

**图层顺序**：背景 → 介质 → 墙脚（裁切在卡内）→ 沿口 → 铆钉 → 门徽 → 标题 / 副题 / 标语 → 金色分隔线 → 键帽表（5 行）→ 目标 / 存档说明 → 提示（提示基线上移到墙脚上方 6px）。

**动效**：仅 100ms 落位，无其他。

**接入点**：`_drawMenuAbout`（5642）内部加介质与墙脚；键帽表与文本结构不动。

**预算**：结构 12 + 门徽 10 + 文本 12 + 键帽表 20 + 提示 1 ≈ **55**；改前约 50。

## 3 动效规则（四页共用，硬性）

| 规则 | 数值 |
|---|---|
| 进入落位 | 100ms，位移 2px（整数），沿口 alpha 0.6→1 |
| 选中迁移 | 90ms |
| 值切换 | 80ms，位移 2px |
| 滚动 / 翻页 | 120ms 缓出 |
| 单次动效总时长 | ≤ **120ms** |
| 无限循环动效 | **禁止**（呼吸、闪烁、粒子、视差全部不做） |
| 时间源 | `st.now`（验证页可注入）优先，否则 `performance.now()`；**不得使用 `Math.random`** |

理由：菜单是「翻东西」的入口，动效只负责「东西落到位」，不负责表演；循环动效会在菜单停留时持续重绘且分心。

## 4 窄档回退矩阵

档位由 `_menuTier(W,H)` 给出；字号阶梯**一律不变**（正文 13，窄档 12，标题 22 / 窄档 20，kicker 10，提示 11）。

| 页面 | `mid`（480≤W<900） | `narrow`（W<480） | `compact`（H<620）叠加 |
|---|---|---|---|
| 玩法说明 | 单列；竖井宽度按剩余空间缩到 ≥ 240，否则隐藏 | 单列；隐藏竖井；正文 12px；8 组全部走滚动 | 页头 62→54，上下留白 20→10；竖井替换为「五枚 24px 层徽 + 2px 竖线 + 48px 龙」，高约 200（见 §8） |
| 设置 | 卡宽 ≤ 560 居中，行高 54 | 卡宽 `W−24`，行高 50，说明只在选中行显示 | 行高 **46**；6 行 × 46 = 276，卡高 ≈ 350，`520` 高视口仍完整可见 |
| 确认 | 卡宽 ≤ 460，按钮并排 | 卡宽 `W−40`，按钮宽 `(卡宽−88)/2` | 按钮区 40→32；`lineH` 与字号不变 |
| 关于 | 自然宽度 ≤ 560 | 卡宽 `W−24`；副题另起一行（现状保留） | 隐藏「零构建…」标语与存档说明两行；门徽与键帽表 5 行不动 |

**硬性禁止**：

- 不得用缩小字号换取空间（`H<620` 只允许减留白、减装饰、减非关键行、换表达）。
- 不得把多行内容压成一行截断（`…` 截断只允许出现在设置页的行内说明，且只在 `mid` 及以下）。
- 不得让卡片底边越过 `H−8`；越界时优先砍装饰，其次砍非关键行，最后才启用页面内滚动。

## 5 预算

口径沿用 D-108 / D-111 的**静态 UI 最坏帧 ≤ 214**，本规格把它扩为「子页每帧 ≤ 214」；每个子页**新增 ≤ 20**。

| 页面 | 改前（估算） | 新增 | 改后（估算） | 上限 |
|---|---|---|---|---|
| 玩法说明（宽档，含竖井） | 110 | +12（石钉 4、火把 2、铁链 1、碎屑 1、沿口 2、阴影 2） | **122** | 214 |
| 设置（6 行） | 45 | +14（石缝 2、刻槽 6、阀值框 6） | **59** | 214 |
| 确认 | 22 | +8（厚度 2、封条 2、骨饰 1、沿口 2、阴影 1） | **30** | 214 |
| 关于 | 50 | +16（墙脚 8、铆钉 4、沿口 2、阴影 2） | **66** | 214 |

- 以上为**执行端口径的估算**；落地时必须用 D-108 的计数器实测并在回执里报「改前 / 改后 / 增量」三列。
- 每帧新增 `drawImage`：关于页 +2（墙脚两格），其余页 +0–2；不得新增离屏画布。
- 所有精灵必须 24×24 原生、整数倍（1× 或 2×），坐标取整。

## 7 不建议做的

1. **四页各换一套背景纹理**——立刻变成四个游戏；背景只有一套（网格 + 暗角），差异只发生在介质与实物锚上。
2. **整页铺岩壁/地块贴图**——§16 的岩框语义是「地图之外」，铺到菜单会被读成一张地图；只允许关于页底部 24px 墙脚。
3. **给设置页每行加图标**——6 行 6 个图标既超预算，又把「机关槽」读成「列表装饰」。
4. **无限循环动效**——呼吸光、闪烁、粒子；菜单停留时不重绘才是对的。
5. **用缩字号解决窄档**——`H<620` 只减留白、减装饰、减非关键行，或换表达。
6. **新增素材、网络字体、远程纹理**——`file://` 双击必须可玩。
7. **顺手把 M 面板四页一起改**——范围外，且 M 面板有 4 页 × 滚动 × 图鉴，风险不可控。
8. **用 `Math.random` 摆放装饰**——会破坏像素稳定与验证可复现。

## 8 风险：最可能做不出来的一处

**玩法说明页在 960×540（`compact`）时，「图纸 + 五层竖井」同时成立。**

竖井现有高度是 `84×4 + 144 = 480px`，而 `H=540` 下可用内容高约 `540 − 20×2 − 54 − 34 ≈ 412px`，放不下。三条路里：

- 缩字号硬塞：违反 §18 与 §4 的硬性禁止；
- 直接隐藏竖井：退回「文档」，等于本规格没做；
- **换表达**（推荐）：`H<620` 时竖井改为「五枚 24px 层徽竖排 + 一条 2px 竖线 + 底部 48px 龙」，总高约 `5×24 + 4×8 + 48 = 200`，仍读作「向下」，字号一个不动。

这条是硬要求。如果执行端在 960×540 下拿不出 200px，说明左侧文字列没按 §4 收紧留白，应先改排版而不是砍剖面。
