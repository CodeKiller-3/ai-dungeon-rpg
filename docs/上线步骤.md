## 五、Pages 生效时间与"缓存伪影"判断

### 生效时间

- 普通静态 Pages：push 后 **1–3 分钟**常见，偶发 **5–10 分钟**。
- 看仓库 **Actions → pages build and deployment**：最后一次 run 变绿、且 commit 是新 HEAD，才算构建完成。
- 也可以在 **Settings → Pages** 看到 "Your site is live at …" 的最近构建时间。

### 项目里的 `?v=<commit>` 口径

打开页面时在 URL 后加 `?v=<短 hash>`，例如：

```text
https://codekiller-3.github.io/ai-dungeon-rpg/index.html?v=2aba50c
```

它有两个作用：① 作为"我看的是哪个 commit"的人工标记；② 让**HTML 本身**绕过缓存。
**注意**：本项目的 `<script src="js/...">` 都是不带查询串的相对路径，所以 `?v=` **不会**自动刷新子资源。D-26 就实测过"HTML 已新、`js/core/render.js` 还是旧版"的缓存伪影。

### 判断真假新版（按顺序做）

1. **看构建**：Actions 最后一次 Pages 部署的 commit 是否等于 `git rev-parse HEAD`。
2. **看 HTML**：`view-source:` 查 `<title>地牢：我独自升级</title>`；`?v=` 换成新 hash 再刷新。
3. **看新资源**（关键，绕开子资源缓存）：
   ```powershell
   $v = git rev-parse --short HEAD
   Invoke-WebRequest "https://codekiller-3.github.io/ai-dungeon-rpg/js/systems/juice.js?v=$v" -UseBasicParsing |
     Select-Object StatusCode, @{n='HasJuice';e={$_.Content -match 'Game\.Systems\.Juice'}}
   ```
   期望 `200 / True`。D-43 没有这个文件，线上会 404。
4. **比哈希**（最硬）：
   ```powershell
   (Get-FileHash .\js\systems\juice.js -Algorithm SHA256).Hash
   # 下载线上同名文件后 Get-FileHash，两者应一致
   ```
5. **换通道**：DevTools → Network 勾 "Disable cache" 硬刷新；或手机热点/另一台机器再开一次。
6. **看响应头**：`age`、`etag`、`last-modified`、`x-cache`；`age` 很大说明命中了边缘缓存，等 5–10 分钟再试。
7. **别用"标题变了"当唯一证据**：D-26 的伪影就是 HTML 新、JS 旧——标题新但玩法还是旧的，比全旧更有欺骗性。

## 七、存档兼容

前提：**`file://` 本地与 `https://codekiller-3.github.io` 的 localStorage 不互通**。下面说的"老存档"指同一个线上 origin 下、D-43 时期写入的存档。

### 旧 → 新（D-43 的档 → D-74）

- **能读**：`SAVE_VERSION` 都是 2，`save.js#load` 按字段逐个兜底；缺 `npcQuests` 补 `{}`、缺 `adaptive` 走 normalize、缺 `eliteAtk` 补 0、缺 `run/ending` 标 unknown/null。
- **地图**：`importState` 只校验网格结构，不校验尺寸；旧档的小地图会被原样恢复。旧档快照没有 `npcs/elites` 字段时，`generate` 会用**快照自己的宽高**补生成 NPC 与精英并写回缓存（`map.js` L1288-1303），不会越界。
- **代价**：D-64 的"每层 +4"只对**新生成**的楼层生效，旧档当前层仍是旧尺寸；如果快照结构不合法，会降级重建一次地图并提示"存档地图数据不可用，已重建一次"，之后固化。
- **结论**：**可读、不崩、不丢等级/金币/背包**；旧尺寸地图与一次重建是预期行为。
- 证据等级：**静态分析**（`js/systems/save.js` L67-181、`js/systems/map.js` L1271-1306、L1601-1621）。**未做**旧档实测。

### 新 → 旧（D-74 的档 → D-43）

- **能读**：旧 `save.js` 也是 v2，会忽略不认识的字段（`eliteAtk/npcQuests/adaptive/run/ending`）。
- **会丢**：D-71 的精英武器在 D-43 的 `ITEMS` 里不存在，`recalcEquip` 会把它当 0 攻击（`inventory.js` L122-127 的 `w ? … : 0`），**刀还在装备栏但加成归零**；NPC 任务、自适应历史、本局统计、结局记录全部丢失。
- **地图**：旧代码的 `importState` 同样只查结构（`git show 92dba9a:js/systems/map.js`），大网格会被接受；旧代码没有精英/NPC 字段，会忽略。是否能完整渲染**未实测**。
- **结论**：不崩的概率高，但会静默丢新内容；**不建议降级**。真要回退，先让玩家导出 `ai_dungeon_rpg_save_v1`。
