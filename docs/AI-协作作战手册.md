# AI 协作开发作战手册（豆包 × Trae CN × 黄文博）

> 适用范围：《AI勇者闯地牢》S3 界面定稿 → M8 内容 → M9 表现 → M10 AI 原生 → 收尾交付。
> 原则：**豆包指挥、Trae 执行、你（黄文博）传令与验收，GitHub 是唯一的交接黑板。** 每个模块固定流程，打磨到 PASS 即止。

---

## 1. 工具链全景（谁干什么）

| 工具 | 角色 | 能干什么（明确边界） | 不能干什么 |
|---|---|---|---|
| **豆包（本对话 = 我）** | 总指挥 / 总工程师 | 拆模块、写任务卡（含接口契约与效果判据）、审查 Trae 产出、跑验证（headless+试玩检查单）、裁定 PASS/打回、规划与答辩材料、指挥调度 | 不直接改项目代码（验证、文档、规划除外）；不替你向 Trae 传话（你自己传，我来给话术） |
| **Trae CN**（内置豆包1.5Pro+DeepSeek 免费） | 执行工程师 | 按任务卡写/改代码文件、内置 git 提交、Agent 模式批量改、读你的报错日志修 bug | 不做方案决策（架构由 PLAN.md 契约锁定）；不做跨模块设计 |
| **GitHub + gh CLI** | 交接黑板 / 仓库 | 存代码、Pages 线上版、记录每模块 commit 链、开源合规凭证 | — |
| **DeepSeek API（可选）** | 游戏运行时 NPC | 游戏内 NPC 对话生成（免费用量内） | 不参与开发过程 |
| **Edge headless** | 验证工具 | 跑验证页输出 PASS/FAIL JSON | — |
| **Dev-sidecar** | 网络通道 | GitHub 访问代理（唯一通道） | — |
| **WorkBuddy** | 已评估排除 | 只做文档/办公辅助；编程能力弱且付费 | 不进开发链路（应急写纪要可用） |

## 2. 角色定位矩阵（各司其职）

```
                    ┌────────────────────────────┐
                    │  黄文博（项目 owner / 验收人）│
                    │  ① 从我这里领任务卡+话术    │
                    │  ② 原样转给 Trae CN        │
                    │  ③ 把 Trae 的疑问/报错带回   │
                    │  ④ 每模块试玩 3 分钟        │
                    │  ⑤ 拍板方向、最终交作业      │
                    └────────┬───────────────────┘
                             │ 任务卡 / 话术（我给）    │ 疑问 / 报错（带回）
                             ▼                          ▲
                    ┌─────────────────┐          ┌───────────────┐
                    │  豆包（总指挥）  │◄────────┤  Trae CN（执行）│
                    │ 规划/任务卡/审查  │          │ 写代码/改代码  │
                    │ 验证/裁定PASS    │──验证页──▶│ git 提交       │
                    └────────┬────────┘          └───────────────┘
                             ▼
                    ┌────────────────────────────┐
                    │ GitHub（唯一交接黑板）        │
                    │ PLAN.md / 任务卡 / preflight │
                    │ 验证页 / 代码 / README       │
                    └────────────────────────────┘
```

- **每个 AI 的作用边界已锁定**：豆包只指挥不写游戏代码；Trae 只执行不决策；你只传令+试玩+验收，不自己写代码（当然你想看代码随便看）。
- **传递内容只走文件**（R-03）：任务卡写进 `docs/tasks/`，接口契约在代码注释里，验证在 `preflight/`。禁止用对话口头传方案。

## 4. 每模块标准流程（六步循环）

1. **我写任务卡**：`docs/tasks/<模块名>.md`，含目标、文件范围、接口契约、效果判据、给你的话术。
2. **你传令**：把任务卡 + 我的话术原样发给 Trae CN（复制粘贴，不加工）。
3. **Trae 实现第 1 版**：写完告诉我"改动文件 + 自测结果"。
4. **我验证**：headless 跑 `preflight/verify_<模块>.html` + 审查代码 + 列"试玩检查单"。
5. **你试玩**：按检查单玩 3 分钟，把现象（含报错截图）带回；有问题我打回 Trae 第 2 版；循环。
6. **验收提交**：我裁定 PASS → 你让 Trae（或我用代理 git）commit + push → 我核对远程 HEAD → 记录到 PLAN.md。

## 5. AI 之间传递机制（关键纪律）

- 交接载体**只有三个**：`docs/tasks/`（任务卡）、代码注释（接口契约）、`preflight/`（验证页）。PLAN.md 是总纲。
- **你负责唯一的口头通道**：豆包 → 你 → Trae。不许 Trae 的对话历史污染我的判断，也不许我的上下文污染 Trae 的执行。
- Trae 说"这个做不了"→ 你原样带回 → 我改任务卡或换实现路径，你再去传。
- Trae 改了接口/命名 → 必须让它写进代码注释和任务卡回执，否则我验证时按契约打回。

## 6. 你上场时刻表 + 现成话术（到你说的时候，直接复制）

### 场景 A：每模块开工（对 Trae CN 说）
> "请按 `docs/tasks/<模块名>.md` 任务卡实现。<模块一句话>。遵守接口契约注释，保持零构建 file:// 双击可玩，不要引入构建工具和付费资源。完成后列出改动文件清单、自测结果，以及你认为需要我（人）注意的地方。如果任务卡里有你实现不了的部分，直接说卡在哪、为什么，不要绕过。"

### 场景 B：Trae 卡住 / 报错 / 说做不了（对 Trae 说）
> "把完整报错信息、涉及的文件和行号贴出来，说明你试过哪几种做法、各自结果是什么。不要猜测原因，不要自己改接口契约，等我（人）确认方案。"

### 场景 C：把 Trae 的疑问带回来（对我——豆包说）
> "Trae 反馈：<原样粘贴 Trae 的话>。它说做不了/改了方案，怎么处理？"

### 场景 D：模块第 1 版完成，你试玩（对 Trae 说）
> "我玩过了，现象：<逐条列：正常/异常/卡死/数值不对>。有报错的话：<粘贴控制台错误>。你按这个修，不要动其他功能。"

### 场景 E：我裁定 PASS 后提交（对 Trae 说）
> "模块通过验收。请 commit，message 用 `feat(模块名): 一句话说明`，然后 push 到 main。完成后告诉我提交哈希。"

### 场景 F：你拿不定主意 / 想加功能（对我——豆包说）
> "我想在 <模块> 加 <功能>，会不会影响 <现有部分>？该排到哪个模块？"（我会给结论+排期，不会让你自己决定）

## 7. 现役任务卡样例（S3-1，下一个就做这个）

`docs/tasks/S3-1-rotjs-fov.md`：
- **目标**：引入 rot.js 做 FOV 迷雾，地牢探索有"周围亮、远处暗"。
- **文件范围**：新增 `js/vendor/rot.min.js`（BSD-3，来源 ondras/rot.js）；新增 `js/systems/fov.js`；改 `js/core/render.js`（渲染前先按 FOV 结果画暗层）。
- **接口契约**：`window.Game.fov = { compute(pos, radius) -> Map }`；`map:fovChanged` 事件；离线/加载失败自动降级为全亮。
- **效果判据**：file:// 运行角色周围 5 格亮、其余暗；走过区域点亮；验证页输出 `{"rotLoaded":true,"fovOk":true}`。
- **来源声明**：README 组件表加 rot.js（BSD-3）。
- **给你的话术**：见场景 A，`<模块名>` 填 `S3-1-rotjs-fov`，`<模块一句话>` 填"引入 rot.js 实现 FOV 视野迷雾，保持原有地图/移动逻辑不变"。

## 8. 紧急情况处置

- Trae 连续 2 版不过验证：我换实现路径（改任务卡）→ 你去传新任务卡。
- Trae 擅自改架构/契约：我打回 + 它恢复，你只传话不裁决。
- 你电脑网络断 / Dev-sidecar 挂：git 操作暂缓，本地开发不受影响，恢复后我统一补推。
- 任何"要不要加功能"：先问我，别直接让 Trae 加。
