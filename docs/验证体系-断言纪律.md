# 验证体系 · 断言纪律（D-110）

本文件是 `preflight/` 下所有验证页的**判据宪法**。它约束的不是画面，而是"页面变绿"这件事本身是否可信。

一句话：**如果断言可以靠放宽来变绿，前面所有全绿都没有意义。**

---

## 0. 适用对象

- `preflight/verify_*.html` 里的每一条 `rec(...)` / `out.sub[...]`；
- `preflight/selfcheck/` 下的参考文件（`d19-report.json`、`d37-g*.json`、`d34-bot-report.json` …）；
- `preflight/lib/` 下被验证页复用的测量代码。

参考文件是**判据的一部分**。改参考值等于改判据，同样受本文件约束。

---

## 1. 允许的三种改法

### 1.1 重钉参考值（行为确实变了时，唯一正确做法）

适用：产品行为按设计变了（如 D-99 陷阱改用独立随机流、D-64 扩图、D-66 怪物血量重排）。

做法：
1. 用**当前代码**、固定种子、确定性 bot 跑出新结果；
2. 把新结果写成**新的参考文件**，文件名带本轮编号（如 `d110-d19-repin.json`），**旧参考保留不删**，作为历史；
3. 断言写成与新参考**逐局逐字段相等**；
4. 页面顶部写明"本轮参考文件 = `xxx`，旧参考 `yyy` 仅作历史"。

禁止：把"相等"改成"区间"来吸收行为变化。行为变化不是统计波动。

### 1.2 拆分断言

适用：一条断言里混了"确定部分"和"有波动部分"。

做法：拆成两条，确定部分继续 `===`，波动部分单独成条并写明波动来源与样本量。

示例：`deaths` 这类 50 局统计量允许区间（来源：每局 bot 路径对随机数的消耗不同），但同页的"逐局动作数"在固定种子 + 确定性 bot 下必须精确。

### 1.3 改判据（必须配真实可失败的负例）

适用：原判据测的东西变了口径（如从"扫全屏"改成"扫主体区"）。

**硬性配套**：改判据的同一次提交里，必须新增一条负例，并且这条负例**真的能红**：
- 临时把被测修正关掉（关白闪、回放旧 chip 生成、把格宽压到 39 走真实 guard …）；
- 观测到 FAIL，把 FAIL 的日志与截图落到 `preflight/artifacts/d110/`；
- 恢复修正，观测到 PASS；
- 一 FAIL 一 PASS 成对落盘，这条负例才算成立。

只有 PASS 没有 FAIL 的负例 = 未完成。

## 2. 禁止的四条

### 2.1 禁止用放宽区间代替重钉

`=== 0` → `<= 1`、`>= 38` → `[30, 46]`、逐项相等 → `0.65×–1.35×` 带宽，都属于此类。

固定种子 + 确定性 bot 的跑局**没有统计波动**。它变了，说明代码变了，应该重钉新值并解释变化原因，而不是把判据泡软。

区间只允许用在**本身就有统计波动**的指标上（如"50 局死亡数"），且必须写明：波动来源、样本量、为什么无法确定化。

### 2.2 禁止恒真式负例

负例必须是"把修正关掉就会红"的断言。形如：

```js
// 反例：常量代入自己的函数，永远为真
var oldJump = 0;
rec('d109.n3.tintNeg', (oldJump) => oldJump < 20, ...);   // 恒真

// 反例：把常量 32 代进 d>=38
rec('B3b_negativeOld38SnapshotFails', (d) => d >= 38, 32); // 恒真
```

一律**删除重写为真实回放**：跑一次真实路径，观测 FAIL，落盘证据。

已知的五条恒真式（D-110 必须全部重写）：
- `verify_d24` `B3b_negativeOld38SnapshotFails`
- `verify_d37` `A2`（旧动作快照比较）
- `verify_d102` `d109.n3.tintNeg`
- `verify_d102` `neg.cellTooNarrow`
- `verify_d102` `d109.n2.plusNneg`

### 2.3 禁止收窄扫描范围而不保底

把扫描区从全屏收窄到 `x∈[18%,82%]W` 而不留审计数，等于"看不见就不算"。

收窄必须同时满足：
1. 保留**原范围**的实测值作为审计数（即使不参与判定，也要打印）；
2. 对"边缘异常"有**单独判据**（明示阈值 + 与主体矩形的关系），不许只记录不判。

### 2.4 禁止为了让页面变绿而改判据

顺序必须是"先看红的原因 → 判断是产品错还是判据错 → 改对应的一方"。
如果判断不了，**停下来报告**，由用户裁定。不允许先改判据再看会不会绿。

---

## 3. 元要求：改判据必须单列证据

任何一次改判据的改动，在报告里必须**单独列出**：

1. **被改断言的原文**（改前那一行，含文件与行号）；
2. **改后的判据**；
3. **改动理由**（为什么原判据不再成立）；
4. **负例证据**（FAIL 日志路径 + FAIL 截图路径 + PASS 日志路径）。

不许把它混在"验证通过 128/128"里一句带过。没有这四项的报告，视为本次整改未完成。

## 4. 自检清单（每次动判据前过一遍）

- [ ] 这条断言测的是确定量还是有波动的统计量？
- [ ] 如果是确定量，我为什么不能 `===`？
- [ ] 我改的是判据，还是参考文件？改了哪个都要在第 3 节列原文。
- [ ] 这条负例真的会红吗？我跑过 FAIL 吗？证据在哪？
- [ ] 我收窄了范围吗？原范围的审计数在哪？边缘判据在哪？
- [ ] 我是因为红了才改的判据吗？如果是，我报告用户了吗？

## 7. D-113 口径变更台账（WCAG 对比度 → 线性比值 + 交界带差）

这是本体系第一次**主动更换门槛口径**，按 §3「改判据必须单列证据」留档。

### 7.1 口径原文

清单 §1.1：每格中心取 1 个画布像素；`L = 0.2126R + 0.7152G + 0.0722B`（WCAG sRGB 线性化）；
对比度 `CR = (Lmax + 0.05) / (Lmin + 0.05)`；边界差 `ΔL = |L地板 − L墙|`（地板与四邻墙配对）。
实测：`CR 1.16–1.47`、`ΔL 0.017–0.033`。

### 7.2 数学理由（为什么必须改）

`+0.05` 是 WCAG 的底噪项，暗部比值渐近于 1。设地板 `L∈[0.020, 0.044]`、墙压到理论最暗 `L=0`：

- `CR上限 = (L地板 + 0.05) / (0 + 0.05) = 1 + 20·L地板 = 1.40–1.88 < 2.0`；
- `ΔL上限 = L地板 − 0 = 0.020–0.044 < 0.055`。

也就是说：**墙压到纯黑也到不了 2.0:1 / 0.055**；要达标只能把地板亮度提高到 `L≥0.055`
（F1 +72%、F2 +25%、F3 +83%、F4 +45%、F5 +175%），这与「地板均值抬升 ≤15%」直接冲突。
三项要求在原口径下**数学上不可同时成立**，不是调参能解决的问题。

### 7.3 新口径（门槛）

| 项 | 定义 | 是否门槛 |
| --- | --- | --- |
| 对比度 | `L地板 / L墙`，L 为 WCAG 线性亮度，取**交界 3px 带**面积均值（地板侧 / 墙侧），不加 0.05 | **≥2.0，逐层** |
| 交界差 | 交界 3px 带的 sRGB 差 `(0.299R+0.587G+0.114B)/255`，地板侧 − 墙侧 | **≥0.055，逐层** |
| 可分性 | 交界带面积口径：每条交界取 8 列采样（16px 宽、隔列取 1），统计 `Δ ≥ 0.055` 的列占比 `sep` 与差值分位 `dP05/dP50/dMin` | **sep ≥0.90 且 dP50 ≥0.055，逐层** |
| WCAG 诊断 | `(Lmax+0.05)/(Lmin+0.05)`，同一组交界带 | 只报，**不判** |
| 低照度 | 地板整格均值抬升 | **≤15%** |
| 排序 | 墙必须低于地板 | 必判 |
| 色相 | 五层地板色相改动前后变化 | **≤0.5°/层** |

采样从「整格中心 1px」改为「交界 3px 带」，是因为前者会被砖块纹理与单点噪点主导；
后者正是玩家实际看到的那条边。地图用固定种子（`20261118 + f×7919`）真实生成，只读不改。
「可分性」不是再合成一个均值：它按交界**面积**统计有多少比例的采样列真的能分出边界，
回答的是「玩家能不能看出边界」，而不是「两个平均数差多少」。

### 7.4 旧渲染在新口径下必须判负（证据）

`verify_p2_3` 的 `d113.neg.legacy`：把 `_wallStyle` 注入旧值（墙顶 0.40 / 墙身 0.45、无交界暗边），
仍走同一条 `drawMap`：

| 层 | 旧 ratio | 旧 WCAG | 旧交界差 | 旧 sep | 判负原因 |
| --- | --- | --- | --- | --- | --- |
| F1 | 0.69 | 1.24 | 0.000 | 0.000 | 对比度 <2.0，交界差 <0.055 |
| F2 | 1.05 | 1.04 | 0.001 | 0.103 | 同上 |
| F3 | 0.68 | 1.30 | 0.000 | 0.001 | 同上 |
| F4 | 0.73 | 1.26 | 0.000 | 0.000 | 同上 |
| F5 | 0.46 | 1.59 | 0.000 | 0.000 | 同上 |

`d113.neg.wallOnly`：只压墙体内圈（`guard=4`）、交界像素一个不动。这一条的读数正是
「WCAG 只能当诊断」的直接证据——**WCAG 诊断值反而升到 2.18–3.55（会误判为合格）**，
而真实交界带的有符号差是 **−0.23 ~ −0.37**（墙侧比地板侧更亮），线性比值 0.17–0.38，
交界差 0.000、可分性 0.000，五层全部判负。

> 口径注记：清单里早期按「整格均值」实测的对应值是 −0.07 ~ −0.12；本轮改成
> 「交界 3px 带」后同一负例的量级变为 −0.23 ~ −0.37。两者方向一致、都判负；
> 断言写成 `edgeSigned ≤ −0.06`（方向性门槛），实测值逐层打印在页面里，不写死区间。

结论：口径变更后旧渲染**双负**，不是为了让红色变绿；WCAG 诊断值仍留在表里
（旧 1.04–1.59 → 新 1.63–2.75），能直接看到「旧口径到不了 2.0」。

### 7.5 暗边的五条硬约束与对应证据

| 约束 | 实现 | 证据 |
| --- | --- | --- |
| 只画在地板-墙交界内侧，不许给每块地砖描边 | 只对 `t=0` 的墙格、且四邻**有地板**的那条边画 `edgePx=3`；地板格一个像素不改 | 实拍 `d113-F{1..5}-*-corr.png`：暗边只沿墙侧连续，房间内部地板无缝 |
| FOV 黑场里不许出现 | 未探索格在 `_drawSceneStatic` 里先整格填近黑并 `continue`，墙与暗边都不进入绘制 | `d113.fovBlack`：注入「只看中心 ±2 格」的 fov，未探明区 101 格与地板相邻的墙逐像素与格内同色（黑场 + 主题 tint），越界 0 |
| 不许与可交互高亮抢视觉 | 暗边是**压暗**且画在静态层；宝箱/楼梯/陷阱提示在动态层后绘、且为亮色 | 静态层先后顺序见 `drawMap`（静态层 → 实体 → 高亮）；实拍 F3 全屏：梯子/火把/宝箱仍是最亮点 |
| 颜色只取现有 84 色板 | 墨色 `#1a1024`（84 色里最暗一档，F5 暗紫），**不用色板外的 `#000000`** | `d21-audit.json` 的 `paletteSize=84` 列表里没有 `#000000`；改用 `#1a1024` 后把 alpha 从 0.55 提到 0.90 补偿，五层仍全绿 |
| 静态缓存正确失效 | 暗边在 `_drawSceneStatic` 内绘制，缓存键含 grid/floor/cam/dpr/scale/画布尺寸；`invalidateStatic()` 强制重建 | `d113.cacheInvalidate`：复制真实地图→把一格墙改成地板→`invalidateStatic()`→重建像素与直绘逐像素 `diff=0 / 368928 px` |

> 墨色说明：`rgba(0,0,0,0.55)` 是本次最初实现，实测五层 `edge 0.098–0.225`；但纯黑不在 84 色板内，
> 换成 `#1a1024` 后同 alpha 下 F3/F5 的可分性掉到 0.785 / 0.649（判负），因此把 `edge` 提到 0.90。
> 最终五层：`ratio 4.04–9.43`、`edge 0.109–0.231`、`sep 0.978–1.000`。
