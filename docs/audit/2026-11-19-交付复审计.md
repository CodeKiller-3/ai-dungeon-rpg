### 2.2 是否“首尾相接”、有没有“整体重钉当零差异”

- `d99 → d118` 的 19 个版本，胜/死/空转与逐层到达全部一致，是**真正首尾相接的零差异**，与“D-100 起全是纯表现层”的声明吻合。
- `d97 → d98 → d99` 是真实行为变化，**不是**“重钉后当作零差异”：
  - **D-98**（`js/systems/map.js:1052` 注释、`main.js:1845`）：陷阱放置开始拒采**割点 / 单格走廊**，且“拒采”多抽了主随机流，导致整层重掷 → 6/34/50。
  - **D-99**（`map.js:1053-1174`）：把陷阱拆到**独立确定性随机流**，主随机流恢复到 D-98 之前，地图/敌人/宝箱回到旧序列，只有陷阱位置是新的 → 4/37/50。
- 运行参数核对：`d94-base`、`d94-d98`、`d94-d99`、`d118` 的 `maxActions / seeds / form / adaptive / density / bossDef / sizes` **逐项相同**；唯一差异是 `env.fx` 由 `low` 变为 `null`（纯表现档，且 D-78 起档位恒定），不构成“换参数重钉再当零差异”。
- 因此“相邻零差异”在 D-99 之后成立；**D-97→D-98→D-99 两次跳变没有被当作零差异**，但也**没有在交付文档里重钉**（见第三节）。

### 2.3 与 D-94 审计相比变了多少、能否归因

- 净变化：**B1 +1（3→4）、S1 0、G2 −3（40→37）、M1 0**；B1 到 F5 从 43/50 降到 39/50。
- 可归因：只可能是陷阱落位与陷阱类型抽取方式变化。D-99 之后 19 版零差异进一步收窄了归因范围——不是战斗、AI、掉落或数值改动。
- 不可归因的部分：D-98/D-99 没有留下“逐局差异清单”（哪 3 局 G2 从赢变输、死在哪层、是否踩陷阱致死）。`preflight/selfcheck/d94-d98-*` 与 `d94-d99-*` 只有聚合与 runs，没有对照脚本产物。
- 结论：**变化可解释到“陷阱通道”，但不可逐局归因**；交付文档仍引用 D-94 的 3/0/40/50。

## 七、我认为不该改的

1. **不为了回到 D-94 的 3/0/40/50 回滚 D-98/D-99。** 割点/单格走廊排除与独立随机流是产品修复（陷阱不再堵死唯一通路、地图不再被陷阱拒采重掷），胜率变化是修复的代价，应重钉文档而不是回退代码。
2. **不把 16 张零引用素材删掉。** 许可与体积都不是问题；删文件会让 `NAMES=落盘=355` 的三方对账失效，收益不抵风险。
3. **不做触屏/移动端适配。** README 已明示“桌面键盘 + 鼠标”，本轮硬塞 `pointerdown` 会同时改输入层与布局，风险远大于收益。
4. **不把探索点击改成全图自动寻路。** 现有“只点相邻格 + 远端提示”把楼梯确认、陷阱、遭遇全部复用同一移动入口；全图寻路要处理中途打断、陷阱踩中、怪物移动，属于新功能，不是交付修复。
5. **不删 `monster_chort` / `boss_demon` 兜底。** 精英已通过 `sprite` 正确映射；兜底是未来新增怪的保险，删了只会让未知 id 白屏。
6. **不把“未侦测陷阱不可见”改成常显。** 神秘感是设计意图；D-98 已给 F 侦测/拆除，反制手段存在。
7. **不改龙 350/32/15、成长曲线、精英刀不可强化。** 这是 D-84 已定档的平衡裁决，与本次交付风险无关。
8. **不改 D-113 的新对比度口径。** 旧 WCAG 口径在暗部数学上不可达（§7.2 已证明），且旧渲染在新口径下双负；回退只会让判据重新失效。
9. **不把 24 张卡压成一个巨型 commit。** 分批提交才能在出问题时二分定位；也不要在提交时跳过 hooks。
10. **不把 `page-baseline` 的 128 改回 127 去迁就旧文档。** 页数是磁盘事实，应改文档。
