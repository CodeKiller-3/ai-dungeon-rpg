# D-78：特效居中 + 特效硬性常开

> 范围：只改表现层。数值、怪物、Boss、成长曲线、伤害公式、地图与存档键一字未动。
> 特效代码（fx.js / juice.js / feedback.js）保持零 `Math.random(`。

## 1. 两条反馈的定位

| 反馈 | 根因 | 结论 |
|---|---|---|
| “特效没有出现在屏幕正中间” | 三张结果卡（升级 / 精英之证 / 碾压击杀）被固定画在**右上角** `x = W-264, y = 34`；同时伤害飘字/斩击弧/粒子用了**物理像素** `cv.width/2`，在 scale≠1 时也偏离中心 | 版式问题 + 真坐标 bug，两层都修 |
| “特效应硬性常开” | 设置页有「打击感」off/low/high，战斗内 F 键循环 | 删设置行、删 F 绑定、固定 high；旧设置 `fx:off/low` 强制 high |

## 3. 改动

### 3.1 结果卡居中（juice.js）

- 新增纯函数 `Juice._layout(W,H)`：卡片锚点全部由逻辑视口计算，`x = round((W-cw)/2)`，不写死任何像素。
- 探索：整块在 `H/2` 垂直居中。
- 战斗：整块居中在**敌方血条（212~232）与己方血条（414~434）之间的安全带 236~410**。
  - 不压血条、不压底部指令行（H-30）、不压玩家精灵（H-190..H-100）。
  - 代价：在 960×540 这类短视口下，卡片块的中心是 323，而不是几何中心 270（下移 53px）。这是刻意的避让，不是 bug；字号完全未缩小。
- 同屏三张装不下安全带时，由新到旧取舍（新卡优先），不缩字号、不压缩行距。

### 3.2 跟随类修坐标（battle.js）

`monsterPos()` / `playerPos()` 原来用 `cv.width / 2`、`cv.height`（物理像素）；改为 `Render.cssW` / `Render.cssH`（逻辑坐标），与 `drawBattle` 同一口径。

修好后：

- 怪物飘字/斩击弧/粒子锚点 = `(cssW/2, 135)`；
- 玩家飘字/斩击弧/粒子锚点 = `(cssW/2, cssH-145)`；
- 冲击环本来就取 `cssW/cssH`，因此“环在中间、数字在右边”的错位消失。

### 3.3 硬性常开（fx.js / main.js / render.js / modal.js）

- `Game.Fx` 固定 `high`；`setLevel('off'|'low'|'high')`、`cycle()` 都是兼容空操作，恒返回 `high`。
- 设置页删「打击感」行：`_settingsSpec()` 由 3 项变 2 项（音效 / 画面缩放），`_settingsRows()` 由 6 行变 5 行。
- 旧设置里的 `fx: off/low` 读入时被忽略，`applySettings()` 固定 `setLevel('high')`；`getSettings()` 不再暴露 `fx`。
- F 键解绑：删除 `_updateBattle` 的 KeyF 分支、战斗键表 F 行、战斗指令行 “F 特效”、音频面板说明行。F 键**留空**，没有另造功能（避免凭空增加未验证操作）。
- 顺手修掉一个真实隐患：`_updateMenu` 的设置页曾手写第二份 `ids=['fx','muted','zoom','adaptive','clearSave']`，删行后会与光标错位（光标在“任务指引”却触发“清除存档”）。现改为直接从 `_settingsRows()` 取 id。
- `prefers-reduced-motion` 不再降档（与“硬性常开”一致）；光敏安全仍保留：闪白单次 ≤120ms、一次命中只闪一次、无 strobe。

## 5. 跟随类是否算错：是，错在坐标口径

- 错处：`battle.js` 的 `monsterPos/playerPos` 用 `cv.width`/`cv.height`（物理像素），而 `feedback.js`、`fx.js` 在同一 `ctx` 的逻辑变换下绘制。
- 改成：`Render.cssW` / `Render.cssH`（逻辑），无 Render 时退回 `clientWidth/clientHeight`。
- 实测（画布 1920×1080、cssW=960）：怪物飘字锚点 `(480,135)`，不再是 `(960,135)`。
- 冲击环本来就用 CSS 尺寸，因此保持跟随目标，不搬到屏幕中心。

## 6. D-70 三条断言逐条处理

| 断言 | 处理 | 性质 |
|---|---|---|
| `A2_offSilent` | 改为 `A2_hardOnIgnoresOff`：请求 off 后三张卡仍全部建立、`draw() > 0` | **口径失效**（off 分支不存在），不是放宽；反证强度更高 |
| `B2_fxThreeLevels` | 改为 `B2_fxLevelsCollapsed`：off/low/high 三种请求都折算 high；三份历史 50 局逐局指纹必须全等 | **口径失效**（三档不存在）；指纹全等判据未放宽 |
| `C1_drawBudget` | 去掉“off 必须 0 次”这条不可能分支；保留“空闲 0 次、≤60 次/帧”，新增 low/high 结果必须相同 | **口径失效**（off 分支不存在）；预算上限 60 未放宽 |

`verify_d70` 的 `A5_damageStyles` 同步改为“三种请求都是 36px 碾压样式”，原因同上。
