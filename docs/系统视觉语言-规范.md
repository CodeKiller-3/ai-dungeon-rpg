# 系统视觉语言规范（D-90）

> 性质：**只写规范，不写代码、不动素材**。本文件下发后由执行端按「必须做 / 应该做 / 可以不做」分批实现。
>
> 判决回应：完成度 8.5、艺术性 6，差距只有一句——**画面里没有「系统」**。本规范不再增加布景，而是给现有五层空间加一套**测量层**：它只做三件事——测量、记录、提示下一步。
>
> 事实基线（2026-11-16 工作树）：
> - 画布逻辑基准 960×540，TILE=24，渲染在 `js/core/render.js`。
> - 第 4 页「系统」**已经存在**（`modal.js` D-87 仪表盘：成长账本、突破条、武器共鸣两段条、龙威三格），不是待建页面。
> - 五层网格：25×19 / 29×21 / 33×23 / 37×25 / 41×27（`maps.js` 的 `sizes`）。
> - 战斗时钟 `TL={seg1:100, lock:150, total:180}`；特效 `PRESET.high`：顿帧 80ms、震屏 4px/180ms、闪白 110ms、斩击 200ms、冲击环 180ms。
> - 底部提示条 `Notice`：最多 3 条、`LIFE=2400ms`、战斗场景上移 26px。
> - 验证页基线 `preflight/selfcheck/page-baseline.json` 当前 `count=120`（D-90 第一批实现后）。

## 0 命题

**系统不是界面层，是这层地牢的测量层。它只显示可以被测量、被记录、被推进的东西。**

这句话是后面所有规格的取舍依据。凡是不能用「测量 / 记录 / 下一步」解释的元素，一律不做。

## 1 系统层三要素

### 1.1 线

| 项 | 规格 |
|---|---|
| 线宽 | **1px**。唯一例外：突破刻度 2×6px、龙威档位块 6px 高 |
| 坐标 | 一律整数 + `0.5` 偏移描边（`strokeRect(x+0.5, y+0.5, w-1, h-1)`），保证不糊 |
| 端点 | 直角。**禁止圆角、禁止发光、禁止外阴影、禁止渐变** |
| 常驻透明度 | 底纹 0.06–0.10；可交互标记 0.24–0.32；事件层 0.55–0.90 |
| 覆盖上限 | 任何系统图元覆盖单格像素不得超过 **35%**；不得整格铺色 |

### 1.2 色

一律取自第 4 页已经落地的 `SYS_C`（`js/systems/modal.js`），**不引入新色相**：

| 语义 | 值 | 用途 |
|---|---|---|
| 测量青 | `#7fd1ff` | 当前可读的量：坐标、网格、目标框、有效攻击 |
| 记录金 | `#ffcf6e` | 成长、突破、已归档、精英目标 |
| 次级蓝 | `#9bbbf4` | 第二读数、面板次级行 |
| 正向绿 | `#4ade80` | 差量为正（`+N`）、已达成 |
| 标签灰 | `#8a8aa0` | 所有标签文字 |
| 正文灰 | `#cfcfcf` | 面板正文 |
| 暗灰 | `#5f6578` | 未达成、未解析 |
| 轨道 | `#1c1c33` / 边 `#3a3a5c` | 所有条、格、槽 |
| 威胁橙 | `#ff9b6b` | 龙威（沿用伤害橙系，不另造） |

**唯一禁色**：霓虹紫、全息青绿、纯黑面板上的高饱和蓝。它们会让系统读成「科幻 UI 贴纸」。

### 1.3 字与读数语法

| 层级 | 字号 | 场景 |
|---|---|---|
| 地图标注 | 9px monospace | 房间编号、楼梯层号 |
| 屏幕读数 | 11px monospace | HUD 测量条、战斗右上读数、面板标签 |
| 事件标题 | 13px monospace | 入层、觉醒 |
| 面板大数 | bold 14–20px monospace | 第 4 页 Lv / 攻击 |

读数语法统一为四段：

```
标签（灰） + 值（青/金） + 单位（灰） + 差量（绿/橙）
例：有效攻击 26 · 每击 13        /  突破 0/200       /  龙威 T2 +13
```

硬规则：
- 数值**右对齐**；标签左对齐；同一屏内不混用。
- 差量一律写成 `A → B（+N）` 或 `还差 N`，不写单独一个数字。
- 英文标签只允许两个：`LV`、`ATK`；其余一律中文（经验、突破、龙威、有效攻击）。房间编号 `R01`/`S01` 是坐标标记，不在此限。
- 不出现 `undefined` / `NaN` / `null`；无数据整行隐藏，不补 0。

### 1.4 绘制顺序（z 序，硬性）

1. 场景层（地图静态层 / 战斗背景）
2. **系统底纹层**：网格残迹、房间括号、楼梯层号（在实体之下）
3. 实体层（怪物、玩家、NPC、装饰）
4. **系统标记层**：目标框、命中判定框、龙威档位
5. HUD 顶栏 + 测量条
6. **系统事件层**：入层测绘、精英锁定、觉醒
7. `Juice` 卡片
8. `Notice` 提示条
9. 引导覆盖层

不允许把系统标记画到第 5 层之后再去盖 HUD；也不允许把底纹画到实体之上。

### 1.5 永久禁止清单

- 全屏常驻扫描线 / 噪点 / 色差 / 故障字。
- 六边形网格、旋转环、圆角面板、发光边框。
- 给系统加「假代码」「假进度条」「未知语言」。
- 在玩家身上画整圈选中框。
- 用 `Math.random` 决定任何标记的位置、闪烁或寿命。
- 为系统感新增按键、设置项、HELP 条目。

## 2 HUD：把数值变成「读数」

### 2.1 现状

`js/systems/hud.js` 顶栏高 28px，从左到右：心形 HP、MP 短条、金币、楼层、击杀、`Lv.x exp/expNext`。字号 11px，等级紫 `#a78bfa`。出生点、击杀目标、状态 chip 已经齐了，问题是：**它们只是被「看」到，没有被「读」出来**——没有单位、没有差量、没有「还差多少」。

### 2.2 H1 测量条（必须做）

在顶栏下沿新增一条 **14px 高的读数带**（y=28–42），不改动顶栏任何既有元素的坐标。

| 元素 | 位置 | 规格 |
|---|---|---|
| 基线 | y=28.5，x=0→W | 1px，`rgba(127,209,255,0.14)` |
| 刻度 | 每 48px 一根，y=28→31 | 1px，`rgba(127,209,255,0.10)`；只在 cw≥520 画 |
| 左簇 | x=8 | `LV` 灰 + 等级金；后接 44×4 的 10 段经验条（段间 1px，填充青，轨道 `#1c1c33`）；再接 `exp/expNext` 青 11px |
| 中簇 | 以 W/2 为锚点居中 | `ATK` 灰 + 攻击青 + `刀` 灰 + 武器有效攻击蓝（`Inventory.atkOf`） |
| 右簇 | 右对齐 x=W-8 | `突破` 灰 + `0/200` 金；就绪时写 `突破 就绪` 并在文字左侧加 2×6px 金色缺口 |
| 文字底板 | 每个簇文字下 | `rgba(6,6,12,0.55)`，y=29、高 13px、宽=文字宽+8、无边框；**不铺整条底色** |

- 文字基线 y=39；字体一律 11px monospace。
- 数据来源：`Player.level/exp`、`Battle.expToNext(level)`、`Inventory.atkOf(weaponId, level)`、`Player.atk`、统一的 `Sys.breakthrough()`（见 §5.3）。
- 出现条件：所有场景常驻（探索/战斗/面板都保留），但战斗里中簇改为 `有效攻击`（见 §4.1）。

**降级**：cw<520 去掉刻度与中簇；cw<420 只留左簇，经验条缩到 32px。任何降级都不改顶栏既有元素位置。

**与像素美术冲突时的取舍**：如果读数带压住第一行地砖且你觉得脏，**只保留文字底板、删掉基线外的刻度**，绝不把整条改成不透明黑带，也绝不改 TILE 或相机。

### 2.3 H2 突破刻度（必须做）

- 位置：右簇 `突破` 读数的左侧，2×6px 竖缺口。
- 三态：
  - `未满足`：缺口暗金 `#6b5a2e`，读数 `还差 N`；
  - `就绪`：缺口亮金 `#ffcf6e`，读数 `就绪`，并每 1200ms 做一次 1px 的明度呼吸（0.7→1.0→0.7，**不做缩放**）；
  - `已突破`：缺口换成 6×2px 横线，读数 `已突破`。
- 触发：`exp ≥ GROWTH.lastStep[10]` 且 `level===10` 时为就绪；`level≥11` 为已突破。
- 意义：这是「下一突破还差多少」在画面里的唯一常驻读数；面板第 4 页的突破条必须读同一个模型。

### 2.4 H3 差分读数（应该做）

- 触发：`inventory:changed` 或等级变化后 900ms。
- 表现：在 `ATK` 值后追加 `▲+2`（绿）或 `▼-1`（威胁橙），不弹卡片、不挡画面。
- 只读事件 payload 与 `Player.atk`，不重算、不写状态。
- 取舍：如果和 `Juice` 的升级卡重复，**保留卡片、删掉 HUD 差分**——同一时刻只允许一种「变强」表达。

### 2.5 不改什么

- 心形 HP、MP 条、金币图标、楼层/击杀文字的位置与字号。
- `FPS` 行、底部操作提示。
- 不新增设置项、不新增按键。

## 3 探索画面：系统如何「看」这个空间

### 3.1 X1 层铭牌（必须做）

- 位置：右上角，右对齐 x=W-8；两行（水印级，不抢画面）：
  - 第一行 y=58：`F3 · 33×23`，11px，青，alpha 0.45；
  - 第二行 y=72：`x 12  y 07`，10px，标签灰，alpha 0.32。
- 数据：`Player.floor`、`MAPS.sizes[floor-1]`、`Player.x/y`。
- 条件：仅 `explore` 场景；打开弹窗/对话时隐藏（避免和面板抢读数）。
- 为什么放右上：左上被 HUD 占、右下被 `Notice` 占、右侧 y≈45% 处被任务指引占；58/72 是唯一长期空位。

### 3.2 X3 网格残迹（必须做）

- 在可见且**已探索**的格子上，每 6 格（144px）画一个 3px 十字（交点处），1px，青，alpha 按楼层阶梯（见 §7.4）。
- 只画视口内；960×540 下约 18 个十字，F5 的 41×27 层也不超过 24 个。
- 画在实体之下（z 序第 2 层），不覆盖角色、怪物、装饰。
- 需要新增只读接口 `Map.isSeen(x,y)`；不得改 `seen` 的写入逻辑。

**与像素美术冲突时的取舍**：若十字在花砖上读成噪点，**改成只画在墙脚/房间边界上的短刻线**（每 6 格一根 4px 竖线），不要提高透明度去硬压。

### 3.3 X2 目标框（必须做）

- 对象：4 格内、当前可见的可交互物——陷阱、宝箱/金币堆/补给包、上/下楼梯、层内精英。
- 形状：**四角括号**，不是整框。括号臂长 5px，1px，距目标包围盒外扩 2px。
- 颜色：普通目标青 alpha 0.28；精英金 `#ffcf6e` alpha 0.32。
- 出现：首次进入该格 4 格范围时淡入 120ms；离开 6 格或已拾取/触发后 200ms 淡出。
- 绝不画在玩家包围盒内；与玩家包围盒至少留 2px。

**取舍**：如果普通装饰也标会显得吵，**只标「可操作」的三类：陷阱、容器、楼梯**；精英保留金色。

### 3.4 X5 楼梯层号（应该做）

- 在已看见的楼梯上方 12px，9px 标注：下行 `↓ F4`、上行 `↑ F2`，青 alpha 0.45。
- 不新增图标；不改楼梯贴图与碰撞。
- 无下一层（F5 下行梯）时写 `↓ 底层`，不写假层号。

### 3.5 X4 一次性扫描（应该做）

- 只在入层测绘（§6.1）里出现：一条 1px 水平线从 y=0 扫到 H，640ms，最多 2 遍，alpha 0.10。
- **绝不常驻、绝不循环**。战斗、面板、结局里都不出现。
- 光敏安全：不做频闪，单次事件只扫 2 遍。

### 3.6 不遮挡角色的证明方式

- 所有标记都在实体层之上但**外扩 2px**，几何上不进入角色包围盒；验证页可直接断言「标记矩形 ∩ 玩家矩形 = 空」。
- 网格残迹画在实体之下，天然不遮。
- 层铭牌在右上角 y=58–78，角色活动区中心在屏幕中部，不重叠。
- 扫描线只在入层黑场里出现，黑场期间本来就不看角色。

## 4 战斗画面：命中被判定、龙威被测量

### 4.1 B2 右上读数（必须做）

战斗场景右上角，右对齐 x=W-12，两行（第一行 y=64、第二行 y=78），11px，文字底板 `rgba(6,6,12,0.55)`、高 14、无边框：

| 行 | 内容 | 条件 |
|---|---|---|
| 1 | `第 N 回合 · 有效攻击 26 · 每击 13` | 所有战斗 |
| 2 | `龙威 T2 · +13 · 距升档 3 回合` | 仅 `Battle.dragonDread() !== null` |

- 数据：`state.roundNo`、`Player.atk`、`Battle.estimateDamage()`（新增只读接口，内部仍用 `damage(atk, monsterDef())`，不复制公式）、`Battle.dragonDread()`。
- 「每击」指**普通攻击**，不含技能倍率；技能伤害不在这一行预测。
- 颜色：第 1 行标签灰 + 数值青；第 2 行威胁橙 `#ff9b6b`；tier=0 时暗灰 `#5f6578` 并写 `龙威 未启动 · 第 9 回合`。
- 位置理由：敌方精灵顶 y=90，右上 64/78 在其上方；不压名字（202）、血条（212–232）、战报（326–362）、我方精灵（H-190 起）。
- 不写「弱点」——本作没有元素弱点系统，不发明假机制。

### 4.2 B1 命中判定框（必须做）

- 每次实际命中（玩家打怪、怪打玩家）在**命中点**画 4 角括号：8×8px，1px，白 alpha 0.9，110ms 内从 0 扩到 +4px 后消失。
- 命中点取现有 `Fx` 斩击的 `impact` 坐标；不重算几何。
- 与闪白同寿命（110ms），**不延长战斗时钟**；不新增粒子。
- 只在有实际伤害（`dmg>0`）时出现；防御/逃跑/未命中不画。

### 4.3 B3 龙威档位（必须做）

- 复用第 4 页的 `Sys.pips`：3 块，8×5px（战斗）/12×6px（面板），间隔 2–3px。
- 战斗位置：第 2 行读数左侧，右对齐；tier 点亮 1/2/3 块。
- 颜色：1–2 档 `#ff9b6b`，3 档 `#ff5a4a`；未点亮 `#1c1c33` + 1px `#3a3a5c` 边。
- 数据只读 `Battle.dragonDread().tier`；不写 `state`、不写 `Player`。
- 面板与战斗必须调用**同一个绘制函数**，尺寸作为参数传入——这是「同源」的可见证据。

### 4.4 B4 预计击数（应该做）

- 在第 1 行末尾追加 `· 预计 4 击`（`ceil(monster.hp / 每击)`，最小 1）。
- 狂暴切换时实时重算（读 `state.enrageDef`），不缓存。
- 标注「预计」二字；不写「必胜/胜率」。

### 4.5 与 100/150/180 的兼容证明

| 系统元素 | 寿命 | 是否影响输入/结算 |
|---|---|---|
| 命中判定框 | 110ms | 否，纯绘制 |
| 龙威档位 | 常驻文字 | 否，只读 |
| 右上读数 | 常驻文字 | 否，只读 |
| 精英锁定 | 400ms | 否，战斗开始即计时，不锁输入 |
| 入层测绘 | 520ms | 否，探索场景才画 |

- 不新增 `setTimeout` 门控输入；不调用 `Battle` 的写接口；不消耗随机数。
- 所有动画时钟走 `Fx.clockNow()` 或模块自己的可注入时钟，顿帧期间不前进，与现有特效一致。

## 5 系统面板第 4 页：与画面同源

### 5.1 现状

`modal.js` 的第 4 页已经是仪表盘：`SYS_C` 调色板、`sysBox/sysEdge/sysTxt/sysBar/sysSegBar` 五个原语、成长账本等级格、本级经验条、突破条、武器共鸣两段条、`sysPaintDread` 三格。它已经是「系统语言」，缺的是**把同一套语言反向输出到画面**。

### 5.2 同源三条

| 维度 | 面板 | 画面 | 同源方式 |
|---|---|---|---|
| 线 | 1px、`.5` 偏移、直角 | 同 | 共用 `Sys.edge` |
| 色 | `SYS_C` 九色 | 同 | 共用 `Sys.C` |
| 读数 | `标签 + 值 + 差量`，右对齐 | 同 | 共用 `Sys.readout` 与 `Sys.pips` |
| 突破 | `M.brk` 的 `have/need/remain/ready/done` | HUD 右簇 | 共用 `Sys.breakthrough()` |
| 龙威 | 3 格 pips | 战斗右上 3 格 pips | 共用 `Sys.pips` |

### 5.3 数据来源（画面与面板共用，不许第二套口径）

| 读数 | 唯一来源 |
|---|---|
| 等级 / 经验 / 下一级所需 | `Player.level`、`Player.exp`、`Battle.expToNext(level)` |
| 攻击 / 防御 / 生命 | `Player.atk/def/hp/maxHp`（`Inventory.recalcEquip` 之后） |
| 刀的有效攻击 | `Inventory.atkOf(Player.equipment.weapon, Player.level)` |
| 突破（还差 / 就绪 / 已突破） | `Sys.breakthrough()` 读 `GROWTH.lastStep[10]` 与 `GROWTH.milestones[11]` |
| 龙威档位 | `Battle.dragonDread()` |
| 战斗每击 | `Battle.estimateDamage()`（内部仍走 `damage()`） |
| 房间矩形 | `Render._roomKind()` + `Map.getRooms()`（密室） |
| 已探索 | `Map.isSeen(x,y)`（新增只读） |

### 5.4 面板侧改动（必须做，原 P1）

## 6 过场与节点：系统开口时，画面发生什么

所有节点都**不写字幕段落**，只发生一个画面事件 + 一行读数。

### 6.1 T1 入层测绘（必须做）

触发：`map:floorChanged` 后、场景为 `explore` 的第一帧；总时长 **520ms**。启动/读档期间的 `floorChanged` 不触发（复用 `main.js` 的 `booting` 口径）。

| 时间 | 画面 | 规格 |
|---|---|---|
| 0–80ms | 黑场压入 | `#06060c`，alpha 0→0.72 |
| 80–360ms | 测绘 | 网格十字 alpha 0.18；最多 6 个房间括号；屏幕中心 `F3` 13px 金 + `33 × 23 · 已测绘` 11px 青；上下各一条 180×1px 线 |
| 360–520ms | 黑场退去 | alpha 0.72→0，网格回落到常驻 0.06–0.14 |

- 不锁输入；玩家可以在淡出时移动。
- 期间如果切到战斗/弹窗，立即取消事件，不延迟任何结算。
- 不能写「生成中」「载入中」这类假状态——它只是一次测量。
- **换层与入层是同一个事件**：上/下行都走 T1，不区分方向、不做第二套动画；方向由常驻的楼梯层号（§3.4）承担。

### 6.2 T2 精英遭遇（必须做）

触发：`battle:start` 且 `MONSTERS[id].elite === true`；总 400ms。

- 四角括号从屏幕四角外 28px 处向敌方包围盒收拢，1px 金，alpha 0.9→0.55。
- 收拢完成后右上出现一行 `目标锁定 · 精英` 11px 金，停留 900ms 后淡出。
- 不震屏、不闪白、不黑场；第一回合输入不受影响。

### 6.3 T3 觉醒（必须做）

触发：`Player.level` 首次达到 **11**（`GROWTH.milestones[11]`）；总 900ms，每局一次。

- 屏幕中心一条 1px 金线从中心向两侧展开到 W；
- 上方 `Lv.11 突破完成` 13px 金；
- 下方三行 11px：`攻击 +9`、`防御 +4`、`生命 +20`（数值只读 `GROWTH.milestones[11]`，不复制）；
- HUD 右簇同时从 `就绪` 切到 `已突破`，缺口变横线；
- 不锁输入、不暂停战斗、不额外回血（回满仍由既有升级逻辑负责）。

### 6.4 T4 Boss 遭遇（应该做）

触发：`MONSTERS[id].boss === true`；600ms。

- 一条 1px 水平线从 y=90 扫到 180（敌方精灵区），青 alpha 0.25，只扫 1 遍。
- 右上读数追加 `威胁 高`（金/橙），与 §4.1 同一位置，不另开面板。
- 不做全屏黑场——Boss 的体量已经由 2× 精灵承担。

### 6.5 T6 结局归档（应该做）

- 在现有 `drawVictory` 内容外圈加 1px 内框（inset 24px）+ 四角括号，青 alpha 0.20；
- 右上 `记录 · 已归档` 11px 金；
- 600ms 淡入；不新增统计字段、不改评级、不改排行榜。

## 7 五层空间如何被「计算」

### 7.1 手法一：每层被重新量一遍

- 入层测绘（T1）每次都报 `F{n} · {w}×{h}`，格数来自 `MAPS.sizes`，不是文案；
- 网格十字按层加密（§7.4），玩家越深，系统的「测量密度」越高；
- 层铭牌常驻右上，坐标逐格更新——它证明系统在持续读位置，而不是播一次动画。

### 7.2 手法二：房间被「划分」的痕迹（G3，必须做）

- 时机：`map:floorChanged` 时计算一次，结果缓存在系统层，不每帧扫图。
- 算法：读 `Render._roomKind(grid,x,y,...)`（已存在的纯函数），对 `room` 类格子做 4 邻接洪泛，取包围盒；只保留 ≥3×3 的前 6 个。
- 绘制：包围盒四角 1px 括号，臂长 6px；左上 9px 标注 `R01 7×5`。
- 密室：用 `Map.getRooms()` 的精确矩形，标注 `S01`，金色；与普通房间区分。
- 条件：房间中心格 `Map.isSeen(center)` 为真才画；不再扩大 FOV。
- 取舍：如果 6 个框太吵，**降到 3 个最大的**，并只画在墙脚（把括号裁到房间边界内侧 2px），不要取消。

### 7.3 手法三：边界刻度（G4，应该做）

- 对象：地图最外圈墙（`grid` 的第 0/最后一行与列），不标视口边缘——标在**空间本身的边界**上。
- 规格：沿可见边界每 6 格一根 3px 竖刻线（横边）/横刻线（竖边），画在墙内侧 1px，1px 青，alpha = 该层网格 alpha + 0.02（仍受 0.20 上限约束）。
- 条件：只在边界进入视口时画；`Map.isSeen` 为假的边界段不画。
- 意义：房间括号说明「内部被划分」，边界刻度说明「外部被界定」；两者合起来才是「这个空间被计算过」，而不是一张随便画的地图。
- 取舍：若边界墙贴图本身已有装饰线，**只保留四个角各一根 6px 角标**，不逐格画。

### 7.4 手法四：深度阶梯（参数表）

| 层 | 网格 alpha | 房间括号 alpha | 备注 |
|---|---|---|---|
| F1 | 0.06 | 0.12 | 系统刚接入，几乎看不见 |
| F2 | 0.08 | 0.14 | 密室出现，`S` 标记启用 |
| F3 | 0.10 | 0.16 | 网格开始成「尺」 |
| F4 | 0.12 | 0.18 | 坐标读数常驻更明显 |
| F5 | 0.14 | 0.20 | 上限，不再加深 |

- 上限 0.20 是硬线：再高就会盖过像素地块的明度差。
- 这套阶梯只改 alpha，不改线宽、不改颜色、不改数量公式。

### 7.5 为什么这不会变成「通用科幻 UI 贴在奇幻地牢上」

| 通用科幻 UI 的做法 | 本规范的做法 |
|---|---|
| 发光全息面板、蓝黑底 | 无背板、无发光；线是「刻」在画面上的 1px |
| 常驻 HUD 动画、扫描线循环 | 只有事件点动效；扫描最多 2 遍 640ms |
| 显示系统知道但玩家不知道的信息 | 只标 `Map.isSeen` 为真的格子，系统不透视 |
| 悬浮在屏幕空间的卡片 | 全部锚定格边、房间矩形、精灵包围盒，偏移 0–2px |
| 新造一套霓虹色 | 只用第 4 页已有的青/金/灰/绿 |
| 用科技字体和假代码 | 与游戏文案同一 monospace；英文标签只允许 `LV`/`ATK` |

一句话：**它看起来像测绘员在石头上做的记号，不像飞船驾驶舱。**

## 8 与「我独自升级」主题的关系

### 8.1 「独自」

- HUD 右侧没有任何队友槽、没有队伍列表、没有同伴头像——**空着本身就是叙事**。
- 系统只标注敌人、陷阱、容器、楼梯；NPC 是人，不被系统框选，也不被系统指挥。
- 全游戏只有一个「对你说话的声音」，就是系统；它的句式只有三种：测量值、记录、下一步。
- 救援仍是「协议介入」，不是同伴赶来——与本规范同一条设定。

### 8.2 「升级」

- 所有成长都以**差量**出现：`11 → 26（+15）`、`还差 200`、`Lv.11 突破完成`。
- 记录是可见且持久的：HUD 突破缺口、第 4 页成长账本、结局归档章。
- 系统不替你打，只负责「测量你变强了多少」——这正是标题里「独自」与「升级」的交点。

### 8.3 一句话回答

**这个画面里有系统，因为每一层空间、每一次命中、每一点成长，都在被同一套 1px 的线和同一组读数测量、记录、并指出下一步。**

## 10 如果只做一件事

**做 T1「入层测绘」——把 §6.1 的 520ms、§3.2 的网格残迹、§7.2 的房间括号合成一个事件。**

理由：
- 它一次性回答三个问题：这是第几层（层号/格数）、这层怎么被划开（房间括号）、系统还在不在（退去后留下 0.06–0.14 的常驻底纹）。
- 它每局至少出现 5 次（每层第一次进入），是玩家无法错过的画面事件；同时不常驻、不挡战斗、不碰随机数、不碰战斗时钟。
- 成本约 100 行，一个新文件 + 一个绘制钩子，零新素材、零新按键。

一句话答案：**你每次进层，系统先把这个空间量一遍——层号、格数、房间边界在 520ms 内被画出来，又退成底纹；地图不是画出来的，是刚被测量出来的。**

## 16 追加：地图构图与场外边框（D-116，2026-11-19）

本节只追加，不改 §13 的墙体参数、不改 §15 的可交互语法。

### 16.1 选型与理由

候选两条：**A 场外岩壁框**；**B 相机居中 + 四周固定画框**；或两者结合。**只做 A**。

- B 在本作里没有可测收益：F1 在地图小于视口时相机已被夹边居中，390 竖屏上下空白本来就是对称的（±194px），1024 下是 ±212 / ±92。空白"像没画完"不是因为不对称，而是因为**空白没有语义**。
- 硬约束禁止改地块尺寸与缩放，A/B 都不会改变"地图占视口比例"，所以选型的判据只能是"空白读成了什么"。A 直接把洞窟黑换成岩体，B 只是把同一块空白挪个位置。
- 不动相机是零风险：四策略逐局结果与 D-113 基线逐字段相同（`TOTAL_DIFF=0`），构图比例表改前改后一字不差。

### 16.2 场外岩框规则

**层次（由内到外）**

1. 地图沿口 1px 线 `#2b2440`（暗紫，亮度约 0.14，仍远低于地板均值）。
2. 地图外沿 4px 接触阴影 `#040407`：让地图像"嵌进岩体"，不是浮在纹理上。
3. 岩壁层：480×480 无缝贴图（错缝石块 71~78×31~37px，缝 2~9px），石块三档色
   `#191330` / `#120e21` / `#0b0813`，约 7 成石块上沿有 1px `rgba(178,158,220,0.06)` 受光；
   另有 2~3px 碎屑与 1px 裂隙。**任何尺寸都不是 24 的倍数**，不会被读成第二张地块网格。
4. 向内收光：150px 预烘渐变条逐侧叠加，靠地图 alpha=0、远端 alpha=0.62。
5. 最远底色 `#08070e`。

**硬边界**

- 岩壁用 `evenodd` 裁剪在地图矩形之外，**地图内部 0 像素改动**；FOV 黑场仍由原有静态层负责，场外不读任何地图数据。
- 石块色相是**紫**，与地板/墙的棕紫拉开；场外不出现暖棕，也不会出现 24px 对齐的可走质感。
- 贴图在镜头移动/换层时重建一次；每帧仍是 1 次静态层 blit，**每帧绘制调用 0 增量**。

1. 层与层之间**没有音乐差异**，换层只有 `stair` 音效。
2. 音乐状态机只有三档，**没有精英 / Boss / 死亡 / 菜单**，暂停不处理。
3. 音效与音乐**共用一条增益**，命中/暴击全部被音乐同等压着听，无 ducking。
4. 解锁只认键盘；鼠标/触屏玩家首次点击不出声，且解锁前起播会积压。

### 19.2 音乐语言骨架

#### 19.2.1 调式与调中心

**五层各有调中心，不共用主音。** 沿五度圈每往下一层走一步：`A → D → G → C → F`。累计步数就是"离家"的距离，单调递增；五层没有任何一层回到 A。

| 层 | 调中心（根音） | 相对上一层 | 离主调步数 | 调式 | 色彩音 | 听感定位 |
|---|---|---|---|---|---|---|
| F1 | A（A1 55.00 Hz） | — | 0 | 自然小调 | ♭6（F）作邻音 | 空、冷、少 |
| F2 | D（D2 73.42 Hz） | 上四度 | 1 | 弗里吉亚 | ♭2（E♭） | 粗、土、有跺脚感 |
| F3 | G（G1 49.00 Hz） | 上四度 | 2 | 小调 + 三全音 | ♭5（D♭） | 灼、不稳定、在冒泡 |
| F4 | C（C2 65.41 Hz） | 上四度 | 3 | 爱奥利亚 + 大七度 | ♮7（B）作冰晶 | 薄、玻璃、几乎静止 |
| F5 | F（F1 43.65 Hz） | 上四度 | 4 | 小调为骨 + 和声小调导音 | ♮7（E）只在重音位 | 压、仪式、向下走 |

**叙事意图**：四步五度圈是"一层一层往下走"的可听版本——每层都还是同一块地的延伸（四度是最自然的转调），但累计起来已离 A 四步。**F5 的根音 F 正是 F1 主调 A 的 ♭6**：王座前厅不是新的地方，是石厅的阴影。所以 F5 的动机落点停在 F 与 C 上，**不解决回 A**。

**代价（必须接受）**：换层不能再靠 drone 滑音过渡（滑音会滑出调），必须用 §19.4.1 的 **150 ms 全静默**把旧调切断。这 150 ms 是调性迁移的必要成本，不是"卡顿"。

**旋律音域 220–880 Hz**，硬上限 1.2 kHz。理由：`hit` 的基频是 160 Hz、`attack` 是 420 Hz；把旋律抬到 2 kHz 以上会和音效抢同一块频谱。

#### 19.2.2 节奏区间

| 用途 | BPM | 允许误差 |
|---|---|---|
| 探索（F1/F2/F3/F4/F5） | 64 / 84 / 72 / 56 / 88 | ±4 |
| 普通战斗 | 140 | ±6 |
| 精英战斗 | 140（同骨架 + 层） | ±6 |
| Boss | 96 起，仅第 17 回合 +4（上限 **100**） | ±2 |
| 菜单 | 60 | ±4 |
| 死亡 | 自由（下行 sting，不设 loop 速度） | — |

**节奏下限 56 BPM、上限 150 BPM。** 低于 56 会读成"音效拖尾"，高于 150 会读成"通用动作游戏"。

#### 19.2.3 配器（三件套，不得加第四件）

| 轨 | 实现 | 频段 | 备注 |
|---|---|---|---|
| 低频层 | 正弦/三角 drone | 40–110 Hz | 每层最多 2 个固定音（根音 + 五度或 ♭2） |
| 动机层 | 单声部拨弦 / 击弦 / 钟 | 220–880 Hz | 同时最多 1 个音；不叠加和弦 |
| 噪声层 | 预生成确定性噪声 buffer → bandpass | 200 Hz–6 kHz | 岩屑、骨响、风、熔岩气泡各一种；**只在重音位出现** |

**禁止**：弦乐群、合唱/人声、铜管齐奏、军鼓滚奏、任何"渐强到全奏"的交响手法。唯一例外是 F5 的"低铜管替身"（saw + lowpass 700 Hz + 120 ms attack），且只允许在王座层出现。

#### 19.2.4 动态范围与混音天花板

| 指标 | 规格 |
|---|---|
| 输出峰值（master 之后，全部同时） | ≤ **−6 dBFS** |
| 探索 RMS | −28 ±2 dBFS |
| 普通战斗 RMS | −25 ±2 dBFS |
| Boss RMS | −24 ±2 dBFS |
| 菜单 RMS | −32 ±2 dBFS |
| 音乐与音效的 RMS 差 | 任何时刻 ≥ **6 dB**（音效在上） |
| 波峰因数 | ≥ 10 dB（不许压成砖墙） |
| 留白 | 每层曲目 ≥ 12% 时长为"只有 drone 或全静" |
| 同屏最大发声数 | ≤ 12 个 oscillator（含音效），超限时新音效抢占最旧音乐音 |

沿用 `BASE_GAIN`，**不因为加音乐而抬高总音量**。音乐音量靠新总线衰减拿到，不改 master。

#### 19.2.5 循环与结构

- 单层 loop 时长 **≥ 24 s**（F4 建议 32 s），且 ≥ 16 小节。
- 循环点不连续度：首尾各取 100 ms 窗口，RMS 差 **≤ 3 dB**；音高差 ≤ 1 个半音。
- 结构：`drone 常驻 + 8 小节动机单元 × 2–3 次变奏`。变奏只改音色/八度/留白，不改动机轮廓——轮廓是身份，变奏是耐久。
- **不做 4 秒一循环**：短循环会在 30 秒内被听成手机铃声。

### 19.3 五层各自的音乐身份

动机以**相对本层调中心的半音偏移**书写，执行端按此建表，验证页按此断言——同一组偏移在五个调中心上移调，但调式、音色、低频层各不相同。

| 层 | 调中心 | 动机（半音） | 动机形状（音名） | BPM | 主音色 | 低频层 | 视觉锚点（对应规范） | 闭眼识别线索 |
|---|---|---|---|---|---|---|---|---|
| F1 石厅 | A | `0 +7 +8 +7 0 −5 0` | A–E–F–E–A–D–A | 64 | 三角波拨弦，attack 8 ms，decay 900 ms | A1 55.00 + E2 82.41 | D-116 场外岩框：大块静止质量 | 空旷、长尾、每两小节才落一个音 |
| F2 兽人营地 | D | `0 +1 +5 +8 +7 0` | D–E♭–G–B♭–A–D | 84 | 低通 square（1.2 kHz）+ 骨响噪声 | D2 73.42 + A1 55.00 | D-117 砌筑/土地：有模数的块 | 有"干活"的规律脉冲，但没有人声喊号 |
| F3 熔岩裂谷 | G | `0 +6 +7 +6 0 −1` | G–D♭–D–D♭–G–F♯ | 72 | 低通 saw（cutoff 320→900 Hz 慢扫） | G1 49.00 + D2 73.42 | F3 熔岩白热 | 持续低频压力 + 每 2 拍一次"气泡"噪声重音 |

| F5 王座前厅 | F | `0 −2 −3 −5 −7` | F–E♭–D♭–C–B♭ | 88 | 低铜管替身（saw + LP 700 Hz） | F1 43.65 + C2 65.41 | D-116 岩框 + 王座构图 | 每小节第一拍重踏，第二拍空出一拍 |

#### 19.3.1 "五层互不相同"怎么量化

为每层建一个 **7 维指纹**：`(调中心, 调式, BPM 档, 动机轮廓, 主音色, 低频层, 留白率)`。

- **判据**：任意两层之间，**至少 5 维不同**；五层调中心两两不同（根音差 ≥ 2 个半音）；任意两层动机的前 4 个半音偏移序列**不完全相同**。
- 七维全部相同的两层视为同一层——验证页直接判红。
- "只换调中心、其余全同"（同一首移调）也不通过：它只差 1 维，距离 5 维还差 4 维。这条防止五层变成一段移调练习曲。
- 仅"音色不同、动机与速度相同"同样不算区分。

#### 19.3.2 与视觉的对应关系

| 视觉事实 | 音乐上的对应 | 不做的事 |
|---|---|---|
| D-116 场外岩框：厚重、静止、把画面压住 | F1 用长 decay 与 2 小节以上的留白，**音符密度 ≤ 0.5 音/拍** | 不加"岩壁回声"式的连续混响墙（会糊掉命中的 160 Hz） |
| D-117 砌筑/土地：格子、模数、被砌起来的块 | F2 用 8 分音符的规律脉冲，重音落在"块"的边界；节奏网格感来自**间隔**而不是音量 | 不做人声号子；不做打击乐独奏段 |
| D-113 边界：地板/墙亮度分离、3 px 暗边 | F4 用"亮边 + 暗体"：高频钟（亮边）每次只响 1 个音，其余全空（暗体） | 不用连续高频嘶声冒充"冷" |

| 像素 + 矢量混排、克制系统口吻 | 所有音色都带 8–30 ms 的硬 attack，不用慢渐强；动机每层 ≤ 8 音 | 不用 pad 铺底把整首填满 |

#### 19.4.2 Boss 龙威：改的是"层"，不是"曲"

`dragonDread()` 三档各叠一层，全部在 `boss` 曲目内完成，**不重启、不换曲、不改变动机**：

| 档 | 叠加内容 | 增益变化 | 可测效果 |
|---|---|---|---|
| tier 0 → 1（第 9 回合） | 低频 tom 重音，落在每小节第 1 拍 | +2 dB（60–100 Hz 频段） | 该频段 RMS 上升 ≥ 1.5 dB |
| tier 1 → 2（第 13 回合） | 五度音 −18 cent 失谐层 | 中频密度 +1 层 | 频谱峰值数从 1 个基频变为"基频 + 失谐副峰" |
| tier 2 → 3（第 17 回合） | BPM 96 → **100**（只 +4），加 40 Hz sub 脉冲 | 瞬时峰值 +1 dB | 节拍间隔从 625 ms 降到 600 ms ±8 ms |
| 狂暴（独立） | 失真 saw drone | +3 dB（80–200 Hz） | 该频段能量翻倍 |

**不做的**：龙威不切"紧张版主题曲"。一旦换了旋律，玩家会认为换了一场战斗，而战斗本身并没有换。

#### 19.4.3 转场规则（硬性）

1. **决策延迟 ≤ 100 ms**：事件发生到开始淡出，不得超过 100 ms。
2. **驻留门槛 400 ms**：战斗音乐只有在进入战斗状态并持续 400 ms 后才起播；任何 < 400 ms 的状态抖动不触发换曲。
3. **重复抑制 800 ms**：同一曲目在 800 ms 内被再次请求时不重启（沿用现有 `cur !== scene` 思路，扩展到所有 id）。
4. **只在状态边沿触发**：按键、移动、翻页、打开/关闭子页、点击 UI **一律不换曲**。这是"每按一次键就切一次"的反面约束。
5. **战斗结束回探索**：战后结算停留 ≥ 1.2 s，再 500 ms 交叉淡化回该层探索曲。
6. **淡入淡出一律用 equal-power 曲线**，禁止线性交叉（线性会在中点掉 3 dB，听成"音量抖一下"）。
7. **除死亡与 Boss 进入外不做硬切**。硬切只允许出现在这两处，且必须伴随静默窗口。
8. **同层重入不重播**：探索 → 子页 → 探索，曲目保持，不 reset `bgmStep`。

### 19.5 与音效的关系

#### 19.5.1 总线结构（必须新增）

```
master (0.25 × volume，不改)
├─ sfxBus   (1.00)          ← 现有 11 个 SFX
└─ musicBus (0.50 = −6 dB)
    └─ duckGain (1.00 → 按表下压)
        └─ 各层曲目
```

- 新建两条总线是**实现要求**，不是可选项：没有分总线就无法做 ducking，也无法单独关音乐。
- `jingle`（胜利/死亡）绕过 `duckGain`，直接进 `musicBus`——它们本身就是前景声音。

#### 19.5.2 音量配比

| 项 | 值 | 依据 |
|---|---|---|
| `musicBus` 默认 | **−6 dB**（linear 0.5） | 让 `hit`（0.14）高出音乐峰值（0.05）约 8.9 dB |
| 探索 BGM 峰值 | ≤ 0.05（与现有 explore 持平） | 不改现有听感基线 |
| 战斗 BGM 峰值 | ≤ 0.055 | 比探索高 0.8 dB，不靠"更响"表达紧张 |
| `sfxBus` | 1.00（不变） | 音效现有相对关系全部保留 |
| 全局静音 | `master = 0` | 沿用 K 键与既有入口 |
| 用户音量滑块 | 仍作用于 `master` | 语义不变：它是总音量，不是音乐音量 |

#### 19.5.3 Ducking 表

| 等级 | 事件 | 下压 | attack | hold | release |
|---|---|---|---|---|---|
| P0 | `hit`、暴击、升级、`stair` 确认、陷阱触发 | **−6 dB** | 30 ms | 音效时长 + 120 ms | 260 ms |
| P1 | `attack`、`defend`、`gold`、`buy`、`quest` | **−3 dB** | 30 ms | 90 ms | 220 ms |
| P2 | `move`、`run` | 0 | — | — | — |
| 子页常驻 | 背包/商店/任务/NPC 打开期间 | −6 dB | 120 ms | 保持 | 300 ms |
| 暂停 | — | −9 dB + LP 800 Hz | 40 ms | 保持 | 200 ms |
| 学习者页 | — | −12 dB + LP 1.2 kHz | 120 ms | 保持 | 300 ms |

规则：

- **同时触发取最深的那一档**，release 取最长的那一个；不叠乘（−6 与 −3 同时发生仍是 −6，不是 −9）。
- P0 的 hold 必须覆盖音效本体，否则"命中"会变成"半声"。
- 下压只作用于 `musicBus`，`sfxBus` 恒 1.0——**音效永远不被音乐压**。

#### 19.5.4 开关与默认值

| 项 | 规格 | 理由 |
|---|---|---|
| 音效 | **不可单独关闭**，只能随全局静音一起关 | 继承既有"特效硬性常开"的同一条原则：反馈是玩法信息，不是装饰 |
| 音乐 | **可单独关闭**，默认 **开**；只加**开关行**，**不新增音乐音量滑块** | 音乐是氛围，不是判读依据；设置页行数已紧张，加一行开关可以，加一条滑块不行 |
| 用户音量 | 默认 **0.7**（沿用 `aiDungeon_volume`），**同时作用于音乐与音效** | 一条滑块 = 总音量；音乐相对电平由 `musicBus` 固定 −6 dB 决定，不交给玩家二次调节 |
| 全局静音 | 默认关；`K` 键与设置入口同源 | 沿用 |
| 音乐开关的落点 | 设置面板新增「音乐」开关（id `music`，默认 `true`），持久化进既有 `aiDungeon_settings_v1`；**不新增存储键、不新增滑块** | 与音量滑块解耦：滑块只改总音量，开关只决定 `musicBus` 是否接通 |
| 两个静音入口 | **必须合并为一个语义**：主菜单「音效」行改为「全局静音」，设置面板复选框同步；两处读写同一 `settings.muted` | 现状是两个入口各说各话，规格要求单一真值 |

### 19.6 技术路线

#### 19.6.1 路线 A：继续 Web Audio 程序化合成（**推荐**）

**理由**

1. **零文件 = `file://` 双击必可玩**。没有 `fetch`、没有 `decodeAudioData`、没有跨域；这是现有代码已经验证过的路径。
2. **零授权成本**，不需要在 `LICENSE.md` 登记任何素材。
3. **确定性**：合成参数全为常量，`audio.js` 现在零 `Math.random`，不会污染四策略 200 局基线。
4. **与现有实现同构**：`BGM_PATTERNS` 已是"音符数组 + stepMs + 波形"，扩成"每层一张表"是增量，不是重写。
5. **体积**：五层若用 ogg 循环，按 60 s/层估约 4–8 MB；程序化合成是 0 字节。

**代价**

- 音色上限低：做不出真实弦乐/人声，只能做"合成器质感"。这与"像素 + 矢量混排"的美术其实是同一档次的表达，可以接受。
- 需要新写约 400–600 行合成/调度代码；建议单独 `js/systems/music.js`，在 `audio.js` 之后加载，**不改 `audio.js` 既有接口**。
- 噪声层需要预生成 buffer；必须用**固定种子的 LCG**，不得用 `Math.random`，且只能用于音频，不得被模拟层读取。
- 五层各自调中心 → 需要 5 套 drone 频率与移调参数（约 +80 行常量），并放弃"共享 drone 滑音"这条省事路径。

**必须一并修的三个硬点**

| 问题 | 修法 |
|---|---|
| 只认 keydown 解锁 | `init()` 同时监听 `keydown / pointerdown / touchstart`，任一触发即解锁并移除全部三个 |
| 手势前起播积压 | `bgmPlay` 在 context 未 running 时只记 `pendingTrack`，解锁后再起；`nextNoteTime` 每次排程前 `Math.max(nextNoteTime, currentTime + 0.05)` |
| 调度器在暂停时继续跑 | `scheduler` 首行判 `ctx.state !== 'running'` 直接 return；暂停 > 60 s 主动 `suspend()`，恢复时 `resume()` 并把 `nextNoteTime` 钳到当前时间 |

#### 19.6.2 路线 B：落音频文件

**取舍**

| 维度 | 评价 |
|---|---|
| 音色质量 | 明显更好，可做真实乐器与环境录音 |
| `file://` 风险 | `<audio src="...">` 通常可用，但 `fetch` + `decodeAudioData` 在 `file://` 下会被拦截；若走 Web Audio 解码，必须先转 base64 内联，体积再涨 33% |
| 体积 | 五层 × 60 s 循环，ogg 约 4–8 MB；若加 Boss / 菜单 / 死亡，约 8–12 MB |
| 授权 | 必须逐条登记，见下 |
| 授权登记格式（`LICENSE.md`） | 表格列：`文件 | 来源 URL | 作者 | 许可 | 是否需署名 | 获取日期`。优先 CC0；CC-BY 必须在游戏内可访问处给出署名；**禁止**来源不明、仅"免费下载"标注的素材 |
| 确定性 | 文件播放不消耗随机数，对基线无影响；但解码耗时会让首帧抖动 |

**结论**：B 只在"Boss 主题后续拿到可商用授权"时作为局部替换，不作为基础方案。

#### 19.6.3 推荐与迁移顺序

**推荐 A（程序化合成）**，按以下顺序落地，每步都可独立验证：

1. 拆 `sfxBus` / `musicBus` / `duckGain`，保持现有三场景音色与音量不变（听感回归基线）。
2. 扩 `bgmPlay` 接受 `f1..f5 / battle / elite / boss / victory / death / menu`；旧 `explore` 映射到 `f{player.floor}`，旧调用方零改动。
3. 修解锁（三事件）与积压（钳 `nextNoteTime`）。
4. 填五层曲目表（§19.3）与 `battle@fN` 音色槽。
5. 接状态机（§19.4）与 ducking（§19.5.3）。
6. 加 `verify_music.html`（§19.7）。

### 19.7 验收判据（`verify_music.html`）

| id | 断言 | 测法 | 阈值 |

### 19.8 不该做的

1. **循环点短于 24 s** 的洗脑循环——层内停留通常远超 2 分钟。
2. **每层上人声/唱诗/号子**——与"克制的系统口吻"直接冲突，也压不住混音。
3. **战斗音乐铺满、盖住命中**——反馈被吃掉就是玩法事故，不是风格问题。
4. **用音乐替代视觉提示**——楼梯确认、陷阱、可交互物已有 D-113/D-115 的视觉语法，音乐只做氛围。
5. **任何按键/移动/翻页触发换曲**——见 §19.4.3 第 4 条。
6. **在音频里用 `Math.random`**，或让音频读取模拟层随机流——会污染 200 局基线。
7. **运行时 `fetch` 音频**——`file://` 下必失败，且违反零请求约束。
8. **Boss 全程不变**——龙威三档必须可闻，否则第 9 回合的机制升级在听感上是隐形的。
9. **音乐默认关**——多数玩家不会去开；默认开 + 可关。
10. **写成有强主题旋律的"主题曲"**——会抢叙事、也会在 10 分钟后被厌倦。动机要短、要留白。
11. **用 Howler 加载新素材**——现有 vendored 引擎保持原样，不扩用、不新增素材依赖。

### 19.9 裁定记录（2026-11-19）

以下 8 项原为待定，现全部关闭。前 4 项由用户裁定，后 4 项由设计方定；§19 正文已按裁定就地改写，不留"待定"。

| # | 项 | 谁定 | 裁定 |
|---|---|---|---|
| 1 | 音乐是否独立开关 | 用户 | **要**。只加开关行，**不加第二条音量滑块**，音量仍是一条总音量 |
| 2 | 死亡是否单独一段 + 前留静音 | 用户 | **批准**。1.4 s sting → 2.0 s 完全静音 → pad 淡入，静音段保留 |
| 3 | 龙威第 3 档是否提速 | 用户 | **批准 +4 BPM**（96→100）。不再往上加，避免"听得出在赶" |
| 4 | 五层是否共用主音 | 用户 | **否决共用**。五层各自调中心，沿五度圈逐层走一步（A→D→G→C→F） |
| 5 | 菜单是否单独曲 | 设计方 | **单独 `menu` 床**。理由：复用 `f1` 降速会让"菜单"与"第一层"在听感上粘住；代价是多 16 小节合成数据（约 60 行） |
| 6 | 精英是否独立曲 | 设计方 | **加层不新建**。理由：精英出现频繁，独立曲会变成"每场小战斗换歌"；代价是辨识度只能靠音色与失谐，不能靠旋律 |
| 7 | 旧 `bgmPlay('explore')` 是否保留 | 设计方 | **保留签名**，`explore` 映射为 `f{player.floor}`。理由：既有调用方与验证页零改动；代价是接口语义从"场景"变成"场景别名"，必须在文档写明 |
| 8 | 结局页是否有循环 | 设计方 | **无循环**。理由：结局页是读数页，循环会抢文字；代价是结局页几乎全静，只能靠视觉撑住 |
