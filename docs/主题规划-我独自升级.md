# 主题规划：我独自升级

> 状态：只读规划。未修改 `js/`、未改任何数值、未改既有文档。
> 目标：回答“这个主题到底该怎么落、先落哪一步”，不是再写一份功能清单。

## 0. 结论先行

1. **“独自”不是被玩法破坏的，是被文案破坏的。** 全游戏只有一个 NPC（`js/data/npcs.js:14-40`，F1 的守夜人·洛恩），没有队伍、没有同伴、没有召唤物；但自适应救援在任意楼层都以“守夜人递药/塞金币/塞旧剑/把你拽起来”的口吻出现（`js/systems/adaptive.js:151-157`），死亡面板还写着“守夜人还能拉你一次”（`js/systems/modal.js:751`）。机制上是独自下潜，叙述上却像有个保姆跟着。
2. **救援和商店都必须保留，不能为了“更独自”删掉。** 救援是 D-50 的保底：关闭救援的 d49 是 10/50，开启的 d50 是 14/50（`docs/平衡定档.md §11`）；商店是整条经济与 B1 基线的一部分。要改的是“谁在说话”，不是“给不给”。
3. **“升级”链断在 F4→F5 的“我练了”这一段。** F4/F5 层内普通怪都是 3→3 回合、0% 提升（`docs/层内精英-D-69.md §4.2`）；F5 本层经验 544.4，低于 L10→L11 的 600（`docs/升级曲线-D-65.md §3`、`docs/平衡定档.md §4`），练级在最后一层几乎不产生可见台阶。游戏实际靠“打精英必掉一把更强的刀”推进（`js/core/main.js:503-545`、`docs/精英武器曲线-D-72.md §1`），所以体感是“捡到”而不是“练成”。
4. **“系统感”不需要新系统，只需要一面只读的镜子。** 最小形态是：系统语音（救援/死亡/精英三处）+ 一个只读摘要，全部读现有字段（等级/经验/攻击/防御/金币/楼层/本局统计/图鉴/救援次数/精英武器）。不新增战力值、胜率、系统等级这类没有数据源的东西。
5. **失败叙事只换判断，不换事实。** 死因、楼层、差距、救援名额全部保留；把“离下一层”改成“系统评估”，把“守夜人还能拉你一次”改成“系统：应急协议仍可介入 N 次”。不动 `deathCauseText` 的任何来源标签。

## 1. “独自”这条轴

### 1.1 现状盘点：谁在替玩家做事

| 外力 | 代码/数据 | 实际给什么 | 是否必要 | 对“独自”的影响 |
|---|---|---|---|---|
| NPC 守夜人·洛恩 | `js/data/npcs.js:14-40`，仅 F1 | 一次性任务“探路”，60 金币，0 经验 | 教程与唯一活人 | 中：有人味，但他不下场、不给战斗资源 |
| 自适应救援 | `js/systems/adaptive.js:19-24、151-157` | 2 瓶小血瓶 / 60 金币 / 攻击 +13 的旧剑 / F5 原地复活 | **必要**：d49 10/50 → d50 14/50 | **强**：叙述上是一个人在任意楼层递东西 |
| 商店 | `js/systems/shop.js:30-60` | 每层货架、药剂、装备、卷轴 | **必要**：经济与 B1 基线 | 中：没有商人实体，本质是菜单；但标题叫“商店” |
| 精英爆装 | `js/core/main.js:503-545`、`js/data/items.js` | 5 把只掉不卖的武器，逐层 +7/+4/+4/0/+6 | **必要**：当前真正的成长引擎 | **正面**：自己打出来的，最符合“独自” |
| 地牢守门人（T 对话） | `js/data/dialogue.js:9-23` | 攻略提示、氛围对话 | 课程 AI 功能 | 弱：不影响战斗，保留 |
| 等级/技能/图鉴 | `js/systems/battle.js:81-100`、`js/data/skills.js` | 自身成长 | 必要 | 正面：都是“我”的力量 |

**结论：真正削弱“独自”的只有自适应救援的叙述，以及死亡面板那一句。**
依据：NPC 只有 F1 一个（`npcs.js` 的 `list` 只有 `warden_f1`）；救援文案却出现在任意楼层，包括 F5（`adaptive.js:151-157` 的 `f5` / `revive`）。这是叙述与实体数据直接矛盾，不是设计取向问题。

### 1.2 必要的保底，不能删

- **救援必须留。** D-50 的定档就是“能通但不惩罚”：d49（无救援）10/50，d50（救援）14/50，达标线 ≥13/50（`docs/平衡定档.md §11`）。删掉救援会直接把通关率打回不达标，也会推翻 D-49/D-50 的验证基线。
- **商店必须留。** 它是药剂、装备、卷轴的主要来源，也是 B1 经济的一部分；改价格或删货架会推翻 S-01/S-03 与 D-67 的基线。
- **NPC 任务可以留。** 60 金币、0 经验，对数值几乎没有影响（`npcs.js:28-37`）；它是“唯一还留在门口的人”，反而能强化“你一个人往下走”。
- **精英爆装必须留。** 它是“自己打出来的力量”，不需要改叙述。

### 1.3 叙述改写清单（不改数值）

只改“谁在说话”，不改发放内容、触发条件、次数、金额、攻击值。

| 位置 | 现在 | 建议 | 风险 |
|---|---|---|---|
| `adaptive.js:152` MSG[1] | 楼梯口的守夜人递来两瓶小血瓶…… | 系统：检测到濒死。应急补给已注入（2 瓶小血瓶）。本局协议 1/2（已用）。 | 无断言；注意 `n` 是已用次数，不是剩余 |
| `adaptive.js:153` MSG[2] | 守夜人塞来 60 金币…… | 系统：应急额度已划入 60 金币。本局协议 N/2（已用）。 | 同上 |

| `adaptive.js:155` MSG.f5 | 守夜人把整包药塞给你…… | 系统：终局协议启动。补给已注入（一大两小血瓶）。本局协议 N/2（已用）。 | 同上 |
| `adaptive.js:156` MSG.revive | 守夜人把你从地上拽起来…… | 系统：濒死协议介入。战斗继续。 | 末尾的“生命恢复至 X%”由代码追加（`adaptive.js:217`），不要写死 |
| `battle.js:403` | 守夜人把你按回地上…… | 系统：濒死协议介入。战斗继续。 | 无断言 |
| `modal.js:751` | 守夜人还能拉你一次（自适应救援 N/2） | 系统：应急协议仍可介入 M 次（已用 N/2） | M = `MAX_TRIGGERS - N`，真实值 |
| `items.js` 的 `sword_rescue.name` | 守夜人的旧剑 | 残响·旧剑 | id/攻击/价格/卖出价不变；D-49 只断言 id/atk/price/sell |

**建议保留不改的：**
- 商店标题“商店”不改。它没有商人实体，本身已经像系统菜单；改标题会牵动按键表、帮助文案和 D-20 的键位审计，收益小于成本。
- NPC 名字“守夜人·洛恩”不改。他是 F1 唯一活人，留着他能让“独自”有对照：有人留在门口，没人跟你下去。
- 精英卡片标题“精英之证”不改。`verify_d70.html` A7 明确断言 `titles[0] === '精英之证'`。

### 1.4 这一轴的结论

**“独自”该落的不是“删掉帮助”，而是“把帮助改写成系统”。** 爽文里的“独自”从来不是没有外挂，而是没有同伴；系统是主角独有的东西，不是外力。当前代码已经把系统该做的事做完了（保底、补给、复活），只是把它写成了一个会瞬移的守夜人。改 8 条字符串，就能让机制不变、主题归位。

## 2. “升级”这条轴

### 2.1 爽文链路与当前实现

爽文链路：**打不过 → 我练了 → 我碾压**。
当前实现的三段分别是：

- 打不过：F5 Boss / 深层怪物；
- 我练了：等级 + 装备 + 精英之证；
- 我碾压：面板提升后，普通怪从 N 回合变 1–2 回合。

### 2.2 实测：哪一段断了

**（a）F4/F5 的“层内成长”是 0。**

| 层 | 层内普通怪中位回合（D-69，精英后） | 变化 | 层内 atk（D-68，精英前口径） | 本层经验（D-65） |
|---|---|---|---|---|
| F1 | 4 → 3 | -25% | 11 → 18 | 139.0 |
| F2 | 5 → 3 | -40% | 19 → 22 | 622.2 |
| F3 | 3 → 2 | -33% | 29 → 33 | 476.6 |
| F4 | 3 → 3 | **0%** | 33 → 39 | 756.7 |
| F5 | 3 → 3 | **0%** | 40 → 40 | 544.4 |

依据：`docs/层内精英-D-69.md §4.1/§4.2`、`docs/层内爽感-D-68.md §3`、`docs/升级曲线-D-65.md §3`。
说明：D-68 是精英实装前的口径（F1 5→3、F2 5→4、F3 4→3、F4 4→3、F5 3→3）；D-69 把精英战利品算进去后，中段变好，但 **F4/F5 仍然是 0%**。D-72 只改五把刀的数值，没有再测三时点，所以这条结论沿用 D-69；若要把“F4/F5 0%”当作当前版本的硬结论，落地前应补一次 D-69 同口径复测。本规划把它当作“已记录的设计事实”，不当作新版本实测。

**（b）“练了”在 F5 不产生台阶。**
F5 本层经验 544.4，L10→L11 需要 600（`docs/升级曲线-D-65.md §3`、`docs/平衡定档.md §4`），出层等级约 10.33。也就是说，清完 F5 也未必能稳定跨一级；D-68 实测 F5 层内 atk 40→40（精英前口径）。精英武器会带来一次固定跳变，但那是“打赢精英掉刀”，不是“练级”。

**（c）“碾压”在 F4 撞到整数地板。**
按 D-69 口径：F4 出层 atk 47，打 88 HP / def 10 的大僵尸是 3 回合；压到 2 回合需要约 52 atk。F5 出层 atk 50，压到 2 回合需要约 55–65（`docs/层内精英-D-69.md §4.4`）。当前面板离下一档差 5–15 点，正好是“看得见、够不着”。

**（d）“打不过”只在 F5 成立。**
B1（只打 Boss、绕精英）当前 48%（24/50，死 23、空转 3），B1 到达 F5 是 42/50；M1（全清）是 50/50（`docs/精英武器曲线-D-72.md §3`、`docs/平衡定档.md §22`）。对全清玩家来说，F1–F4 几乎没有“打不过”，真正的墙只有 F5 Boss；而对冲层玩家来说，墙在 F5，但“练了”的补救手段也恰好最弱。

### 2.3 这条链到底断在哪

**断在 F4→F5 的“我练了”。**
- “打不过”只在 F5（B1 48%，M1 50/50）；
- “练了”在 F5 不成立（544.4 经验 < 600，出层约 10.33 级）；
- “碾压”在 F4 撞整数地板（3→3，需 52/55–65 攻）；
- 装备曲线在 F3→F4 是 +0，F4→F5 才 +6（`docs/精英武器曲线-D-72.md §1`），和“F4 层内 0%”正好重合。

换句话说：**当前游戏不是“打不过→练级→碾压”，而是“打精英→必掉一把更强的刀→继续推进”。** 这不是 bug，是 D-71/D-72 的设计结果；它让节奏稳定，但让“升级”的体感变成了“捡装备”。

### 2.4 这一轴的结论

**不要用文案假装“练级”存在，也不要在本阶段动数值。** 现有数据足以让玩家看见“我变强了”，只是游戏没有把它汇总出来：
- 本局等级/攻击/防御的前后值；
- 本局击杀、回合、药水、救援；
- 已获得的精英武器；
- 图鉴进度。

把这些放进“系统”摘要，比改经验曲线更安全，也更符合 D-70 已有的“把真实前后值摆出来”的做法。若未来一定要修“练了”，最干净的数值杠杆是**给精英经验**（当前精英 `exp: 0`，见 `js/data/monsters.js` 的精英条目），但这会推翻 D-65/D-66/D-67/D-68/D-72 的全部基线，本阶段不做。

## 3. 系统感

### 3.1 先定义：系统感不是新系统

爽文里的“系统”有三个特征：只对主角说话、只报真实状态、给出下一步。当前游戏已经有这些数据，只是分散在 HUD、图鉴、结局评级、D-70 卡片里。**最小可行的系统感 = 一个只读聚合层 + 一套系统语音，不是新的成长系统。**

### 3.2 最小可行形态

**MVP-0（真正最小，推荐先做）：**
- 系统语音：救援、死亡、精英战利品三处（这三处的文案没有被验证页锁死）。
- 一行只读摘要：打开 M 面板时，在页脚/页头显示
  `系统 Lv.{等级} · ATK {攻击} · DEF {防御} · 击杀 {本局击杀} · 救援 {已用}/2`
  （花括号是真实字段的位置，不是示例数值）
- 不新增按键、不新增页签、不新增存档字段、不新增数值。
- 如果放在页头，需要同步调整 `visibleRowCount` 并人工复核行位；优先放在页脚，避免改变列表可见行数。

**MVP-1（“系统面板”的正式形态，第二步）：**
- 从暂停菜单进入一个只读页面（不占用新的探索按键）。
- 三块：状态 / 本局记录 / 已解析档案。
- 只是把 MVP-0 的一行展开，数据源完全相同。

**不推荐作为 MVP：**
- 新增 V 键：会触发 D-20 的按键表双向审计（`preflight/verify_d20.html` A1），还要补 `Render.KEYMAP`、HTML 按键表、回放行为。
- 给 M 面板加第四个页签：会破坏 M8-4 的三页签环形逻辑（`js/systems/modal.js:341-346`），`verify_m8_4.html` 的页签断言需要重写。
- 新增 HELP 条目：`verify_d48.html` D 组断言 `HELP.length === 8` 且 id 列表固定。

### 3.3 面板读哪些真实数据

| 面板字段 | 真实来源 | 是否已存在 |
|---|---|---|
| 等级 / 经验 / 距下一级 | `Player.level`、`Player.exp`、`Battle.expToNext(level)`（`battle.js:97-100`） | 是 |
| HP / MP / 金币 / 楼层 | `Player.hp/maxHp/mp/maxMp/gold/floor`（`save.js:32-46`） | 是 |
| 攻击 / 防御 / 生命上限 | `Player.atk/def/maxHp`，由 `Inventory.recalcEquip` 重算（`inventory.js:113-140`） | 是 |
| 武器 / 护甲 / 强化等级 | `Player.equipment`、`Player.upg`、`Inventory.effValue`（`inventory.js:96-111`） | 是 |
| 本局击杀 / 回合 / 药水 / 救援 / 最高等级 / 最深层 | `Main.getRunStats(true)`（`main.js:777-797`） | 是 |
| 图鉴进度 | `Bestiary.data.monsters/items` 的 key 数；总数来自 `MONSTERS`/`ITEMS`（18 / 48） | 是 |
| 当前层 Boss | `MAPS.bosses`（`maps.js:45-49`）+ `MONSTERS[id]` | 是 |
| 救援记录 | `Adaptive.snapshot().triggers/spent/log/deaths`（`adaptive.js:277-285`） | 是 |
| 任务进度 | `Quest.getActive()`（`quest.js:66-80`） | 是 |
| 精英武器持有 | `ITEMS[id].elite` + 背包/装备栏；5 把（`main.js:503-545`） | 是 |
| 本局起点攻击（可选） | 在开局记录一次 `runStats.startAtk`；不参与伤害/掉落/价格 | **否，需新增一个只读快照** |

**禁止显示的“数字”：**
- 胜率 / 通关率 / 本次成功率：没有运行时统计字段。
- “战力值”：没有这个公式；显示就是编。
- “系统等级”“猎人等级”“技能点”“天赋”：游戏里不存在。
- 未遭遇怪物的 HP/ATK/DEF：图鉴已经约定“未遭遇显示 ???”（`README.md` 功能列表），系统面板必须遵守，否则会破坏探索。
- 掉落率 / 下一层怪物数量：数据里有，但不是当前 UI 口径；MVP 不引入。

**允许的推导数字（必须标明是估算）：**
- “对同层普通怪约 3 回合”：用现有伤害公式和 `MONSTERS` 的 HP/DEF 静态复算，和 D-68 的 `killRounds` 同口径。
- “距下一级还差 X 经验”：`expToNext(level) - exp`，真实可复算。
- “应急协议剩余 N 次”：`MAX_TRIGGERS - triggers`，真实。
- **凡是没有来源的数字，一律不显示。**

### 3.4 只读契约（防止把“系统”做成第二个游戏）

系统面板必须满足：
- 不调用 `Adaptive.onDeath/onFloorArrived/reviveInPlace`，只调用 `snapshot()`；
- 不调用 `Shop.getStock()`（它会 `syncFloor`，换层时重置商品轮换 tick），只读 `Player`/`ITEMS`；
- 不调用 `Battle.checkLevelUp`，只调用 `expToNext`；
- 不调用 `Quest.progress`，只调用 `getActive/isDone`；
- 不调用 `Map.generate`，只读 `MAPS`；
- 不掷随机数、不写存档、不改变任何 `Player` 字段。

满足这六条，面板对逐局指纹的影响为 0；D-70 已经证明“纯表现层 + 零随机”可以是 0 差异。

### 3.5 系统语音的时点

| 时点 | 现有载体 | 可以怎么说 | 不能怎么说 |
|---|---|---|---|
| 救援 | `adaptive.js` 的 `ui:notice` | 系统：濒死协议介入。本局协议 N/2（已用）。 | 不能写“剩余 N/2”（N 是已用次数） |
| 死亡 | `modal.js` 的 gameover 面板 | 系统评估：还差 8 回合…… | 不能改 `deathCauseText` 的来源标签 |
| 精英战利品 | `main.js:532-535` 的 `ui:notice` | 系统：精英战利品【断牙】攻击 8（面板 11 → 18，已装备）。 | 不能改 D-70 卡片标题“精英之证” |
| 升级 | D-70 升级卡片 | 卡片标题已被 D-70 A6 锁死（`升级！Lv.1 → Lv.2`），不要加前缀 | 不要为了“系统感”改已验证的卡片标题 |

### 3.6 这一轴的结论

**先做“系统语音 + 一行只读摘要”，不要先做新面板。** 系统感来自“它只报真实数据、而且只对我说话”，不来自多一个界面。等语音和摘要稳定后，再把摘要展开成暂停菜单里的只读页；那才是“面板”，但它不是第一步。

## 4. 失败的叙事

### 4.1 现状

死亡面板（`js/systems/modal.js:727-752`）的顺序是：

1. `死因：被地牢巨龙打死（第 5 层）` —— 事实，且被 `verify_d52.html` B 组断言；
2. 本局统计：层数 / 击杀 / 等级 / 回合 / 药水 / 救援 / 用时 / 金币；
3. `离下一层：还差 8 回合（怪物剩 118 HP，每回合约 15 伤害）`；
4. `守夜人还能拉你一次（自适应救援 1/2）`。

问题不在信息量，在语气：它像验尸报告，而且最后一句把“失败”交给了一个人。

### 4.2 改写原则

- **事实全部保留**：死因、楼层、统计、差距、救援名额都是可复算数据，不能动。
- **只换判断**：把“离下一层”改成“系统评估”，把“守夜人”改成“系统协议”。
- **不怪运气**：爽文语感是“我还不够强”，不是“这局运气差”。
- **不承诺假机制**：不要说“系统会帮你复活”，除非 `canRescue` 真的为真。
- **不加行**：gameover 面板高度固定（`HEADER_H + 300 + FOOTER_H`），加行会挤按钮；用“替换同位置文案”的方式改。

### 4.3 具体文案

**推荐版（克制，适合课程展示；下面的“还差 8 回合”是示例，实际由 `st.gap.text` 生成）：**

| 位置 | 现在 | 建议 |
|---|---|---|
| 标题 `modal.js:841` | 冒险结束 | 系统评估：未达标 |
| 第 3 行 `modal.js:746` | 离下一层：还差 8 回合…… | 系统评估：还差 8 回合…… |
| 第 4 行 `modal.js:751` | 守夜人还能拉你一次（自适应救援 N/2） | 系统：应急协议仍可介入 M 次（已用 N/2） |

**爽文版（语气更冲，供选择）：**
- 标题：`系统：任务终止`
- 第 3 行：`系统评估：强度不足，不是运气。还差 8 回合。`
- 第 4 行：`系统：应急协议仍可介入 1 次。是否重启？——是。`

**救援文案示例（与 1.3 一致）：**
- 死亡触发：`系统：检测到濒死。应急补给已注入（2 瓶小血瓶）。本局协议 1/2（已用）。 生命恢复至 50%。`
- 金币触发：`系统：应急额度已划入 60 金币。本局协议 2/2（已用）。`
- 旧剑触发：`系统：武器解析完成——【残响·旧剑】攻击 +13。本局协议 N/2（已用）。`
- F5 原地复活：`系统：濒死协议介入。战斗继续。 生命恢复至 60%。`（百分比由 `adaptive.js:217` 追加，不要写死）

### 4.4 不能动的字符串

| 字符串 | 位置 | 断言 |
|---|---|---|
| `死因：` 后面的来源标签（怪物名/陷阱/中毒/流血） | `main.js:273-316` `deathCauseText` | `verify_d52.html` B 组 |
| 结局页的 `被救援：N 次` 等统计标签 | `main.js:318-329` `endingLines` | `verify_d52.html` |
| `升级！Lv.1 → Lv.2` / `升级！Lv.1 → Lv.4（连升 3 级）` | D-70 卡片 | `verify_d70.html` A6 |
| `精英之证` | D-70 卡片标题 | `verify_d70.html` A7 |
| `精英战利品不可出售` | `shop.js` | `verify_d71.html` A7（只要求包含“不可出售”） |
| 五把精英武器的名字/攻击/价格 | `items.js` | `verify_d72.html` |
| `F` 键不绑定战斗功能 | `main.js` | `verify_d78.html` A4 |

### 4.5 这一轴的结论

**死亡不需要“更温柔”，需要“更像系统”。** 保留验尸数据，把它从“死因报告”改成“系统评估”；把最后一根救命稻草从“守夜人”改成“应急协议”。这样失败仍然清楚，但语感从“我被人救了”变成“我的系统判定我还不够强”。

### 5.1 先落哪一步

**先做 P0，再做 P1，最后做 P2。**
- P0 是零数值风险、零断言风险、改动最小的一步；它直接回答“为什么游戏叫独自升级，却像有个守夜人跟着”。
- P1 紧接着把失败的语气改对；它和 P0 是同一套“系统语音”，可以一次文案走查完成。
- P2 才需要碰 UI 布局；在没有把语音跑通之前，先做面板容易变成“多一个界面，少一点味道”。

### 5.2 为什么 P4 现在不做

D-68 已经裁定“F4/F5 的层内成长不再追”，D-70 裁定“精英卡不换标题”，D-72 的数据支持“F3 可以不用换刀”。这些是已经过验证的取舍。为了主题去改经验/血量，会同时推翻 D-65/D-66/D-67/D-68/D-72 和 B1 带宽；而主题真正缺的不是数值，是**把已有成长讲出来**。所以本阶段只做叙述与只读聚合。

## 8. 一句话收尾

**这个主题不需要再做一个系统，它需要让现有的系统“开口说话”。**
先把救援和死亡从“守夜人”改成“系统”（P0/P1），再把本局成长做成一行只读摘要（P2）；数值、层数、怪物、物品都不动。这样“独自”是叙述上的独自，“升级”是看得见的升级，“系统”是只报真实数据的系统。
