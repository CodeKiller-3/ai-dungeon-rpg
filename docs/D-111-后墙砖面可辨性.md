## 1. 判据先行：纯砖面怎么取（代码可复算）

取样规则全部写在 `verify_d104.html` 里，不靠人眼挑：

1. **比例矩形**（`WALL_SAMPLES`）：矩形本身避开拱门、王座、帐篷、栅栏、崖壁内缘与楼梯口。

   | 层 | 矩形（x0,y0,x1,y1，比例） | 说明 |
   |---|---|---|
   | F1 | 0.30,0.08 → 0.70,0.52 | 石厅中央连续砖面，避开左右火把与中央暗拱 |
   | F2 | 0.30,0.08 → 0.70,0.52 | 营地后墙，避开两侧火把与帐篷顶 |
   | F3 | 0.06,0.06 → 0.27,0.27；0.73,0.06 → 0.94,0.27 | 熔岩裂隙只取左右两段砖面（中段是黑缝+熔岩） |
   | F4 | 0.40,0.08 → 0.60,0.55 | 霜墓中央，避开冷白烛光与两侧冰晶 |
   | F5 | 0.35,0.06 → 0.65,0.52 | 王座厅中央，避开王座与垂旗 |

2. **内缩 3px**：每个矩形四边各收 3px，排除边缘过渡像素。
3. **彩色像素剔除**：矩形内逐像素算 `max(R,G,B)-min(R,G,B)`，`> 28` 判为金脉/熔岩/火光/烛光/垂旗等
   发光或装饰像素并丢弃；灰阶砖面（色差 ≤22）保留。
4. **覆盖率下限**：保留像素数 / 矩形总像素 ≥ 0.60，否则判负——防止「样本被装饰吃光后只剩几个亮点」冒充砖面。

亮度一律 `0.299R+0.587G+0.114B`。判据（每层各一条，共 4×5）：

- `d111.wall.F.pureLower`：纯砖面均值 ≥ 16
- `d111.wall.F.pureRange`：`p95 − p05` ≥ 10
- `d111.wall.F.pureSubordinate`：纯砖面均值 ≤ 该层地面均值 × 0.55
- `d111.wall.F.pureShare`：`keptShare` ≥ 0.60

## 3. 负例（两条都必须能真红）

### 3.1 还原旧砖面 → 必须判负

`paintOldWall()` 把取样矩形恢复成 D-110 之前的底色，并叠上旧版「中心压暗 × 墙压暗」的等效衰减
（`OLD_DIM = 0.40 / 0.34 / 0.16 / 0.48 / 0.34`），其余像素（拱门/火把/边缘）保持现行版本——
精确复刻复判说的「带亮砖不亮」。

| 层 | 旧砖面均值 | 旧 p95−p05 | 旧带均值 | 判负原因 |
|---|---:|---:|---:|---|
| F1 | 11.84 | 4.46 | 14.9 | 均值 < 16 |
| F2 | 11.14 | 0.00 | 14.8 | 均值 < 16 且无层次 |
| F3 | 22.56 | 0.00 | 15.5 | 平涂无层次（range < 10） |
| F4 | 12.58 | 2.70 | 17.2 | 均值 < 16 且层次不足 |
| F5 | 12.40 | 0.00 | 15.8 | 均值 < 16 且无层次 |

`d111.neg.F.oldBrickFails` 断言「整条规则套旧砖面必须为 false」；证据：
`preflight/artifacts/d111/d111-oldbrick-FAIL.log.html` / `.png`（五层逐层给出旧值）。

### 3.2 只提亮拱门/边缘 → 也必须判负（本卡关键负例）

在旧砖面上按上一轮做法只加三样：顶边 12px 暖光、左右 12px 竖边、画面 15.5% 处一团火把径向光晕。
砖面像素一个不动。

| 层 | 砖面均值（应仍 < 16 或 range < 10） | 带均值 | 带均值抬升 |
|---|---:|---:|---:|
| F1 | 11.84 | 19.2 | +4.3 |
| F2 | 11.14 | 19.2 | +4.4 |
| F3 | 22.56（range=0） | 20.0 | +4.5 |
| F4 | 12.58 | 21.4 | +4.2 |

判定条件同时要求两件事：**带均值必须被抬高 > 2**（证明负例确实生效、不是空转），
**且砖面判据必须仍判负**。这正是防「看起来变亮了其实没变」。

## 8. 附带修正（披露）

`verify_d100` 的 D 段（键盘 vs 点击同状态对照）在随机地图下约 1/5 概率判负：
C 段探索可能踩到带「流血」的陷阱（S-04），玩家状态跨段残留，并在 D 段两次 `B.start` 之间继续按回合 tick，
于是 key 路径是「流血剩 1 回合」、click 路径是「流血消退」，两份快照的 `php` 与 `log` 必然不同。

修法是在 D 段开头 `Status.clearAll()` 做前置隔离，让该段只比较输入通道本身；
状态结算由 S-04 既有断言覆盖。这是**隔离测试状态**，没有放宽任何判据——
`D_battleClick` 仍然要求 `viaKey === viaClick`、`noMpKey === noMpClick`、cursor `pointer/default`。
修后连跑 10 次全部 PASS（修前 10 次里 1 次 FAIL）。
