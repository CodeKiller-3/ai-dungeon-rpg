# 已知缺陷（D-110 登记）

本文件登记**验证页不放宽、但当前代码确实做不到**的行为缺陷。每条写清：现象、判据为什么不能放宽、归属哪张卡。

---

## D-110-1 · bot 在"本层目标被清空"后原地空转到 maxActions

- **现象**：`preflight/lib/d17_bot.js` 的 `stuckReason()` 会返回 `本层无可用目标`。这类局的 `outcome` 是 `stuck`，`actions` 停在 `maxActions`（2500/4500/6000），但地图结构本身没有堵路（全格 BFS 能到下行梯）。
- **为什么不是合法状态**：这不是"地图生成问题"，而是 bot 策略缺陷——bot 已有 stairs / boss 阶段与探图兜底（`preflight/lib/d17_bot.js:378`、`:1244-1249`、`:1440-1456`），但仍会在 `本层无可用目标` 的判定下空转到 maxActions。根因待下一张 bot 卡定位，不能再用"缺下行梯兜底"描述（该兜底已经存在）。真人不会这样卡住。
- **为什么验证页不放宽**：把 `outcome === 'stuck'` 从失败改成可接受，等于用验证页替产品行为开脱。`verify_d38` D 组维持"不许 stuck"，样本换用真正不卡死的种子 1012；旧种子 1013 保留为负例（`D2_negativeOld1013Stuck`，现在必须判 stuck）。
- **归属**：bot 策略卡（下一张），修的是 `preflight/lib/d17_bot.js` 的收尾策略，不是判据。
- **复现**：`verify_d38` 的 `D2_negativeOld1013Stuck` 会把 1013 的 `stuckReason` 打印出来。
