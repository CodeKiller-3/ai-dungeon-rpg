## 2. 新的优先级顺序

1. **E-R1 地图构图/场外边框**（原 E-P0-2 + E-P2-7）
   - 改什么：地图小于视口时加 1px 双线框 + 四角刻度 + 场外 8×8 噪点/暗角；竖屏改为贴 HUD 下沿而不是垂直居中。
   - 为什么排第一：它出现在**每一层、每一个尺寸**；F1 只占 41.7% 屏面积，是当前探索最大的“没做完”信号；纯渲染，不动地图/碰撞。
2. **E-R3 可交互物统一标识（楼梯为主）**
   - 改什么：楼梯/金币/药水统一 1px 金色内描边 + 地面投影；X2 提到 0.5/2px 或换成地面箭头；不给藤蔓/木桶加。
   - 为什么排第二：它影响“能不能找到出口”，是玩法可读性；D-113 把墙压黑后，深色楼梯与墙内缘更容易混。
3. **E-R2 F1/F2 层辨识**
   - 改什么：只给 F1 或 F2 加一个结构母题（F2 兽骨地板细节 `bones` + 木桶 `barrel`，或 F1 `wall_outer_*` + 火把/木桶），覆盖 ≥8% 可走格；不调 tint alpha。
   - 为什么排第三：F3/F4/F5 已能靠色相分开，只剩 F1/F2 一对；这是“主题记忆点”，优先级低于构图与出口。
4. **S-R1 窄档信息完整性**
   - 改什么：390 读数带补 `ATK12`（320 可只留左簇）；窄档档案行改两行 `精英 0/5 · 图鉴 0/18` / `任务 0/12`，或图标 + 数字。
   - 为什么排第四：只在 390/320 出现，影响面小；但两项都是“信息在窄档消失/变缩写”，一次 QA 矩阵可以一起验收，所以合并成一张。
5. **不建议排期**：T1 文案/时长（S-P1-4 已关闭；要做只能算 P3 品牌微调）、图鉴/物品 `???` 占位（属菜单域 8.1 的内容解锁态，不是系统层 7.7 的视觉缺陷）。

## 3. 合并 / 拆分建议（批次边界）

- **合并 E-P0-2 + E-P2-7 → E-R1**：
  - 同一对象（地图矩形与场外），同一套修复（框、刻度、暗角、竖屏锚点），同一组验收（占屏 ≥60%、空白 ≤80px、无直边）。
  - 拆开会让第二张卡只能重复第一张的边框代码，属于人为制造依赖。
- **合并 E-P1-5 + E-P1-6 → E-R3**：
  - 同一视觉语言（可交互物 vs 纯装饰），同一实现点（`_drawDecor` 的描边/投影分类 + X2），同一验收（3/3 指认）。
  - E-P1-6 的“纯装饰也要区分”已无必要；只保留“可交互物要统一”，并进 E-P1-5，避免两次美术 pass。
- **E-R2 必须单独一张**：
  - 它是“层主题母题”，改的是地板/装饰内容与盲测验收，和构图/描边没有共享代码；合进去会让一张卡同时改相机、装饰、层主题，无法回滚。
- **合并 S-R1 + S-R2 → S-R1**：
  - 两项都是“窄档文字完整性”，共用 390/320 两档验收矩阵；每项 <10 行，合并后一次截图 QA 即可。
  - 如果评审要求按文件隔离，可拆成 `sysviz.js` 与 `modal.js` 两张；但不建议，因为拆开后两张都要重复同一套窄档验收。
- **T1 不与 S-R1 合并**：
  - T1 是瞬时覆盖层的时长/文案，S-R1 是静态读数布局；验收完全不同（像素亮度/时长 vs 文本出现次数）。
- **`???` 页不并入系统卡**：
  - 它属于菜单域 8.1 的“未解锁态内容表达”，本轮系统层不背这个债。

### E-R1 地图构图：小地图浮在暗场里，竖屏上下留白

- **现象**：1024 逻辑下 F1 地图 600×456（**41.7%** 屏面积）、F2 696×504（**53.5%**）；F1 960 下 52.8%。390×844 下 F2 宽 696 > 390（左右裁），高 504 < 844，**上下各约 170px 空白**。地图外是平涂暗场，地图矩形是一条无处理的直边，没有框/暗角。
- **尺寸档/层**：1024×640、960×540、390×844；**F1/F2 最明显**，F4/F5 接近填满。
- **证据**：`preflight/artifacts/d113/d113-F1-1280x800-full.png`、`d113-F2-1280x800-full.png`、`d113-F1-960x540-full.png`；`preflight/artifacts/aeval-1118b/explore-f2-390x844.png`（旧对比度，几何未变）；`js/core/render.js:2355-2358`。
- **判据**：1024 下 F1/F2 地图占屏 **≥60%**，或地图外有 1px 双线框 + 四角 6px 刻度 + 暗角；390 竖屏上下空白 **≤80px**；画面里不再出现一条无处理的 600×456 直边；场外/未探索/已探索至少 **3 个亮度台阶**。
- **改法方向**：纯渲染，不改 `TILE`/关卡尺寸。① `_updateCam` 在 `h <= H` 时把 `cam.y` 贴到 HUD 下沿（`28+14+8`），不再 `-(H-h)/2`；② 地图外画 1px 双线框 + 四角刻度；③ 场外 8×8 噪点 ≤4% alpha 或 8px 羽化；④ 不要给未探索区提亮（避免泄露地形）。
- **预计**：**7.55→7.65**；单卡增量约 +0.10。

### E-R3 可交互物统一标识：楼梯和墙内缘都是近黑方块

- **现象**：D-113 把墙身压到 0.70、墙内缘 0.90 黑；楼梯/坑洞本身是深色贴图，在 F2/F5 的亮地板上是一个近黑方块，和墙内缘的视觉重量接近。X2 仍是 1px、臂长 5、alpha **0.28/0.32**，没有帮忙。宝箱/金币/药水已有金边或颜色，问题集中在**楼梯**。
- **尺寸档/层**：F2/F5 最明显；1024/960/390 都有。
- **证据**：`preflight/artifacts/review-1118c/stair-crop.png`（F2 当前楼梯/墙内缘）；`preflight/artifacts/aeval-1118b/target-f2-1024x640.png`（X2 旧图，alpha 未变）；`js/systems/sysviz.js:235-237`；`js/core/render.js:2112`（`edge:0.90`）。
- **判据**：1024 截图上站在 3 格内，**3/3 测试者 1 秒内**指出楼梯；楼梯格有独占的 1px 金色内描边或 6px 四角标；X2 alpha **≥0.5**、`lineWidth=2`、臂长 ≥7，或不靠 X2、直接在地面画 24×24 楼梯图标；仍不覆盖玩家包围盒（2px 排除）。
- **改法方向**：楼梯在 `render.js:3025-3042` 的 `t===2/3` 分支加 1px 金色内描边或 6px 四角标；`_drawDecor` 只给 `gold_pile`/`potion_stash` 补 `groundShadow`；藤蔓/木桶/骨堆不加。X2 提到 0.5/0.55、2px；如果描边已足够，X2 可以只保留给“可见但不在同屏的容器”。
