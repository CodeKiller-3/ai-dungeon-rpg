## 0. 这次的口径（先定尺，再打分）

旧的 A–D 四档是给“整部作品”用的，主菜单只有一屏，四档分不开。这次改用 **10 分制、两轴独立**：

| 轴 | 10 分代表什么 | 扣分点 |
| --- | --- | --- |
| **完成度** | 三档视口都能用；信息层级清楚；无破损/溢出/重叠；状态文案自洽；危险动作安全；界面承诺与实际一致 | 文案矛盾、跨档错位、信息重复、状态不可辨 |
| **艺术性** | 有明确作者选择（构图、光、材质、叙事）；视觉语言统一；焦点层级成立；不是文字堆叠；与地牢内同源 | 焦点被抢、字体分裂、静态无叙事、右栏仍是通用列表 |

**不要把 7.5 直接和旧 D+ 换算**：旧的是四档粗判，新的是 10 分细判；真正的对比是同一屏的 before/after 实拍（[compare-1024x640-empty.png](../../preflight/artifacts/d93/compare-1024x640-empty.png)）。

## 2. 逐档判决

### 2.1 1024×640（主档，左右分栏）——[无档](../../preflight/artifacts/d93/after-1024x640-empty.png) / [有档](../../preflight/artifacts/d93/after-1024x640-save.png)

**看到什么**：左侧 10×7 格、48px 瓦片的“地牢门口”静帧：墙上双扇门、向下暗井、三级台阶、左侧火把、门前一名 2× 骑士、门缝一条竖金线；右侧 360×448 暗栏：`DUNGEON / ENTRANCE`、金色标题、五项菜单、底部 `Lv.1 → 第 5 层` + 四枚石钉 + 龙。整屏是“左边一张画，右边一块状态栏”。

**完成度：8.5 / 10**
- 不破损、不溢出、不重叠；三档的核心断言（菜单右缘 ≤ 面板右缘、提示基线 ≤ 面板底、进度标签右端 ≤ 终点符号左缘）都成立。
- 上一轮的不实承诺“鼠标可点（非必需）”已不再出现，底部只写 `↑↓ 选择 · Enter 确认`，与真实输入一致。
- 对比度达标：普通 12.84、金色 13.72、禁用 5.30、副标 7.68、提示 5.57、警告 6.98、进度标签 8.46（[pixel-proof.json](../../preflight/artifacts/d93/pixel-proof.json)）。
- 扣分：**第 5 层通关档的文案自相矛盾**——标签写 `第 5 层 · Lv.13 → 第 5 层`，下面又写“已抵达”（[render.js](../../js/core/render.js#L2686)、[render.js](../../js/core/render.js#L2959-L2962)）。系统状态不能既“去第 5 层”又“已抵达”。这是可达状态，不是理论边界。
- 扣分：有档时“继续游戏”行内详情与底部进度标签重复同一组 `第 N 层 · Lv.X`（[render.js](../../js/core/render.js#L2905-L2917) vs [render.js](../../js/core/render.js#L2933-L2937)）；第 5 层时再加一个“已抵达”，同一信息出现三次。
- 扣分：`DUNGEON / ENTRANCE` 是英文眉标，右侧其余全中文；不致命，但它是这块面板里唯一没有“系统读数”功能的字。

**艺术性：7.5 / 10**
- 这是主菜单第一次有**构图**而不是排版：小火把、大暗门、小骑士、向上的墙与向下的井；视线从左上的火，经过骑士的红帽，落到门缝。它是一张能讲故事的画。
- 场景与地牢内同源：同一套 `t1_*` 墙/门/地砖、同一套火把光、同一个骑士，2× 是“封面特写”的放大，不是另画一套。这个选择是对的。
- 失分在**门内的光层级**：设计说“门缝是光”，但实测门缝和门板装饰线是同一档亮度，门内没有“唯一光源”。见下表（对 1024 无档实拍按区域采样）：

| 区域 | 最高亮度 | ≥200 亮度像素数 | 说明 |
| --- | --- | --- | --- |
| 火把核心 | 255.0 | 640 | 合理，它是光源；墙带靠近火把处也被照亮（x≈112–235），到门右侧已衰减到约 160，**光是有方向的** |
| 门区（含门饰金线） | **199.1** | 0 | 门板、门饰与门缝同一亮度上限 |
| 门缝核心 `#ffbf73` | **199.1** | **0** | 与门饰完全同亮；颜色本身的上限就是 199 |
| 门缝均值 / 门区均值 | 120.4 / 97.2 | — | 门缝只比门区均值高约 23，2px 的竖线很容易被读成门饰 |
| 面板标题金色 | 210.2 | 1246 | 大字，不参与场景竞争 |

  结论不是“墙带抢了光”（墙带的亮区集中在火把附近，方向是对的），而是**门内没有明暗差**：门缝和门板上的金线一样亮，所以它读起来像门饰，而不是从门缝里透出来的光。**这是这一屏最大的艺术扣分点，也是下一处该改的地方。**
- 第二个扣分：字体分裂。标题/菜单用 `Microsoft YaHei`，注释/详情用 `Consolas`（中文回退宋体）（[render.js](../../js/core/render.js#L2860-L2863)、[render.js](../../js/core/render.js#L2905-L2917)）。这可以解释为“人话标题 + 机器读数”的双声部，但它和地牢内的 `monospace` 不是同一套字阶；目前更像“封面用了无衬线、系统用了等宽”，还没有被明确成规则。
- 第三个扣分：静态。火把不闪、门缝不呼吸、没有余烬；首屏是唯一没有运动的界面。静态可以是风格，但这里的光本来就在讲故事，完全不动会让“光”变成“贴图”。
- 第四个扣分：右栏仍是**标准五项列表**——去掉左图，这块栏可以属于任何一款地牢游戏。作者性集中在左栏，右栏只是排得整齐。

## 3. 三问的新答案

### 3.1 3 秒内能不能传达「地牢 / 变强 / 独自一人」？

**画面层：2.75 / 3。** 不再是字面 3/3、画面 0.5/3。

- **地牢：1.0。** 墙砖、双扇门、向下暗井、三级台阶、火把、门缝——不认识这个项目的人也能一眼读出“地牢入口”。这是这次最大的进步。
- **变强：0.75。** `Lv.1 → 第 5 层`、四枚石钉、龙终点、有档时的 `第 3 层 · Lv.7 · 金币 456 · 用时 03:25`——它把“成长”表达成了**进度**（楼层/等级/金币/时间/目标），这是标题屏该做的事。但它还没有表达“力量”：没有装备、属性、技能或“从 Lv.1 到 Lv.N”的力量差。对首屏来说，0.75 够用；对“我独自升级”这个标题来说，还差一个“升级后会怎样”的暗示。
- **独自一人：1.0。** 一个 48×84 的骑士，面对 96×96 的门和整面空墙；没有队友、没有 NPC、没有第二个人。小火把 + 大暗门 + 小人是经典的“一个人上路”构图。这次是画面在作证，不是标题在自说。

**但“3 秒”有一个前提**：门缝要和门饰分开。实测门缝与门板金线同为 199.1 亮度，2px 竖线只比门区均值高约 23，**“光”的读法偏弱**——它更像门饰，而不是从门缝里透出来的光。三件事的识别不受影响（你还是会看到门、骑士、火把），但“这扇门在发光”的叙事强度不够。这是焦点问题，不是识别问题。

### 3.2 与地牢内是否终于属于同一部作品？

**场景这一半：是，而且是最硬的那种“是”**——同一套 `t1_*` 墙/门/地砖、同一套火把光、同一个骑士、同一个 2× 整数放大。它不再是“另一套 UI 语言”，而是“把地牢内的一角放大成封面”。

**右栏这一半：是同一部作品的“系统层”，但还没完全同源。** 断裂点从“两个世界”降级成“同一世界里的几种声音”，逐条列：

1. **字体分裂**：右栏中文标题/菜单用 YaHei，注释/详情用 Consolas（中文回退宋体）（[render.js](../../js/core/render.js#L2860-L2863)）；地牢内 HUD/弹窗用 `monospace`（[hud.js](../../js/systems/hud.js#L246)）。首屏是唯一用无衬线中文大标题的界面。
2. **终点图标分裂**：wide 用龙（[render.js](../../js/core/render.js#L2636)），mid/narrow 用 `boss_demon`（[render.js](../../js/core/render.js#L2653)、[render.js](../../js/core/render.js#L2670)），副标题却写“地牢巨龙”（[render.js](../../js/core/render.js#L2883)）。同一屏在三个档位讲三个终点。
3. **终局文案矛盾**：第 5 层仍写 `→ 第 5 层`，同时写“已抵达”（[render.js](../../js/core/render.js#L2686)、[render.js](../../js/core/render.js#L2959-L2962)）。
4. **数据重复**：行内详情与进度标签重复 `第 N 层 · Lv.X`（[render.js](../../js/core/render.js#L2905-L2917) vs [render.js](../../js/core/render.js#L2933-L2937)）；第 5 层再叠一个“已抵达”。
5. **场景与存档楼层不一致**：场景固定用 F1 的 `t1_*`（[render.js](../../js/core/render.js#L2765-L2779)），有档标签却写“第 3 层”。这可以解释为“入口是标题的隐喻”，但它和“系统状态”是两种叙事：入口是固定的，楼层是变化的。
6. **2× 封面放大 vs 1× 游戏内**：这不是断裂，是封面特写；只要保持整数倍（本轮是 2×/1×），它成立。
7. **英文眉标 vs 全中文 UI**：`DUNGEON / ENTRANCE` 是这块面板里唯一的英文；它像系统标签，也像独立游戏装饰。可保留，但要知道它是“第三声部”。
8. **门缝与门饰同亮**：门区与门缝的最高亮度都是 199.1，门缝没有从门板的金线里分离出来（[render.js](../../js/core/render.js#L2848-L2853)）。这不是世界观断裂，是场景内部的“光”不成立。

**回答“是否同一部作品”**：是。上一轮的断裂是“终端 UI vs 像素地牢”，这一轮已经变成“像素地牢封面 + 它的系统状态栏”。剩下的不是世界观断裂，是**字体、终点图标、状态文案**三处还没统一。

### 3.3 每个功能页是否有自己的构图？

**首屏：有。** 左边一张有叙事的画，右边一块状态栏；这是首屏专属的构图，换成设置/关于都不成立。

**另外四页：没有。** 玩法说明还是左对齐文本墙，设置还是居中列表，确认还是居中文字 + 双按钮，关于还是居中六行（[render.js](../../js/core/render.js#L2967-L3143)）。所以答案是：**1/5 有构图，4/5 仍是“同一套文本换个标题”**。D-93 解决的是第一眼，没有解决菜单系统。

## 4. 这一屏现在最像「有作者性的首屏」还是「一屏排得整齐的首屏」？

**像“有作者性的首屏”，但作者性只到左栏。**

依据（不是感觉，是画面上能指出的东西）：

- **有作者性**：小火把 → 大暗门 → 小骑士，构图有叙事；门缝是一条 2px 的竖光，不是装饰边框；火把光溢出场景框，和页面背景发生关系；场景是真的 2× 像素地牢，不是通用插画；右侧把“楼层/等级/金币/用时/目标”做成状态条，而不是纯菜单。这些选择换一款游戏就不成立。
- **还只是“排得整齐”**：右栏本身是标准五项列表（金框选中、右对齐备注、底部提示），去掉左图可以属于任何地牢游戏；标题是标准的“小眉标 + 大标题 + 副标题”；进度是标准的四钉 + 图标；字体是标准 UI 无衬线。右栏没有“只有这部作品才会这样写”的东西。
- **最像“整齐”的一处**：500/320 档的场景、进度、面板三块左缘不齐（20/24/34、12/16），这是排版问题，不是作者问题；它会让“画 + 栏”降级成“三张卡”。
- **最像“作者”的一处**：门缝、火把、骑士的关系。如果门缝能从门板金线里分离出来（门板压暗、门缝保留、门槛加光池），这一屏会从“有作者性的初版”变成“作者知道自己在讲什么”。

一句话：**左栏是作品，右栏是界面；整屏已经越过“文字摆屏幕”，但还没到“每一处都只有这部作品才有”。**

## 5. 「系统」这个主题有没有开始出现在这一屏？

**开始出现了，但只到“状态读数”，还没到“系统窗口”。**

已经出现的三件事：

1. `DUNGEON / ENTRANCE` 的等宽眉标——像系统页的标题条。
2. 有档时的 `第 3 层 · Lv.7 · 金币 456 · 用时 03:25`——这是典型的状态读数，不是剧情文案。
3. `Lv.1 → 第 5 层` + 四枚石钉 + 龙 + “已抵达”——这是一条任务/进度追踪器。

还没出现的：

- 游戏内“系统”页的窗口语法：页签、分段成长条、蓝色数据字、任务条目、`系统` 这个自称（[modal.js](../../js/systems/modal.js#L1512-L1690)）。
- 所以它是“系统层的读数列”，不是“系统窗口”。这是对的方向：首屏应该世界第一、系统第二，不能反过来。

**但这套“系统”目前不可信**：一个系统不会说“第 5 层 → 第 5 层”，也不会在 wide 用龙、在窄屏用恶魔。系统主题最怕的不是不够蓝、不够发光，而是**读数自相矛盾**。先把状态做对，再谈“系统感”。

如果下一步要更像“系统”，不要加蓝色霓虹；把进度追踪器做成一个自洽的任务状态机（1–4 层石钉、5 层龙、通关写“已抵达第 5 层”），让有档数据只出现一次（要么在行内，要么在底部），这就已经是“系统”了。

## 6. 若只允许再改一处，改哪里

**改 `_drawMenuScene` 的门内光层级：让门缝成为门里唯一的亮金线，而不是和门板装饰线同亮。**

具体到可执行：

- 四种门砖画完之后、门缝与暖晕之前，给门矩形盖一层半透明暗化（约 `rgba(0,0,0,0.35–0.45)`），把门板和三道横向金饰压暗；门缝在暗化之后绘制，保持 2px `#ffbf73` 不动。
- 把门缝的暖晕中心从门中腰下移到门槛（[render.js](../../js/core/render.js#L2848-L2853)），并在最上一级台阶加一小片暖光池；光就从“门板上的金线”变成“从门下来的光”。
- 不动火把：火把核心 255、靠火把的墙带被照亮、到门右侧衰减到约 160——这是对的，光源就该最亮。要压的是**门内**，不是墙。
- 不动门缝颜色/宽度：硬数据是 2px / 84 行 `#ffbf73`，加白芯或改色都会破坏逐像素口径。
- 成功判据：同一张 1024 实拍里，门矩形内只剩门缝两列 ≥190 亮度，门板金饰最高亮度从 199 降到 <150；门缝仍是 2px `#ffbf73`；最上一级台阶出现暖光池；火把仍是全图最亮。
- 成本：**S**（单函数、两层绘制，无新素材、无数值、无存档改动、无缩放变化）。

**为什么不是别的**：

- 压墙带不是首选：实测墙带的亮区集中在火把附近（x≈112–235），到门右侧已衰减到约 160，它已经是“有方向的光”；真正和门缝抢亮度的是门板自己的金线。
- 加动效（火把闪、余烬）会让画面活，但它不解决“门缝和门饰同亮”，是第二优先。
- 统一字体要引入像素字/本地字库，成本 M，且会牵动四个子页，不是“一处”。
- 把右栏做成系统窗口是方向问题，成本 M/L，应该等首屏的光先讲通。
- 第 5 层标签、恶魔/龙图标是**完成度 bug**，应该修，但不算“美学再改一处”；它们不修，8.5 的完成度就站不住。

## 9. 总判

**这一屏现在成立，而且第一次值得被称为“首屏”。** 它从“文字 + 方格纸”变成了“地牢门口 + 状态栏”，三问的画面层从 0.5/3 升到 2.75/3；场景与地牢内同源，系统主题以“楼层/等级/金币/用时/进度”的读数形式开始出现。完成度 8.5、艺术性 7.5（主档）。

**但它还没有“讲完”**：门缝是故事，但它和门板金线同亮，还没有成为门里唯一的亮线；右栏是整齐的菜单，不是有作者性的系统层；四个子页还在旧模板里。下一处只改一个地方的话，先把门内的光做出层级——门板压暗、门缝保留、门槛加光池。然后修掉第 5 层的“第 5 层 → 第 5 层”和窄屏的恶魔图标：系统可以不够炫，但不能自相矛盾。
