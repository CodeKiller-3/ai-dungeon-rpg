## 1. N1：结果卡落在「信息元素并集之外」

### 1.1 根因

旧 `battleSafeBand` 纵置只算了两件事：`max(0.30H, 250) + 8` 到 `playerGround − 66`。上界只避开了敌人精灵，管线（26px）、战报（1–2 行）、属性行（12px）都在带内；结果卡按 104px 高居中，于是 390 盖管线/战报、320 盖战报下半/属性行/玩家头顶。

### 1.2 改法

1. `verticalFreeIntervals(W,H,box)`：把本帧实际绘制的 `hudBand / monsterPlate / monster / pipeline / log / stat / playerPlate / player / commandBar` 全部作为障碍（按结果卡 x 范围判断横向是否相交），求它们在纵轴上的补集，得到空白区间表。
2. `battleSafeBand(W,H,layout,box)`：纵置且拿到本帧绘制框时返回 `{top,bottom,free}`；`top/bottom` 取最大区间，Juice 按「离屏幕中线最近且放得下整卡」选段。没有绘制框的纯函数调用仍走旧口径，`verify_d78` / `verify_d101` 的入口不变。
3. 中段信息带由「带内垂直居中」改为**顶对齐**。居中会在带底留下 34–92px 的碎片空间，任何一段都放不下 104px 卡；顶对齐后「战报下沿 → 玩家精灵顶」连成一条连续空白。
4. 每帧重置 `playerPlate / monsterPlate / stat` 登记，消散帧不会把上一帧残影当障碍。
5. Juice 布局：只在**最新一张卡放得下**的空白段里放卡；放不下就换下一段。没有任何空白段时不会去压信息（本卡的真实场景里没有出现这种情况）。

## 2. N2：chip 必须是真实数字

### 2.1 改法

- 删除 `+n` 分支。`cardChips` 每项同时给出 `full` / `short` 两种写法，**两者都含数字**：
  - 防御：`防御1` / `防1`（1 = 本回合剩余回合数，与 `defendRound === roundNo` 同源）
  - 护盾：`护盾8` / `盾8`
  - 持续状态：`中毒3` / `毒3`、`流血2` / `血2`
  - 敌人：`狂暴<atk>` / `暴<atk>`、`龙威3` / `威3`
- 宽度自适应：先保「能看见几枚」，再选写法。候选顺序为
  宽档（带 8px 色块，20px 内边距）→ 宽档去色块 → 窄档（12px 内边距）→ 窄档紧凑间距（2px）。
  每档 chip 宽度由 `measureText` 实测文本宽度反推，所以文本必然落在自己的 chip 内。
- 隐藏数量仍是 `+N`（N 一定有数字），不会出现无数字占位。

### 2.2 四档 × 1–4 枚实测（实际 `fillText`）

| 档位 | 1 枚 | 2 枚 | 3 枚 | 4 枚 |
|---|---|---|---|---|

| 390×844 | `护盾8` | `防御1` `护盾8` | `防1` `盾8` `毒3` | `防1` `盾8` `+2` |

- 2 枚时玩家卡 L3 可用宽度 94px：`防御1` + `护盾8` 各 40px + 4px 间距 = 84px，宽档写法完整保留。

### 2.3 断言与负例（`verify_d102`）

- `d109.n2.<档>#<n>`：chip 数 >0；每枚文本含 `[0-9]`；实际 `fillText` 与 chip 记录一一对应；`measureText` 文本宽 ≤ chip 宽 − 4；chip 右缘 ≤ 卡右缘。
- `d109.n2.plusNneg`：`+n` 与旧标签 `防御中` / `狂暴` / `护盾` 都不含数字，必须被判负。

## 3. N3：横纵受击反馈统一

### 3.1 根因与选择

- 横置怪物只切 `hurt` 帧，纵置走 `tintSprite` 白闪；同一命中在宽屏与竖屏的受击语义不同。
- 纵置的白闪与斩击弧都是白色，弧压在刷白的主体上等于消失。**弧本来就在闪白之上绘制**（`Fx.drawSlashes` 在精灵之后），所以问题不是层级，而是同色；选择「描边加深」而不是提层。
- 横置补白闪；斩击弧改为深色轮廓（`rgba(16,12,26,0.92)`，lineWidth 2），**直接复用刚画完的月牙路径**，调用次数 0 新增。

### 3.2 三帧实测（受击主体为实心替身，取框内亮度均值）

| 布局 | 命中前 | 命中帧 | +60ms | 命中跃升 | +60 跃升 | 弧像素差 | 暗轮廓像素（新/旧） |
|---|---:|---:|---:|---:|---:|---:|---:|
| 横置 1024×640 | 75 | 192 | 152 | **117** | **77** | **146** | 51 / 0 |
| 纵置 390×844 | 75 | 191 | 142 | **116** | **67** | **40** | 5 / 0 |

- 两套亮度跃升差 1，证明同一条 `Feedback` 账本、同一颜色与 alpha。
- 纵置受击主体只有 32×46，弧与主体的重叠面积小；因此纵置阈值按像素差 12 判（实测 40），横置按 20（实测 146）。两者都远高于旧行为的 0。
- 实拍：`d109-fx-horizontal-1024x640.png`、`d109-fx-vertical-390x844.png`。

### 3.3 断言与负例（`verify_d102`）

- `d109.n3.hTint` / `d109.n3.vTint`：命中跃升 ≥20。
- `d109.n3.sameDelta`：两套跃升差 ≤8。
- `d109.n3.hLate` / `d109.n3.vLate`：+60ms 跃升 ≥8。
- `d109.n3.hSlash` / `d109.n3.vSlash`：同一帧只切换描边，主体框内像素差 ≥20 / ≥12，且新描边有暗像素。
- `d109.n3.tintNeg`：旧横置行为（不刷白）跃升为 0，必须 <20。
- `d109.n3.slashNeg`：旧纯白弧（`_setSlashOutline(false)`）暗轮廓 0 像素，必须判负。
