# 横置战斗：可行性、美学重设计与分阶段实施卡

> 性质：**只写文档，不动代码与素材**。本文件回答「横置是否可行、是换构图还是换舞台、要不要顺带做洛克王国那套系统」，并给出可直接下发的分阶段卡。
>
> 读者：主程 / 美术 / 验收。所有结论都带文件、页号、成本与回退方式。

## 0 结论（先看这一页）

| 问题 | 结论 |
|---|---|
| 横置是否可行 | **有条件可行**。技术上没有阻塞；代价集中在 5 张背景重排与 5 张验证页重钉，不在精灵。 |
| 横置是换构图还是换舞台 | **换一套舞台**。只挪坐标不成立：地平线从两条变一条、背景中心从「敌方站台」变「决斗空场」、特效轴从纵变横、文字带全部换位。 |
| 只改画法做不做 | **做，但要先试装**。建议 B 方案，按 P1→P3 先做可逆骨架，过「三秒读成对峙」的截图门再继续。 |
| 洛克王国那套系统做不做 | **不做，延后，单独立项**。技能/属性/宠物是玩法新增，会改伤害公式与 200 局基线，不能混进视觉卡。 |
| 现有五套背景还能不能用 | **能用其色与地标，不能直接当背景用**。5 个 painter 都要重新构图；地平线数值全部作废，改挂到后墙。 |
| 是否需要侧面/背面素材 | **本轮不需要**。采用「三面墙舞台」：双方保持正面朝向，用左右站位、共享地面、横向攻击向量建立对峙。真侧向需要约 128 张新帧，另立卡。 |
| 最大风险 | **正面朝向的精灵在横置后可能读成「两张立绘并排」，不是「在对峙」**。这是 P3 的 Go/No-Go 门。 |

一句话：**能换舞台，但先把舞台搭起来看一眼；看不成立刻退回纵置改良，不要先画 5 张背景。**

## 1 事实基线（先对齐口径）

### 1.1 关于「1024×640」

- 代码里 `render.js` 的 `BASE_W=960, BASE_H=540` 是**缩放设计基准**，不是固定逻辑分辨率。
- 实际逻辑视口 = 窗口 CSS 尺寸 ÷ `scale`。标准验收窗口 1280×800 下 `scale=1.25`，逻辑视口正好是 **1024×640**。
- 因此本规范用 1024×640 写实数，同时给比例式；960×540 下同比例成立。
- `TILE=24` 不变；零构建、`file://` 双击可玩、零运行时网络请求不变。

## 2 核心判断：横置是「换一套舞台」

| 维度 | 纵置（现在） | 横置（提案） | 是否只是挪坐标 |
|---|---|---|---|
| 地平线 | 两条：敌方站台 180，我方 540 | **一条：490**，双方同脚底 | 否，空间关系重写 |
| 背景中心 | 拱门/王座/棺台正对敌人，敌人站在中心 | 中心是**决斗空场**，地标退到后墙或两侧 | 否，5 个 painter 重排 |
| 视线 | 从下往上看敌人 | 平视，两个站位左右对峙 | 否 |
| 攻击轴 | 纵向（下→上 / 上→下） | **横向**（左→右 / 右→左） | 否，前摇/击退/斩击全改轴 |
| 文字带 | 中段 236–410 一条安全带 | 上（名字/血条/回合）+ 中（上次行动）+ 下（指令） | 否，信息架构重排 |
| 结果卡 | 夹在两条血条之间 | 顶部空场（96–270） | 否 |
| 遮挡关系 | 敌方血条在敌人上方 | 双方血条在各自头顶，中间空出决斗区 | 否 |

**结论**：只改 `ex/ey` 与 `px/py` 一定会失败——背景仍然把敌人供在中心，玩家仍然在屏幕底部，读起来只是「左右各站了一个人，中间一大片空」。必须同时改背景构图、地面线、信息带、特效轴，这四项加起来就是「舞台」。

横置真正的美学收益不是「像洛克王国」，而是三件事：

1. **一条地平线让空间成立**：两个人站在同一块地面上，才有「同一个房间里的对峙」，而不是「上屏敌人 / 下屏玩家」两张立绘。
2. **中间空场给体量与特效**：龙 144、Boss 108、玩家 90 的体型差在横向距离里读得出来；斩击、冲击、飘字有地方走。
3. **顶部条带把「测量」从动作里分离**：名字/血条/回合/系统读数在上，动作在中，指令在下——正好接上 D-90 的「系统在看着你」的语言。

这也是为什么「只改画法」值得试：它不只是换构图，而是把战斗从「两张立绘 + 一条文字带」变成「一个有地面、有距离、有测量层的舞台」。

## 3 必须分开评估的两件事

### 3.1 只改画法（B）

范围：构图、站位、地平线、血条/名字、指令区、战报、飘字、特效方向、结果卡安全带、五层背景重排。

- 不改：伤害公式、技能、怪物数值、回合顺序、随机数、时钟、键位、存档。
- 判定：**有条件可行，推荐先试装**。
- 代价：0 张新素材；5 个背景 painter 重写；5 张验证页重钉；约 430–550 行表现层代码。

### 3.2 真的加系统（洛克王国那套底层）

洛克王国战斗的底层不是「横着站」，而是四件事：技能栏（4 技能 + PP）、属性克制、宠物/召唤、捕捉与养成。

本作现状：

| 项 | 现状 | 差距 |
|---|---|---|
| 技能 | 已有火球/冲刺/护盾，键 4/5/6，耗 MP | 有技能，但没有技能栏 UI |
| 属性 | 无 | 缺一整套克制表 |
| 宠物/召唤 | 无 | 缺战斗单位、AI、养成 |
| 捕捉 | 无 | 与「独自升级」主题冲突 |
| 指令 | 键盘 1–7 | 横置后可视化即可，不必改输入 |

**判定：不做，延后，单独立项。**

理由不是「做不出来」，而是它会同时改三件事：

1. **改伤害公式**：属性克制必然乘系数，D-66~D-84 的回合数、Boss 阈值、四策略胜率全部失效，需要重跑并重定档。
2. **改战斗单位**：宠物/召唤会把 1v1 变成 2v2，回合顺序、目标选择、UI、AI 全变。
3. **改输入/面板**：4 技能格 + 宠物位要么新增按键，要么新增点击区；`verify_d20` 的键位审计与现有关卡提示都要改。

这三件都不属于「美学重设计」，混进横置卡会让一张卡同时承担视觉与平衡两条验收线，无法独立回退。

**若以后要做**：单开一张「战斗系统 v2」里程碑，先定属性表与克制系数，再谈 UI；横置舞台可以作为它的承载，但不是它的前提。

**本卡可以顺手做的**：把现有 3 技能 + 3 基础指令 + 用药做成 7 格指令条（§6.5），这只是把已有能力可视化，不新增任何系统。

> 下表把 C（横置 + 侧/背面素材）作为 B 的加强子项一并列出，方便判断「是否值得等素材」；主方案仍是 A / B / D 三个。

## 5 B 方案的成立条件（五条，缺一不可）

1. **接受「三面墙舞台」**：双方保持正面朝向，不旋转、不镜像翻转精灵；靠左右站位、共享地面、横向攻击向量建立对峙。否则进入 C，需要 128 帧新素材。
2. **接受五层背景重排**：地标、色温、地面材质保留；构图、地平线、中心区域重写。不是把纵置背景平移。
3. **接受 5 张验证页按新几何重钉实测值**：只改实测值与条带范围，不改判据方向（例如「背景最亮不在精灵身上」仍然是判据，只是坐标变了）。
4. **不改玩法**：伤害公式、技能、怪物数值、回合顺序、随机数、时钟、键位、存档全部不动。
5. **竖屏自动回退纵置**：`W<720` 或 `H>W×1.05` 时走旧布局；480×800 的验证与手机可玩性不受影响。

**安全区规则**：
- 任何常驻文字不得进入 `291–706 × 342–490` 的决斗矩形（除了「上次行动」这一行，它只在中间空场、y=474）。
- 任何特效不得越过 y=318（血条下沿）或 y=544（指令条上沿）；用 `ctx.clip` 裁到 `[0, 318, W, 226]`。
- 结果卡只允许在 96–270；压到血条或精灵即判负。

### 6.2 站位、尺寸与朝向

- **不旋转、不镜像**。理由：D-88 的龙眼与身份符号是按当前像素方向验收的，镜像会让眼位与角饰换边，直接破坏剪影签名；正面朝向的镜像也不产生侧向感，只有负收益。
- 采用「三面墙」：观众是第四面墙，双方都面向观众；对峙由**站位 + 共享地面 + 攻击向量**建立，不由脸的朝向建立。
- 双方脚底同一 y=490，接触阴影同一 y=490；这是横置最重要的「同一房间」证据。
- 玩家与杂兵同高 90；Boss 108；龙 144。龙仍然是全场最高最大（d86/d89 的层级判据保留）。
- 若未来有侧面素材，只改 `_facing` 与帧组，不改站位与几何；作为 C 卡的接口预留，不在本卡实现。

### 6.3 五层背景在横置下怎么重排

统一骨架：
- 旧 horizon（176/168/184/164/192）是「敌方站台前沿」，服务于纵置的中心敌人；横置后不再使用，改为后墙交界 `backWallY`。
- 后墙 0–`backWallY`；墙地交界 `backWallY`；地面 `backWallY`–640；决斗地面线固定 490。
- 每层仍有独立的 **backWallY**（替代旧 horizon），这样五层纵深不同，但脚底始终 490。

| 层 | backWallY | 地标（后墙/两侧） | 光源（x） | 地面材质 |
|---|---|---|---|---|
| F1 石厅 | 420 | 左右各一座侧拱（0.16W / 0.84W），中心封闭石门（CX，宽 120，顶 300） | 壁挂火把 0.10W / 0.90W，y=430 | 湿石板，冷灰 |
| F2 营地 | 410 | 左侧帐篷（0.12W）+ 右侧木栅栏（0.88W），中心踩实泥地 | 篝火 0.08W，y=450 | 泥地，暖褐 |
| F3 裂谷 | 400 | 中央横向熔岩裂口（0.30W–0.70W，y=440–456），左右岩台 | 熔岩自发光 + 两侧余烬 0.12W / 0.88W | 冷却黑曜石 |
| F4 墓穴 | 430 | 左右两排立柱（0.12/0.32W 与 0.68/0.88W），后墙中心棺台（CX，顶 400） | 冷烛 0.10W / 0.90W，y=470 | 霜石阶，冷青 |
| F5 王座 | 415 | 后墙中心王座（CX，300–430）+ 台阶（CX±180，430–470） | 火盆 0.08W / 0.92W，最亮 | 黑曜石金脉 |

硬规则：
- 地标不得进入两个精灵包围盒（1024 下 201–291 与 706–850）。
- 最亮像素必须在 **x≤0.12W 或 x≥0.88W、y≥380**；两个精灵包围盒内最亮 ≤115，比光源低 ≥60。这保留了 `verify_d88` 的判据方向，只改坐标带。
- 五层像素签名仍两两不同；仍是一次离屏构建 + 每帧 1 次 blit，不新增每帧 drawImage。

**为什么不直接平移旧背景**：旧五景的拱门、王座、棺台、帐篷都以 CX 为轴，敌人站在中心；横置后中心是决斗空场，原地标会正好压在两个精灵之间，既挡特效又让空间读成「一张背景前面站了两个人」。所以是重排，不是平移。

## 10 风险清单（按杀伤力排序）

1. **正面朝向读成「两张立绘并排」**（最可能砸掉的一条）。
   - 现象：左右各一个正面精灵，中间空，像选人界面，不像战斗。
   - 缓解：共享地平线、双向接触阴影、向内前摇、横向斩击、中央地面刻线/尘土、背景纵深。
   - 止损：P3 截图门不过就退回 A，不再投入 P4–P6。
2. **五层背景失去身份**。D-88 刚把「任意两层不能只换颜色」做出来，重排可能退回「同骨架换色」。
   - 缓解：每层保留地标 + 色温 + 地面材质 + backWallY 四个差异；一次一层验收。
3. **重钉 5 页掩盖真回归**。改实测值最容易把「压到血条」改成「允许压」。
   - 缓解：只改数字，不改判据方向；每页附截图；d77/d78 指纹作为独立闸门。
4. **结果卡没有安全带**。横置后两条血条都在顶部，卡片可用的只有 96–270；三张卡可能放不下。
   - 缓解：按 d78 既有规则「装不下由新到旧取舍」，不缩字号、不压精灵；放不下就只显示 1–2 张。
5. **整数倍口径冲突**。骑士/杂兵当前 90px 已是非整数倍；若字面执行，横置卡会先被判负。
   - 缓解：P0 拍板；要么沿用「图标/地块」口径，要么另开整数化卡，不混入本卡。
6. **竖屏/小窗退化**。480×800 强行横置会挤压。
   - 缓解：`auto` 回退纵置；d78 的 480×800 用例继续走旧带。
7. **指令条遮挡 Notice**。底部 96px 被指令条占用，旧 Notice 的 H−24 会盖住格子。
   - 缓解：横置战斗里 Notice 底边改 `H−104`；截图验收。
8. **纯表现层仍改到随机数**。例如为了「站位微差」用 `Math.random`。
   - 缓解：全线禁止；方向/偏移全部由 `who` 与固定常量推导；每阶段跑 200 局指纹。

## 12 最终建议

1. **先做 P1–P3，不做 P4–P6。** 横置的成败在「两个人是否站在同一个房间里对峙」，不在指令条长什么样。P3 截图门不过，后面的投入全是沉没成本。
2. **P3 过了再一次性做 P4–P6。** 背景、实体、信息带一起看，才能判断「舞台」是否成立；分开看单张截图容易自欺。
3. **洛克王国那套系统不做。** 现有 3 技能已经够用；属性/宠物会把这张视觉卡变成平衡卡，且与「独自升级」的 1v1 主题冲突。若要做，单开里程碑，先定属性表。
4. **保留纵置为正式回退路径。** 不是临时开关，而是 `auto` 的竖屏分支与 `_battleLayout=vertical` 的永久能力；横置失败不影响可玩性。
5. **一句话回答「横置值不值」**：如果 P3 的截图能让人一眼看出「左边的人要往右打，右边的东西正压过来」，就值；如果只是「左右各站一个正面精灵」，就不值，回 A。
