# 部分 A：可以先做（日志后缀 + 三条换档提示）

## A.1 走哪条通道：只走 `state.log`，**不发 `ui:notice`**

`ui:notice` 不是屏幕中央弹窗，是**底部提示条**（[notice.js](file:///d:/桌面/工作/人工智能大作业/js/systems/notice.js#L1-L13)）：

| 参数 | 值 | 与战斗的关系 |
|---|---|---|
| 同时显示 | `MAX=3` 条，超出踢最旧 | 与“升级 / 精英之证 / 任务完成”抢槽位 |
| 存活 | `LIFE=2400ms`，末尾 400ms 淡出 | 读完就没了，不能回看 |
| 位置 | 画布底部 `H−24`；战斗场景上移 26px 让开指令图例（`notice.js:109-110`） | **不覆盖画面中心玩家区、不覆盖顶部 HUD**，也不挡精灵动画 |
| 去重 | 同文本 1500ms 内忽略 | 补发会静默失败 |

结论：**换档提示不进 `ui:notice`，只进战斗日志**。理由不是“怕挡动画”（它本来就不挡），而是三件事：

1. 3 个槽位会被 2.4 秒后自动清空，玩家一低头就错过；日志可以回看。
2. 第 9 回合同时发 2 条会把“精英之证/升级”这类更急的提示挤掉。
3. 龙威的“当前层数”是**持续状态**，不是瞬时反馈，属于战报，不属于提示条。

因此本卡对 `ui:notice` 的改动量是 **0**；验收里要反向断言“这些字符串没有出现在 `Notice._historyTexts()`”。若将来想要一次屏幕闪烁，走 `Juice/Fx`，另开卡，不在本卡。

## A.2 可视窗口：缓冲 6 行，屏幕只画 3 行（既有行为，不改）

- `logPush` 上限 6 行（[battle.js:201-204](file:///d:/桌面/工作/人工智能大作业/js/systems/battle.js#L201-L204)）。
- 战报**屏幕只渲染最近 3 行**（[render.js:1416-1425](file:///d:/桌面/工作/人工智能大作业/js/core/render.js#L1416-L1425)）。
- 所以“6 行上限之外”不存在额外处理：三条提示就是普通战报行，同样被自然挤出，**禁止**清空 `state.log`、**禁止**加第 7 行缓冲、**禁止**改 3→4 行显示。

由此定下第 9 回合**只发一条**（r1 的两条方案作废）：回合起拍 → 提示 → 玩家行动（1 行）→ 龙出手（1 行），正好是可视 3 行，提示不会被自己的攻击行顶掉。若该回合玩家侧额外产生 2 行（状态伤害），提示可能被挤出可视区——此时**伤害行后缀仍报当前层数**，信息不丢。

   - `dreadSuffix()`：`bonus>0` 时返回 `'（龙威 +' + bonus + '）'`，否则返回 `''`。

3. **三条换档提示**（在 `playerAction` 里、`state.roundNo = (state.turn | 0) + 1;` 之后，玩家行动结算之前）：

   - `state.dreadTier` 记录已播报到第几档，`Battle.start` 里置 0；**只在上升时播报**。
   - 读档/复活/防御/喝药都不重播（`dreadTier` 随 `state` 存活）。
   - 三条都走 `logPush`，都占 1 行，不清空日志。
