# 零引用素材清点（16 张）

> 只出结论，**没有删任何文件、没有改 `NAMES`**。移除需要单独裁定（见 §5）。
> 口径：`js/` 内除 `sprites.js` 的 `NAMES` 外，任何文件都不再出现该素材名（含拼接、映射、回退规则）。

## 0 结论

1. 零引用素材 **正好 16 张**：4 张按钮态、4 种药瓶、8 把武器。与任务给的数量一致，无第 17 张。
2. **一张都不建议现在删**：项目审计要求 `NAMES` 与磁盘张数相等（当前 355/339，接轨后 355/355）；单删 `NAMES` 会让审计从"相等"变成"注册少 16"，比留着更糟。
3. 真正该动的是 8 把武器：它们**没有任何物品 id 能映射到**，也不参与稀有度回退，属于纯冗余；建议**下一轮连同文件一起移出**（`355 → 347`），而不是只删注册。
4. 4 张按钮 + 4 种药瓶有明确复用场景（图形按钮、新药水类型），建议**保留并标注备用**。

## 1 判定方法（为什么不是 134 张）

朴素地"在 js 里搜文件名"会误报 118 张：地块/装饰是拼出来的（`t2_floor_3`、`t5_dc_web`），不是字面量。实际做法：

1. 取 `assets/sprites/` 全部文件名，剥离 `_anim_fN` 得到"组"；
2. 在 `js/**/*.js`（排除 `sprites.js`）里搜组名；
3. 对地块/装饰类单独核对拼接规则（`theme` 前缀 + `floor_`/`dc_` 后缀），确认是动态引用，剔除；
4. 对武器/药瓶/按钮逐个反查 `items.js` 的 `ITEM_ICONS` 与 `modal.js` 的 `itemIcon()` 回退规则。

剩下的就是本文 16 张。

## 4 为什么不能"只从 NAMES 删"

项目把"素材完整性"定义成三条硬等式（`LICENSE.md` §统计口径、`verify_d21/d30`）：

```
LICENSE 声明数 == 磁盘 PNG 数 == NAMES 条数
```

只删 `NAMES` 会让第三条先断；只移文件不删 `NAMES` 会让第二条先断。**任何移除都必须三处同批改**：文件 → `NAMES` → `LICENSE` 计数。这也是本轮只出文档、不动手的原因。
