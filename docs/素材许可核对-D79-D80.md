### 4.3 MIT 署名补齐草案

**结论：这不是"改一句话"，是补两份东西——版权行 + 许可全文。**

**(1) 版权行原文**

必须**逐字**来自上游 LICENSE，不能凭印象写。我两次尝试抓取上游原文（`raw.githubusercontent.com/fernandovmp/kni-dungeon` 的 `master` / `main`）均返回空，属网络阻断，因此这里只给可直接落地的格式，**不编写者名**：

```
Copyright (c) <上游 LICENSE 中的年份与署名，逐字复制>
```

- 上游 LICENSE 若只有模板、没有具体版权行（部分 MIT 仓库如此），则写 `Copyright (c) <仓库作者/组织名>`，并在同一节注明"版权行取自上游 README/仓库页，获取日期 YYYY-MM-DD"。
- **不要**把这条替换成本项目作者（黄文博）——那会变成冒名。

**(2) 许可全文放哪**

| 落点 | 内容 | 为什么 |
|---|---|---|
| **仓库根 `THIRD-PARTY-NOTICES.md` 新增第 4 节「kni-dungeon（像素素材）— MIT」** | 版权行 + MIT 全文 + 上游 URL + 本项目改动说明 | 与既有 astar / howler / rot.js 三节同构；这是"许可文本随分发物走"的主副本 |
| **`assets/sprites/THIRD-PARTY-NOTICES.txt`（同文副本）** | 同上，纯文本 | 只分发 `assets/sprites/` 时不会丢；MIT 要求"随所有副本或实质部分"保留 |
| `assets/sprites/LICENSE.md:41` | 改成指向上面主副本的相对链接 | 消除"只有外链"的问题 |

**(3) `LICENSE.md` 怎么改才不自相矛盾**

现状两句互相打脸：

- `:40`「本项目仍在 README 与 `THIRD-PARTY-NOTICES.md` 中主动署名」——该文件里没有 kni-dungeon；
- `:41`「再分发时须保留其版权声明与许可文本，见 <GitHub 链接>」——仓库内没有这份文本。

建议改成（两行一起换）：

```md
- **CC0 部分**：可自由使用、修改、再分发，无需署名（本项目仍在 README 与 `THIRD-PARTY-NOTICES.md` 中主动标注来源）。
- **MIT 部分**（kni-dungeon）：本目录已随附版权行与 MIT 全文，见仓库根 `THIRD-PARTY-NOTICES.md` 第 4 节，
  以及同目录 `THIRD-PARTY-NOTICES.txt`；上游原始许可：<https://github.com/fernandovmp/kni-dungeon/blob/master/LICENSE>。
```

**(4) 一条常被误解的事**

MIT 的署名/许可保留义务**与是否盈利、是否商用、是否只交作业无关**：只要分发（含把仓库/素材包给别人、传到公开平台），就要保留。反过来，CC0 部分确实可以不署名——所以本次要补的只有 MIT 这一节，CC0 那半句只是措辞修正。

## 5 CC0 / CC-BY / MIT 逐项判定

| 许可 | 现有素材 | 要求 | 当前是否合规 |
|---|---|---|---|
| **CC0 1.0**（0x72 / 本项目释出） | 地块、装饰、7 张道具、D-79 新增、D-80 角色/史莱姆 | 无署名义务；可自由改、可再分发 | ✅ 合规（项目还主动署名，超出要求） |
| **CC-BY 4.0** | **0 张**（依据：`LICENSE.md` 无 CC-BY 条目 + 磁盘无 DawnLike 等 CC-BY 文件名；未逐个向上游反查） | 必须署名 + 许可链接 + 是否修改 | ✅ 不适用；**若以后引入，必须补四要素**（作者 / 作品名 / 来源链接 / 许可链接 + "已修改"） |
| **MIT**（kni-dungeon） | 120 张上游素材（怪物帧、墙体边角、楼梯、`player.png` 等） | **保留版权声明与许可全文** | ❌ **不合规**：仓库内无版权行、无 MIT 全文；`LICENSE.md:41` 只有超链接 |
| 自绘（若 §4.2 确认为纯自绘） | 疑似 49 张图标 | 无（可自选 CC0 释出） | ⚠️ 待确认后登记 |

补充两点，避免误判：
- **CC0 不需要"署名合规"，只需要"不虚假声明来源"。** 所以 §2 那些"归 0x72"的错行，性质是**台账失真**，不是侵权。
- **MIT 的问题也不是"没署名"，是"没保留许可文本"。** 这是可被上游追责的一条，优先级高于所有 CC0 措辞问题。
