# 《AI勇者闯地牢》答辩讲稿

> 广西科技大学 · 《人工智能基础》课程大作业 · 黄文博（软件245班）
> 本项目仓库：https://github.com/CodeKiller-3/ai-dungeon-rpg （在线试玩：https://CodeKiller-3.github.io/ai-dungeon-rpg/）

## 一、开场：为什么做这个（30 秒）

各位老师好。我的大作业题目是《AI勇者闯地牢》，一个像素风 RPG 小游戏。选它的原因有两个：第一，我在这门课上最想验证一件事——**AI 时代，一个人能不能独立做出一个完整的游戏**；第二，我特意选了班级里没人做的 RPG 类型，并且用"组件化拼装"的方式，站在开源巨人的肩膀上完成，而不是从零手写一切。

## 二、现场演示要点（1 分半）

请允许我直接双击打开 `index.html` 演示（或打开在线链接）：

1. **随机迷宫**：每一层都是程序实时生成的迷宫，出生点、楼梯、怪物位置每次都不同；
2. **移动与战斗**：WASD 移动，踩到红点怪物进入回合制战斗，按 1 攻击、2 防御、3 逃跑；
3. **背包与商店**：B 打开背包使用血瓶、装备武器；S 打开商店买卖，楼层越深货架越强；
4. **任务与通关**：M 查看任务，击败第 3 层巨龙后通关；
5. **AI 亮点一**：看到灰色方块了吗？那是巡逻怪——当我靠近时它会变红、追着我跑，这就是 **A\* 寻路 + 行为状态机**；
6. **AI 亮点二**：按 T 打开地牢守门人，可以直接和它对话。现在演示的是离线规则版；配置 DeepSeek Key 后，它就是真正的大模型 NPC，可以自由对话。

## 三、三大 AI 亮点技术讲解（2 分钟）

**1. A\* 寻路**
- 我直接引入了 GitHub 上 1391 星的开源库 `javascript-astar`（MIT 协议），文件在 `js/vendor/astar.js`，原样引入没有改动——这就是"站在巨人肩膀上"。
- 原理：怪物感知到玩家后，把迷宫抽象成 0/1 网格，用 A\* 计算最短路径，核心是 `f = g + h`（g 是已走代价，h 是到目标的预估代价）；为了让性能可控，我让怪物**每 4 帧重规划一次路径**，而不是每帧都算。

**2. AI 行为状态机**
- 我把怪物的行为建模成一个状态机：`IDLE（待机）→ CHASE（追击）→ ATTACK（贴脸开战）`。
- 感知半径 6 格内，怪物从 IDLE 切到 CHASE；贴脸切到 ATTACK 触发战斗。可视化上，灰块=待机、红块+感叹号=追击，状态转移肉眼可见——这比写死"随机移动"高级得多，也是老师说的"AI 感"的来源。

**3. 大模型 NPC 对话**
- 按 T 打开对话面板，输入文字，系统把对话历史发给 DeepSeek 大模型，它用"地牢守门人"的人设自由回复。
- 关键设计：**离线兜底**。没配 Key 或断网时，自动降级到本地规则问答，游戏在任何环境都能演示——这样答辩现场即使网络出问题也不会翻车。

## 四、组件化拼装方法论（1 分钟）

我的核心思路不是"写代码"，而是**"拼装"**：

1. **选型先行**：先分析班级 34 个选题，确认 RPG 是"可拼组件最多"的类型（地图、战斗、背包、商店、任务、对话、AI 全都能拆成独立模块）；
2. **模块契约先行**：在 PLAN.md 里先定好 `window.Game` 命名空间、16 个模块函数签名、13 个事件频道——模块之间不直接互相调用，只通过事件总线通信，所以"拼"的时候不会打架；
3. **开源优先**：能引现成的就引（A\* 引开源库、战斗背包参考 freeCodeCamp 教程），自己只写游戏特有逻辑；
4. **AI 协作开发**：这个项目我用了两个 AI 工具协作——**Trae CN** 做执行端（直接生成、修改、提交代码），**豆包**做对话端（定方案、审代码、排错）。这是我这门课最大的收获：AI 不是替你写代码，而是和你组成一个团队。

## 五、遇到的坑与解决（30 秒）

1. **GitHub 网络问题**：我的网络环境直连 GitHub 不稳定，最终用 Dev-sidecar 代理通道完成推送，git 提交走本地、推送走代理；
2. **验证问题**：每次完成一个模块，我都写一个 headless 验证页（项目 `preflight/` 目录），让浏览器无头模式自动跑逻辑并输出 PASS/FAIL——开发过程中这样抓到过 canvas 缺失、脚本路径错误等真实 bug。

## 六、总结与展望（30 秒）

这门课教会我的不是某个算法，而是**"AI 时代个体开发者的工作方式"**：把问题拆成模块、站在开源肩膀上、用 AI 当协作者、用工程化手段验证。这个游戏只是起点——下一步我想把 NPC 的对话接上长期记忆，让每个玩家拥有专属的 AI 伙伴。谢谢各位老师，请指正。
