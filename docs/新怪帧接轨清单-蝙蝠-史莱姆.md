# 新怪帧接轨清单：蝙蝠 / 史莱姆

> 本轮只写素材与文档，未改 `js/`、未改 `preflight/`。执行端照本清单接线即可，不需要再判断尺寸或帧序。

## 0 一句话

新增 **16 张 24×24 原生帧**，把 `bat`（暗影蝙蝠）与 `slime`（史莱姆）从"借帧"里摘出来：蝙蝠不再借小恶魔，史莱姆不再借蛞蝓。文件已在 `assets/sprites/`，只剩 3 处接线。

## 1 帧清单与命名

| 组 | 文件 | 张数 | 原生 |
|---|---|---|---|
| 蝙蝠待机 | `bat_idle_anim_f0.png` … `bat_idle_anim_f3.png` | 4 | 24×24 |
| 蝙蝠移动 | `bat_run_anim_f0.png` … `bat_run_anim_f3.png` | 4 | 24×24 |
| 史莱姆待机 | `slime_idle_anim_f0.png` … `slime_idle_anim_f3.png` | 4 | 24×24 |
| 史莱姆移动 | `slime_run_anim_f0.png` … `slime_run_anim_f3.png` | 4 | 24×24 |

命名完全沿用现有约定：`{物种}_{idle|run}_anim_f{0..3}`。`Sprites.getFrame(group, i)` 会拼成 `group + '_anim_f' + i`，所以 `MONSTER_ANIM` 里只能写**不含 `_anim_f` 的组前缀**。

### 为什么是 4+4

- 同体型（24×24）的 `imp / goblin / skelet` 都是 **4 帧 idle + 4 帧 run**；蝙蝠原本借的就是 imp 的 4+4，保持同规格最稳。
- 史莱姆原来借的 `tiny_slug` 只有 4 帧单序列。本轮给到 4+4，是为了让"移动"与"待机"在观感上分开（见 §4）；如果执行端想保守，也可以让 `run` 直接指向 `slime_idle`，8 张里只用 4 张，不会报错。

## 2 接线点（3 处，均在 `js/core/sprites.js` / `js/core/render.js`）

### 2.1 `NAMES`：加 16 行

放在 `imp_*` 那组附近，逐条加入：

```js
'bat_idle_anim_f0', 'bat_idle_anim_f1', 'bat_idle_anim_f2', 'bat_idle_anim_f3',
'bat_run_anim_f0', 'bat_run_anim_f1', 'bat_run_anim_f2', 'bat_run_anim_f3',
'slime_idle_anim_f0', 'slime_idle_anim_f1', 'slime_idle_anim_f2', 'slime_idle_anim_f3',
'slime_run_anim_f0', 'slime_run_anim_f1', 'slime_run_anim_f2', 'slime_run_anim_f3',
```

### 2.2 `MONSTER_ANIM`：改两行

```js
/* 旧 */
slime: { idle: 'tiny_slug', run: 'tiny_slug' },
bat:   { idle: 'imp_idle', run: 'imp_run' },

/* 新 */
slime: { idle: 'slime_idle', run: 'slime_run' },
bat:   { idle: 'bat_idle',   run: 'bat_run' },
```

- 键名就是组前缀，**不要**写成 `'bat_idle_anim_f0'`（会拼成 `..._anim_f0_anim_f0`，取帧失败后静默回退到 `monster_chort`）。
- 改完后 `bat` 与 `slime` 不再经过任何借帧分支；`MONSTER_ANIM` 里 10 种基础怪全部指向自己的帧组。

### 2.3 计数断言：339 → 355

- 磁盘现有 **355** 张；`NAMES` 接完线后也应是 **355**。
- `preflight/verify_d21.html` / `verify_d30.html` 里的"339"断言会失败，这是**预期内的数字变更**，需在接轨的那次改动里同步（本轮按约束不动 `preflight/`）。
- `LICENSE.md` 已同步写为「355 落盘 / 339 已注册 / 16 待注册」，接完线后改成「355 / 355 / 0」。

## 3 落屏与尺寸（不需要改的地方）

- 两张新怪都是 **24×24**，与 `imp / goblin / skelet` 同尺寸；如果绘制端按高度取尺寸，落屏高度仍是 24，**不需要**任何缩放系数。
- 颜色全部取自既有 **84 色板**（每帧 7 色），**没有新增颜色**；审计脚本复算应与 `paletteSize=84` 一致。
- 全部像素不透明（`semi=0`），无半透明抗锯齿；轮廓统一 1px `#222222`，与既有小怪一致。

## 4 四帧在演什么（验收时可对照）

| 组 | f0 | f1 | f2 | f3 | 读法 |
|---|---|---|---|---|---|
| `bat_idle` | 展翼、身体中位 | 收翼（翼尖上抬 1px）、身体上浮 1px | 展翼 | 翼尖下压 1px、身体下沉 1px | 悬停呼吸，幅度小 |
| `bat_run` | 翼尖高抬、身体上浮 | 翼尖下压、身体下沉 | 翼尖最高 | 翼尖最低 | 快速拍翼，幅度大 |
| `slime_idle` | 标准圆顶 | 拉高变窄 | 压扁变宽 | 略高 | 软体呼吸 |
| `slime_run` | 压扁前倾 | 拉高 | 中位 | 拉高变窄 | 弹跳式挤压 |

- 两组的 `f0→f3` 都能无缝回环；渲染按 `animIndex(name, 4)` 取帧，即 4fps，不需要额外调帧率。
- 蝙蝠飞行不落地，底部留白 1–2px 属正常；史莱姆底边压在画布第 20 行并带一行阴影，与 `tiny_slug` 的"贴地收口"一致。

## 5 验收（接完线直接跑这三条）

1. `bat` 与 `slime` 在战斗/地图上不再出现小恶魔、蛞蝓的外形；两者移动与待机可区分。
2. `Sprites.getFrame('bat_idle', 0)`、`getFrame('slime_run', 3)` 返回非空（不是 `monster_chort` 兜底）。
3. 素材审计：355 落盘 / 355 注册 / 0 缺失 / 0 空帧；`paletteSize` 仍为 84。

## 6 本轮没做、也不要顺手做的

- **没有**把 16 个文件名写进 `NAMES`（按约束不碰 `js/`）。
- **没有**改 `verify_d21/d30` 的 339 断言（属接轨同批改动）。
- **不要**给这两组加 `_anim_f4`：现有小怪是 4 帧，5 帧会破坏 `animIndex % 4` 的取帧假设。
- **不要**把新帧加进 `ITEM_ICONS` 或 `MONSTER_ANIM` 之外的映射表——它们只服务 `bat` / `slime` 两个 id。
