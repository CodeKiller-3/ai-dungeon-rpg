# D-10 三局脚本化 E2E

## 一、定位与边界

**脚本驱动**的端到端回归，**不等于真人试玩**，不能替 v1 收工签字。只验三件事，多一件都不做：

1. 三局全程控制台无红色 JS 错误（`error` / `unhandledrejection` 计数为 0）；
2. 无卡死：任意时刻不存在超过 15s 的无响应间隔；
3. 每局结算页出现后，能用键盘回到主界面（不是只能刷新页面）。

本卡不写任何「已连玩 3 局」「手感正常」「v1 可收工」类结论；`README.md`、`docs/答辩讲稿.md` 零改动。

## 二、判定口径

| 项 | 口径 |
|---|---|
| 错误计数 | 页面最早注入 `window.addEventListener('error')` 与 `unhandledrejection`；驱动步内 `Main.loop()` 抛出的异常也计入。按局取「本局开始后的新增条数」，不把上一局错误算进下一局。 |
| 无响应间隔 | 用 `performance.now()`：相邻两次驱动步**起点**的差值（即上一驱动步的耗时 + 步间空隙）。**不用 rAF 间隔**——headless 合成器会把 rAF 节流到低频，产生与游戏响应无关的假阳性（`verify_smoke` 已记录该现象并据此改用主动驱动）。三局各自输出实测 `maxGapMs`，断言 `<= 15000`。 |
| 结算页出现 | 玩家 HP 归零后 `battle:end {result:'lose'}` → `Main.openGameOver()` → `Modal.open('gameover')`；断言 `Modal.current()==='gameover'` 且 `Player.hp===0`。 |
| 回到主界面 | 在结算面板上派发真实 `keydown`（Enter）→ `Modal` 的 gameover 分支调用 `Main.restart()` → 断言 `Modal.isOpen()===false && Main._scene==='explore'` 且玩家回到新局基线（HP 100 / 金币 0 / 等级 1 / 经验 0）。 |

## 四、驱动方式与断言

每局固定四段，全部走既有入口，不新增钩子：

1. `Game.Core.Main.restart()` 起局；断言新局基线（`freshState`）。
2. 真实键盘事件验证探索输入：`KeyB` 打开背包 → `Escape` 关闭；断言 `inventoryOpened` / `inventoryClosed`。
3. 战斗到结算：`Game.Systems.Battle.start('dragon')` + `Main.switchScene('battle')`（与 `ai:encounter` 相同入口），随后每步派发真实 `Digit1` 并同步调用 `Main.loop()`，直到 gameover 面板出现（地牢巨龙 atk 18 / 玩家 def 5 → 每回合 13 伤害，玩家 100 HP 必死；玩家 atk 10 / 巨龙 def 8 → 每击 2 伤害，不可能先杀，故结算方向确定）。
4. 派发 `Enter` 回主界面；断言 `backToTitle` 与 `restartedFresh`。

页面输出：每局一行 `PASS {"run":N,"errors":0,"maxGapMs":<实测>,"backToTitle":true,...}`，最后一行汇总 `PASS {...}`（任一局 `ok=false` 时汇总行输出 `FAIL`，`run-all.ps1` 会因同时出现 PASS/FAIL 判 `MIXED`，会计入失败页）。

## 五、取舍与已知缺口

1. **进战斗用 `Battle.start` 而非在地图上撞怪**：撞怪依赖地图随机生成与 AI 追击，三局无法保证在同一时间点进入同一战斗；`Battle.start + switchScene('battle')` 是 `onAiEncounter` 自身使用的既有入口，未改游戏代码。探索输入仍用真实键盘事件覆盖。
2. **结算方向固定为失败**：胜利需要击杀巨龙（150 HP / def 8），三局脚本化会引入大量回合与掉落随机；本卡只要求「走到结算（胜或负皆可）」，失败分支同时覆盖 `Save.clear` 与 gameover 面板，覆盖面更关键。
3. **只验键盘返回，不验点击返回**：gameover 的「重新开始」按钮矩形在 `Modal` 私有变量 `gameRestartRect` 中，页面无法在 `file://` 下不新增钩子地稳定拿到并换算点击坐标；card 允许「键盘或点击」，键盘路径已证明不是只能刷新页面。
4. **本卡为脚本驱动，未验证手感、平衡、可玩性；v1 收工仍需真人连玩 3 局与线上核验。**
5. 无响应口径只覆盖「同步驱动步阻塞」；真人环境下的 rAF 掉帧、输入延迟不在本卡能力范围。
