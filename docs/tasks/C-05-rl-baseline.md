## 二、实现方式（全部在 `preflight/verify_c05.html` 内）

### 同条件对照的五个条件与落实方式

| 条件 | 落实方式 |
|---|---|
| 同一批地图采样 | 固定 7 个种子 `101/202/303/404/505/606/707`；两组对每个种子各自 `Map.setFloor(1)`（该接口清空楼层快照，确保真正重生成）生成地图，并用网格 FNV-1a 逐一比对相等 |
| 相同步数上限 | 两组都是 60 步；随机组用常量 `MAX_STEPS=60`，Q 组用 `learner.js` 自带的 `maxSteps = 60`，并由源码文本核对 |
| 相同起点采样方式 | 随机组复刻 `learner.randomOpen` 的算法（300 次尝试、`1..w-2`/`1..h-2` 均匀、`grid===1` 才取），同样由源码文本核对 |
| 相同成功判定 | 两组都是"60 步内到达目标格"；随机组判定式与 `learner.stepOne` 的 `nx === target.x && ny === target.y` 一致，源码文本核对 |
| 相同运行次数 | 随机组每图 episode 数 = Q 组该图训练产生的 episode 数（逐图相同，实测 60/58/57/53/59/55/64） |

### 两组各自的 runner

- **Q 组**：`GenMap(seed)` → 取全新 `learner` 模块实例 → `init(grid)` → `tick(1)` × 3000 → `getStats().successRate`。不改 `α/γ/ε`，不改奖励（命中 +10、靠近势 +0.5、撞墙 −1），不加任何评测专用代码。
- **"全新模块实例"的原因**：`learner.js` 的 `epsilon` 是模块级变量，`init` 不重置它；同一页面顺序跑 7 张图会让第 2~7 张从 ε=0.05 起跑（第 1 张从 0.4 起），产生顺序效应。为让 7 张图条件一致，本页用同步 XHR 读 `learner.js` 源码后 `(0,eval)` 重新执行一次 IIFE，得到"同一份源码、同一组超参、ε=0.4、Q 表为空"的新实例；`js/` 文件本身零改动。
- **随机组**：每步在 4 个动作里均匀随机；撞墙计一步（与 `learner.stepOne` 的步数语义一致）；到达目标即该 episode 成功；不使用、不读取、不构建任何 Q 表。

### 种子化

- 页面内 `mulberry32(seed)` 替换 `Math.random`（`withSeed` 作用域内替换、结束即恢复），使 `Map.setFloor`/`Map.generate`、`learner.init/tick`、随机组全部可复现。
- 地图种子与策略种子分离（策略种子 = `seed * 7 + 11`），避免"地图与智能体随机流耦合"。

## 六、取舍与已知缺口

1. **实测结论（无论正负都照实写）**：7 张图上 Q 组 28/22/18/9/24/13/31，随机组 8/3/4/6/12/2/5；中位数 22% vs 5%，区间 9%~31% vs 2%~12%。本批样本里 Q 在每张图都高于随机，但样本仅 7 图，**不足以宣称稳定收敛**，也未据此加断言。
2. **与旧口径（2%~26%、中位数 9%）的差异**：旧数字取自历史单图/顺序训练采样（未固定种子，且 ε 跨图衰减），其"中位数 9%"与本卡"22%"不可直接对比。本卡固定种子、每图独立模块实例后条件统一，中位数上移；已按实测改写 README 与讲稿，旧数字不保留。原因是采样方式不同而非算法改动——`learner.js` 源码零改动可佐证。
3. **"全新模块实例"的边界**：`eval` 只用于让 ε/Q 从初始状态起跑，不改变任何超参与奖励；若规划端认为应改用"顺序训练"口径，需另开卡并重测（届时数字会变）。
4. **随机策略的步数语义**：撞墙计一步、原地不动，与 learner 的"撞墙 reward=-1 且停在原地"一致；这是"同条件"的必要代价，也让随机策略略弱于"撞墙不计步"的宽松口径——但口径由 learner 决定，不另调。
5. **未动 UI**：游戏内 L 演示界面不展示随机策略对照（会改 UI 与运行时开销）；对照数据只存在于验证页与文档，答辩时以数字说明。
