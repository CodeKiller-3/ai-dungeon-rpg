# D-49 自适应难度与兜底救援

- 日期：2026-11-13
- 性质：功能卡 + 轻度数值（救援装备）。不改怪物 / Boss / 伤害公式 / 楼层结构 / 买价卖价 / 存档键。
- 前置：D-47 NPC、D-48 首屏与设置、D-45 装备档位表、D-46 金币口径（单任务 ≤60，主线 ≤120，任何单任务 ≤150）。

## 需求原文

### 要做
1. **表现记录**：每层记录掉血比例、死亡次数、死亡层、当前装备档位。只记录，不进存档以外的隐藏状态。
2. **触发判据**：至少覆盖"同一层连续死 2 次"与"某层出口血 < 20%"；触发点在层间 / 死亡重生时，不许战斗中偷偷给。
3. **分级救助**：一级补给（药水）、二级金币（与 60/120/150 对齐）、三级救援装备（任务/救援专属，不进商店/掉落/不可购买；强度落在当前可买到最好档与最强档之间）。
4. **上限**：单局触发 ≤2 次；所有救援折算金币等价 ≤150。
5. **可关闭**：设置页加"自适应难度"开关，默认开；关闭后行为与 D-48 完全一致。
6. **可感知**：触发时给一句明确提示（谁给了什么、为什么）。

### 硬约束
- 零构建、`file://` 可玩
- 存档键 `ai_dungeon_rpg_save_v1` 不改名，只加字段；旧档默认自适应开、补默认不报错
- 不改怪物 / Boss / 伤害公式 / 楼层结构 / 买价卖价
- 救援装备不得出现在商店货架、宝箱池、怪物掉落表
- 不改既有 bot 判据（只加默认关闭的开关）
- 不覆盖 D-37 至 D-48 任何产物

### 验收（新建 `preflight/verify_d49.html`，`page-baseline.json` 89→90）
A 触发判据可复算；B 上限断言；C 关闭后复现 D-48；D 未触发局不稀释；E 救援装备三表隔离；F 旧档兼容；G 四策略同种子；H 开关持久化。

## 0. 结论

新增 `Game.Systems.Adaptive`，只在两个非战斗时刻判断：**战斗死亡结算**与**换层落点**。首次死亡 → 一级补给（2 小血瓶）+ 复活至 50%；累计第 2 次死亡（含同层连续 2 次）→ 三级救援装备「守夜人的旧剑」(atk13) + 复活至 60%；离开某层时 HP <20% → 二级 60 金币。单局最多 2 次，金币等价上限 150，每次触发都有明确文案。

设置页新增「自适应难度」（默认开），关闭后两个钩子直接返回 `null`，B1 逐局 outcome 与 D-48 **完全一致（7/50，50 局零差异）**。救援装备用不可枚举属性挂在 `ITEMS` 上：商店 / 宝箱 / 怪物掉落三张表都查不到，`Object.keys(ITEMS)` 仍是 48 件，D-45 的 Σprice / Σsell / FNV 不动。

开启后 B1 **10/50（目标 15，差 5）**；零触发局 7 局全部保持 D-48 结局（7 胜）；43 个被救援局里只多赢 3 局。G2 到 F5 由 19→38、S1 由 25→35、M1 到 F4 由 29→50。救援装备发放 23 次，全部来自救援。

## 1. 设计

### 1.1 触发判据与理由

| 判据 | 触发点 | 级别 | 为什么 |
| --- | --- | --- | --- |
| 累计第 2 次死亡（含同一层连续 2 次） | `battle:end lose` 结算内、清档前 | 三级 | 第一次死亡给补给让玩家再试一次；第二次仍死说明"补给不够"，必须换更强的手段（装备） |
| 离开某层时 HP < 20% | `changeFloor` 落点、`resetPlayer` 之后 | 二级 | 血线见底还往下走，下一次遭遇大概率猝死；在层间给 60 金币让玩家自己买药/装备 |
| 首次死亡（兜底） | `battle:end lose` 结算内 | 一级 | 没有第一次复活就永远到不了"连续死 2 次"；这条是判据能成立的前提 |

- 触发点全部在**战斗结束之后**或**换层落点**，战斗回合中不注入任何东西。
- 死亡计数按层记在 `player.adaptive.deaths[floor]`；到达新层时把新层计数清 0，因此"连续"= 没离开本层就再次死亡。
- 每条未触发的检查也会写进 `trace`（`why=disabled / budget / hp-ok`），验证页 A 组可查"为什么没触发"。

### 1.2 分级救助与金币等价

| 级别 | 发放 | 金币等价 | 备注 |
| --- | --- | --- | --- |
| 一级 | `potion_small ×2` | 20 | 首次死亡；复活至 50% |
| 二级 | 60 金币 | 60 | 低血换层；与"单任务 ≤60"同口径 |
| 三级 | `sword_rescue`（atk13） | 90 | 第 2 次死亡；复活至 60% |

- 组合上限：20+90=110；60+90=150；20+60=80；三级在 F5 或当前武器已 ≥13 时改发等值 60 的补给包。
- `Adaptive.trigger()` 里还有一次硬夹：`spent + value > 150` 时只发剩余额度，任何组合都不会越线。

### 1.3 救援装备强度推导（D-45 档位表）

D-45 / C-04 的可买到最好武器档：F1 atk3（sword_iron）、F2 atk8（sword_steel_rare）、F3 atk12（sword_anime）、F4 atk12（sword_anime/sword_knight）、F5 atk16（sword_dragon_epic）；现有最强档 atk16。

- 取 **atk13**：高于 F1–F4 的可买最好档（3/8/12/12），严格低于现有最强档 16。
- F5 的可买最好档已等于最强档（16），区间为空，因此 **F5 不发放装备**，改发等值补给。
- 名称「守夜人的旧剑」，`price 90 / sell 45`（仅作金币等价与买价>卖价口径，不可购买）。

三表隔离做法：`Game.Data.RESCUE_ITEMS` + 在 `ITEMS` / `ITEM_ICONS` 上用 `Object.defineProperty(..., {enumerable:false})` 挂一个不可枚举条目。`ITEMS[id]` 直接访问照常工作（背包/装备/弹窗），但 `Object.keys(ITEMS)` 仍是 48 件，D-45 的物品 Σprice / Σsell / FNV 断言不受影响。

### 1.4 可关闭

- 设置页第 4 行「自适应难度」（前三行仍是 D-48 的打击感 / 音效 / 画面缩放；`_settingsSpec()` 保持 3 项，D-48 的 E 组断言不被破坏）。
- 持久化到既有 `aiDungeon_settings_v1`（`adaptive: true/false`），关闭后 `Adaptive.onDeath` / `onFloorArrived` 直接返回 `null`。
- 机器人侧新增默认关闭的 `opts.adaptive`：不传 = 关闭，D-49 的跑局显式传 `true` / `false`。

### 1.5 提示文案

- 一级：「楼梯口的守夜人递来两瓶小血瓶：『刚才那一下够狠，先活着。』（自适应救援 1/2 · 补给） 生命恢复至 50%。」
- 二级：「守夜人塞来 60 金币：『买点保命的，别硬撑。』（自适应救援 n/2 · 金币）」
- 三级：「守夜人把自己的旧剑按进你手里（攻击 +13）：『拿着，活着下去比什么都强。』（自适应救援 n/2 · 救援装备） 生命恢复至 60%。」

文案不写"你太菜"，只写"守夜人"这个叙事角色与具体给了什么。

## 4. 必须回答

### 4.1 触发条件是什么？为什么是这两个？

见 §1.1：累计第 2 次死亡（含同层连续 2 次）→ 三级；离开某层 HP <20% → 二级；首次死亡 → 一级兜底。理由：第一次死亡先给补给让玩家自己再试，第二次仍死才升级到装备；低血换层是在"下一次遭遇必死"之前给钱。触发点固定在死亡结算与换层落点，战斗中不给。

### 4.2 一共触发了几次、在哪几层、给了什么？

50 局 86 次：43 局 ×2 次；F2 10、F3 9、F4 29、F5 38；`potion_small ×2` 43 次、`sword_rescue` 23 次、F5 等值补给 20 次。**二级"低血换层"在这 50 局里 0 次**（trace 里都是 `hp-ok`）——代码路径存在且可断言，但 B1 的死亡都发生在战斗里，没有"低血成功换层"的样本。

### 4.3 通关率涨到多少？涨的那部分是不是全靠救援？

B1 7→10（+3）。7 个零触发局全是原来的 7 个胜局（1003 / 1004 / 1016 / 1019 / 1036 / 1043 / 1044）；43 个被救援局里只多赢 3 局（1005、1033、1041，靠 F2/F3 的 atk13 旧剑与多一次复活）。其余 40 个被救援局仍然输在 F4/F5——F5 触发 38 次却只能发等值补给，因为 F5 可买最好档=最强档 atk16，没有"中间档"可发。

### 4.4 没触发的局被稀释了吗？用数据说。

没有。7 个零触发局的 outcome 与 D-48 逐局完全一致（7 局全胜）；关闭自适应后 50 局 B1 outcome 与 D-48 零差异（7/50）。C / D 两组都是逐 seed 对比，不是只看总数。

### 4.5 玩家会不会觉得被施舍？提示文案怎么写？

文案用"守夜人"这个 NPC 口吻，只说他给了什么、为什么（"刚才那一下够狠，先活着" / "买点保命的，别硬撑" / "拿着，活着下去比什么都强"），不评价玩家水平；每次带"自适应救援 n/2 · 补给/金币/救援装备"标签，让玩家知道这是系统的兜底而不是正常掉落。
