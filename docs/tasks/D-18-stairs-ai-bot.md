## 三、第一件：楼梯落点导致不可达（真缺陷）

### 3.1 缺陷机理

`changeFloor(±1)` 不是"走到隔壁"，而是把玩家**传送到目标层出生点 (1,1)**。所以楼梯格是**传送门，不能当走廊穿行**。

原 `placeStairs()` 只抽两个"空地"直接写 tile 3 / tile 2，不做任何可达性校验。当上行梯落在宽度 1 的唯一走廊上时：

1. 出生点到下行梯的唯一路线必须经过上行梯；
2. 踩上去立刻被传送回上一层；
3. 从上一层再下来，又回到本层出生点——**下行梯永远走不到**。

D-17 的 4/50 卡关全部是这个原因（`stuckReasons = {"上行梯封住唯一走廊":4}`）。

### 3.2 修法（不降难度）

- 判据：**去上行梯的路上不许踩下行梯；去下行梯的路上不许踩上行梯**。这比"网格连通"严格，因为它表达的是真实移动语义。
- 第 1 层的上行梯 / 最深层的下行梯：`changeFloor` 越界返回 `null`，踩上去等同普通地板，**不计入阻断**（否则会把正常地图误判为卡死）。
- 首轮抽样顺序与旧实现一致（先上行梯、再下行梯），只有校验失败才整体撤销重抽 ⇒ 原本合法的地图指纹不变，**只有真正会卡关的层会重新抽**。
- 60 次重抽仍失败 → 扫全图找死角（可走邻居 ≤ 1 的格子不可能成为别人路径的中间点，放楼梯必然安全），扫描顺序固定、不消耗随机数。
- **未改**：每层仍是 1 上 + 1 下、地图尺寸、房间数、楼层数、敌人数（仍为 `5+2×(层-1)`）。

### 3.3 证明（`verify_d18` A 组）

| 断言 | 实测 |
|---|---|
| `A1_birthToUpStairReachable` | 200 种子 × 5 层 = **1000 张地图**：出生点→上行梯（不踩下行梯）、出生点→下行梯（不踩上行梯）、以及两条普通可达性，**0 失败** |
| `A2_exactlyOneStairEach` | 每层恰好 1 个 tile 3 + 1 个 tile 2，**0 异常**（没有靠减楼梯回避） |

| `A4_checkerDetectsBlockedCorridor` | 合成地图：上行梯卡在宽度 1 的唯一走廊 → 判不可达 `true`；上行梯挪到支路 → 双向可达 `true`（负例证明断言不是空转） |

### 3.4 地图指纹影响

- 抽样序列确实变了（失败重抽会多消耗随机数）⇒ **部分种子的地图指纹改变**，D-17 与 D-18 **不是逐种子可比**的，对照只能看分布。

## 四、第二件：A\* 坐标转置越界（真缺陷）

### 4.1 缺陷机理

`Graph(data)` 把**第一维当 x 用**：`g.grid[真实y][真实x]`，所以节点上 `node.x = 真实 y`、`node.y = 真实 x`。`nextStep` 取起点/终点时用 `g.grid[from.y][from.x]` 是**对的**，但返回第一步时直接 `{x: path[0].x, y: path[0].y}` 是**转置**的：

- 多数情况 → `tick()` 里 `grid[next.y][next.x]` 的 `next.y` 超过行数 ⇒ TypeError（D-17 的 230 帧）；
- 少数情况 → 坐标刚好在界内且是地板，怪物会"斜跳"一格到不相邻的格子；
- 异常在 `tick()` 的 `try` 之外，同帧剩余巡逻怪被整段跳过。

### 4.2 修法

只改消费端一行：`return { x: path[0].y, y: path[0].x }`。**图的构建、`astar.search` 调用、`closest:true` 全部未动。**

### 4.3 等价性证据（`verify_d18` B 组）

同一次搜索拿到的 `path` 数组在两套映射下长度必然相同（映射不改搜索）。42 次真实重规划实测：

| 项 | 值 |
|---|---|
| 路径长度一致 | **42 / 42**（min 3 / 中位 10 / max 66，均值 16.74） |
| 新映射首步"相邻且可走" | **42 / 42** |
| 旧映射差异逐类 | 越界 **12**、撞墙 **14**、跨格 **14**、方向被镜像 **1**、落在 `x=y` 对角线上两套映射相同 **1**，合计 **42/42** |

即：**没有任何一条差异是"换了条更长的路"**，全部是被修掉的缺陷本身（越界 / 非法落点 / 非相邻移动）。其中"方向被镜像"这一类不会崩，但会让怪走错方向——修前无法通过崩溃计数发现，本次一并消除。

| 断言 | 实测 |
|---|---|
| `B1_twoHundredRunsNoThrow` | 200 局（种子 1201–1400，`maxActions=700`，共 90023 步）**抛错 0 帧**（修复前同入口 50 局 230 帧） |
| `B2_negativeTransposeFails` | 把转置写回去（在 astar 出口交换 x/y，等价于旧的 `path[0].x/.y`）→ 5 局抛 **11 帧**，证明 B1 能抓回归 |

### 4.4 同类越界排查

- 起点 `g.grid[from.y][from.x]`、终点 `g.grid[to.y][to.x]`：`from/to` 都来自巡逻怪与玩家坐标，行/列索引顺序正确，无越界。
- `Graph.prototype.neighbors`：`grid[x-1] && grid[x-1][y]` 双向都有边界守卫，不存在同类越界。
- `tick()` 里 `grid[next.y][next.x]`：修好映射后 `next` 必为图内相邻格，不再越界。
- 结论：**同类越界只此一处**，已无潜伏点。

### 4.5 只记录、未修

- 第 1 层也放上行梯、第 5 层也放下行梯：`changeFloor` 越界返回 `null`，踩上去像踩空（无提示、无位移）。修它要动地图生成与「每层楼梯数」的既有断言，收益低、指纹影响大，本卡**只记录**。可达性校验已按"空转 = 普通地板"的真实语义处理，不会因此误判。

## 五、顺带修掉的真缺陷：模态框监听器泄漏

**发现方式**：校准 bot 时 `Shop.buy` 的调用次数（695）远大于实际成交（4），逐层定位到 `Modal.open()`——它只 `_bind()` 不先 `_unbind()`，一旦"开着再开"就会把上一份 `keydown` 监听器的引用覆盖掉，导致它永远删不掉。之后**每按一次 `Enter` 会被重复确认 N 次**。

- 影响面：不只是商店。长跑后一次 `Enter` 在背包里会连续使用多瓶药 → **D-17 的"34 局死亡时无药"被这条泄漏放大过**（bot 实际嗑药比真人的一次一按更多）。
- 修法（1 行）：`open()` 在 `kind !== null` 时先 `_unbind()`。
- 验证：同一批种子修复前 `Shop.buy` 调用 695 次 / 成交 4 件，修复后 **调用 4 次 / 成交 4 件**；全量回归 60/60 全绿。

## 八、缺口

### 8.1 新 bot 与真人还剩哪几条差距

1. **战斗内不能用药**（最大一条）：`_updateBattle` 没有用药指令。50 局里有 **16 局**死亡时背包仍有回血药却用不出去。真人在 Boss 战嗑药是常态。
2. **不会逃跑**：D-15 已实现逃跑机制，bot 从不用。真人血量见底会退一格。
3. **不会用技能 4 / 5**：只会 `Digit6` 护盾。冲刺与 AOE 的收益未被计入。
4. **不会主动刷任务**：哥布林任务要求 5 只，bot 只按探索路径顺手打（单局最多 3 只）。
5. **不会追宝箱/密室**：宝箱是踩上去自动拾取，但 bot 的目标只有"未探索格"和"下行梯"，不会为一个 `rich` 宝箱绕路。
6. **不会按怪物类型换装**：只比 `atk/def` 总分，不考虑命中/属性克制（游戏本身也没有克制系统）。
7. **不会跨层回访**：每层只走一遍，不会退回上一层补给或绕路。
8. **寻路是"上帝视角"**：BFS 直接读 `Map.getGrid()`，真人受 FOV 限制，会漏掉未见的岔路。
9. **每层只开一次店**：真人可能在攒够钱后回头再开（每次开张会轮换货架，bot 不利用这一点，是刻意的——避免把"刷货架"当成策略）。

### 8.2 修复后 0 通关是否改变结论

**没有改变"bot 通不了关"，但改变了归因**：

- 原来的 0/50 里混着 **8% 的地图缺陷卡关**（真人也会被困），这部分已修掉；
- 原来"7 局打到 F4"里有监听器泄漏导致的多嗑药成分，修正后只有 **1 局**到 F4；
- 校准后的 bot 会买药、会买装备、会换装，**仍然 0 通关、50 局全部死于战斗**，且 32 局死在 F2。

所以现在的结论更硬：**卡住玩家的不是地图，是战斗强度与资源节奏**。但这句话只对"这个 bot"成立——它不会逃跑、不会战斗中嗑药、不会用技能，真人的上限仍然没有被测到。

### 8.3 "楼梯可达"这个验证方法测不到什么

1. **只验证静态地图**：不验证怪物堵路、陷阱位移、FOV 遮挡下的实际走位。理论上地图可达 ≠ 玩家一定能走到。
2. **只验证单层**：三层之间的往返（下楼→上楼→再下楼）没有逐步模拟。虽然每层都重置到出生点、逻辑上应成立，但"来回换层后楼梯是否还在原位"依赖 `floorCache` 缓存，未在本断言覆盖。
3. **不覆盖全部种子空间**：200 个种子 × 5 层 = 1000 张图，不是穷举。
4. **noop 楼梯按"可穿行"处理**：第 1 层上行梯 / 第 5 层下行梯的语义来自"`changeFloor` 越界返回 null"。如果以后改成"留在原层并提示"，这条判据要重算（代码里两处都写了 `floorIndex` 判断，改一处即可）。
5. **死角兜底分支未被覆盖**：1000 张图里主抽样（60 次内）都已通过，兜底扫描分支没有实际触发，属于"写了但没被跑到"的代码，只能靠合成地图间接证明逻辑。
6. **不测落点的"手感"**：楼梯是否离出生点太近、是否总是落在同一个角落，不在断言范围（`findOpen` 的距离约束未改）。
