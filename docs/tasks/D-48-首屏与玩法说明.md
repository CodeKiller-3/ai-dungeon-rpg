# D-48 首屏与玩法说明

- 日期：2026-11-13
- 性质：产品功能卡（不改战斗数值、不改怪物、不改楼层结构、不改存档键）。

### 要做
1. **主菜单作为启动首屏**：至少包含 开始新游戏 / 继续游戏 / 玩法说明 / 设置 / 关于。视觉沿用现有像素素材与字体，不引外链资源。
2. **继续游戏**：有档时可进、无档时置灰并给一行说明，不许点了没反应也不许报错。

## 0. 结论

冷启动现在先落**主菜单**（开始新游戏 / 继续游戏 / 玩法说明 / 设置 / 关于），菜单是主循环内的一个场景，不是第二套循环：`Main.start()` 加了 `_rafStarted` 守卫，重复调用直接返回 `false`，进入/退出菜单只做 `switchScene`。`index.html` 用 `window.__AI_DUNGEON_MENU__ = true` 声明首屏；所有既有验证页 / 机器人页不声明，`init()` 仍直接进 explore，行为与 D-47 完全一致。

「继续游戏」用 `Save.has()` 现查存档：无档时选项置灰、右侧写「暂无存档」，按 Enter 只给一行提示并留在菜单（`enterGame('continue')` 返回 `false`，不抛错）；有档（含 D-46 及之前的 v1 旧档）读入后进 explore。

玩法说明 8 条，每条都带 `src`（源码文件）与 `need`（必须字面出现的实现片段），`verify_d48` 逐条对照；负例塞入「按 8 键治疗」时判据直接拒绝。设置页只有三项既有开关（打击感 off/low/high、音效、画面缩放），改动即时生效并持久化到独立键 `aiDungeon_settings_v1`，不碰存档键。

同种子 1001–1050 / maxActions 2500：B1 **7/50**、G2 到 F5 19、S1 到 F5 25、M1 到 F4 29，与 D-47 **逐局一致**（零退化）。

## 1. 设计

### 1.1 首屏长什么样、怎么排

- 深色网格背景 + 金色标题「AI 勇者闯地牢」+ 副标题「往地牢更深处走 · 第 5 层击败地牢巨龙」。
- 五个选项竖排居中：**开始新游戏 / 继续游戏 / 玩法说明 / 设置 / 关于**；选中项金框 + `▶`，未选中灰色。
- 「继续游戏」无档时整行变暗，右侧显示「暂无存档」。
- 底部固定提示：`↑↓ 选择 · Enter 确认 · 鼠标可点（非必需）`。
- 全部用 canvas 纯色块与 monospace 字体绘制，沿用现有字号与配色（`#0b0c14 / #ffcf6e / #9bbbf4 / #7f8fa8`），不引任何图片或外链。
- 冷启动实拍：`preflight/artifacts/d48-menu.png`（1280×800，Edge headless）。

### 1.2 继续游戏：有档 / 无档

| 状态 | 选项 | Enter 行为 | 场景 |
| --- | --- | --- | --- |
| 无存档 | 置灰 +「暂无存档」 | `enterGame('continue')` 返回 `false`，`ui:notice`「暂无存档：请先开始新游戏」 | 留在 menu |
| 有存档 | 正常可选 | `Save.load()` 成功 → 进 explore，恢复金币/血量/背包 | explore |
| 存档损坏 | 正常可选 | 返回 `false`，提示「存档无法读取」 | 留在 menu |

读档期间复用既有 `booting` 守卫，避免 `floorChanged → Save.save()` 用半读状态覆盖磁盘档。

### 1.4 设置：只放既有三项

| 项 | 取值 | 即时生效调用 | 持久化 |
| --- | --- | --- | --- |
| 打击感 | 关 / 低 / 高 | `Game.Fx.setLevel` | `aiDungeon_settings_v1` |
| 音效 | 开 / 关 | `Game.Systems.Audio.setMuted` | 同上 |
| 画面缩放 | 自动 / 100% / 125% / 150% | `Render.setScaleMode` → `resize()` | 同上 |

默认值与改前一致：打击感 `low`、音效开、缩放 `auto`（`_computeScale` 原公式），因此所有既有像素/坐标断言不受影响。

### 1.5 菜单与场景之间的循环

- `Main.start()` 是全游戏**唯一**的 `requestAnimationFrame` 入口，首行 `if (this._rafStarted) return false;`，成功后 `_rafChains = 1`。
- `loop()` 内按 `_scene` 分支：`scene === 'menu'` 时走 `_updateMenu()` + `Render.drawMainMenu()`，与 explore/battle 同级，**不新开任何定时器或 rAF**。
- 进场景只调用 `enterGame('new'|'continue')` → `restart()` / `Save.load()` → `switchScene('explore')`；没有 `start()`/`stop()` 的反复启停。
- `verify_d48` F 组断言：`start()` 返回 `true`、第二次返回 `false`、菜单↔场景往返多次后 `_rafChains` 仍为 1，整帧执行无异常、页面级错误为 0。

## 4. 必须回答

### 4.1 首屏长什么样？有哪些选项、怎么排的？

深色网格背景，顶部金色标题 + 副标题，中间竖排五个选项「开始新游戏 / 继续游戏 / 玩法说明 / 设置 / 关于」，选中项金框与 `▶`、未选中灰色；无档时「继续游戏」整行变暗并显示「暂无存档」；底部一行键盘提示。全部 canvas 绘制、沿用现有字体与配色。

### 4.2 没存档时点「继续游戏」会发生什么？

不会报错、不会没反应：选项本身置灰并带「暂无存档」说明；按 Enter 时 `enterGame('continue')` 返回 `false`，底部提示条给一行「暂无存档：请先开始新游戏」，场景仍停在菜单。

### 4.3 说明页每一条，在代码里对应哪一处？

见 §1.3 对照表（8 条，逐条列 `src` 与 `need`）。验证页 D 组用同一份 `Main.HELP` 数据逐条匹配源码，负例会被拒绝。

### 4.4 菜单和场景之间的循环是怎么接的？怎么保证没有两条 rAF？

菜单是 `loop()` 内的一个场景分支；`Main.start()` 用 `_rafStarted` 保证只注册一条 rAF 链，重复调用返回 `false`；进/出菜单只走 `switchScene` 与 `enterGame`，不调用 `start()`。F 组用 `_rafChains` 计数与二次 `start()` 返回值做断言。

### 4.5 通关率变了没有？

没有。B1 7/50、G2 19、S1 25、M1 29，与 D-47 逐项相同；B1 逐局 outcome 零差异。首屏只影响启动路径，且 bot 走默认关闭的 skip 参数。
