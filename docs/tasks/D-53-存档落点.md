# D-53 存档落点 —— 继续游戏不该把人送回出生点

> 性质：**功能卡，不碰数值**。怪物 / Boss / 伤害 / 掉落 / 价格 / 经验 / 救援量 / 地图生成一行未改。
> 存档键 `ai_dungeon_rpg_save_v1` 未改名，设置键未动，D-51 暂停/清档/放弃与 D-52 结局语义保持。

## 一、落点规则

存档新增顶层字段（只加字段）：

```js
pos: { floor: 当前层, x: 玩家格子 x, y: 玩家格子 y }
```

读档顺序：

1. **没有 `pos` / 字段非法 / `pos.floor` 与 `floor` 对不上** → 回本层出生点（旧档路径，不抛错）。
2. `pos` 指向的格子可站立（地板、非楼梯、无怪物/巡逻怪/NPC/宝箱/奖励点/陷阱）→ **原格落地**。
3. 否则在**同一连通块**内 BFS 找最近可站立格；邻居展开顺序固定为 **上 / 左 / 下 / 右**（并列时取先者），
   起点是墙时取该顺序里第一个可走邻格所在连通块。
4. 整块连通区域都没有可站立格（或坐标越界）→ 回出生点。

为什么是"同连通块最近可通行格"：出生点是"倒退"，随便挑一格是"传送"，都可能把玩家丢进未探明的密室或
跨过本应绕行的墙。BFS 保证落点与存档位置在同一片可走区域、且位移最小；固定邻居顺序保证同一份存档
每次读都落在同一格，可复现、可断言。

实现：`Map.resolveLanding(x,y)` / `Map.canLand(x,y)`（[map.js](file:///d:/桌面/工作/人工智能大作业/js/systems/map.js#L1004-L1020)）。

## 二、落点被占用怎么办

**不挪任何东西，玩家让位。** 怪物 / 巡逻怪 / NPC / 宝箱 / 奖励点 / 楼梯 / 陷阱都视为"不可落"，
BFS 找下一格。这样：

- 不会把怪物挪走（不会改变遭遇顺序或刷新位置）；
- 不会因为落在宝箱上而触发拾取（`takeDecor` 只在移动时调用）；
- 不会生成任何新资源，也不会删除任何旧资源。

落点解析是纯查询：只读 `grid/enemies/npcs/decor/traps`，不写、不 emit、不发奖励。

## 三、会不会靠反复存读档拿好处

不会。`verify_d53` D 组连续 20 次「存档→读档」，前后计数完全一致：
金币 55 / 经验 12 / 背包 `{potion_small:2}` / 怪物 5 / 宝箱与奖励点 4，零变化。
读档路径本身：

- 地图走 `importState + generate({quietQuest:true})`，不重生成、不推进楼层任务；
- 落点只做坐标解析，不触发 `takeDecor`、不调用 `Battle.start`；
- 不写回资源字段。

## 四、战斗中途存档再读

**战斗不是存档点。** 游戏内唯一可能在战斗中触发的写档路径是「暂停 → 返回主菜单」；
D-53 起该路径在 `Battle.isActive()` 时**不写盘**，只静默终止本场战斗（`abort`，不发 `battle:end`、不结算奖励），
回到主菜单并提示"战斗中不写档：继续游戏将回到最近的非战斗存档"。

因此：

- 磁盘上永远是最近一次**非战斗**检查点（换层 / 开箱 / 战斗结束后 / 暂停返回时不在战斗中）；
- 读档不会恢复半截战斗，也不会让怪物"凭空满血"——因为根本没有保存半截战斗；
- 不会重复结算：战斗奖励只在 `battle:end` 发放一次，而 `abort` 不触发它；
- 若存档被人为改成"玩家站在怪物格"，读档会 BFS 到邻格、保持探索场景，不自动开战、不加金币/经验、
  怪物数量不变（`verify_d53` G 组两种情形）。

代价：战斗中返回主菜单再继续，会回到最近的非战斗检查点（可能在本层入口或上一次开箱处），
而不是战斗中途。这是为了满足"不许怪物满血 / 不许重复结算"而做的明确取舍，提示条会告知。
