# C-03 货架档位整平 + 弹窗滚动按可用高度判定

- 卡片编号：C-03
- 定位：修两处"余量已归零"的隐患（轮换池档位不齐、弹窗 12 行顶满上限），不是新功能。

## 一、玩家/读者可见行为

1. 五层轮换池的装备项档位全部对齐：F3 的 `bow_elite`(140) 换成 `chain_mail_rare`(240)，不再低于该层核心装备最低价 150；F1/F2 经核算本来就达标，不动。
2. 矮视口（逻辑高 ≤ 450）打开商店/背包/任务/图鉴时，列表改为**滚动**而不是被视口裁掉：面板始终完整落在视口内，首行完整可见，↑↓ 可到达末行。
3. 1280×800（逻辑 1024×640）下行为完全不变：12 行仍一次显示、无滚动条、行坐标与改动前一模一样。
4. 价格、核心货架、轮换池长度、周期全部不变；买价仍严格高于卖价。

## 六、取舍与已知缺口

1. **天花板已归零**：F2/F3 商店合计恰好 12 行 = `MAX_VISIBLE`(12)，再往核心或轮换池加任何一件，展示条数就会顶到安全阀上限；后续卡若要加货必须先扩 `MAX_VISIBLE` 或改分页，不能默默加。
2. 滚动只做整行跳转（↑↓/点击），没有滚轮与拖动条；触屏用户需用键盘或点击可见行。属既有交互边界，不在本卡扩展。
3. 矮视口下页头/页尾不缩放，面板高度只剩 9~11 行可显示；再小（逻辑高 < 250）时 `visibleRowCount` 钳到 1 行仍可用，但可用性差，未做专门版式。
4. F1~F3 轮换池保留 `potion_mana`（消耗品豁免档位约束）；F4/F5 无消耗品。若后续要求"五层都不得出现消耗品轮换位"，需另开卡。
5. `_layout()` 是验证/调试读取接口（与 `_visibleRange` 同类），不参与运行时逻辑。
