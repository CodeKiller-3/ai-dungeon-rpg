# D-14 反馈层修复（ui:notice 接通 / 失败原因 / 战斗文字）

> 补记卡：D-14 当时有实现、有验证页（`preflight/verify_d14.html`）、有截图，但漏了任务卡。本文按 commit `f30f438` 的实际改动回填，**不补写当时没做的事**。

## 1. 背景

到 D-13 为止，游戏已经有战斗、背包、商店、任务、存档，但**玩家做了操作看不到原因**：

- 技能 MP 不足、陷阱触发、宝箱开启、任务完成、升级、商店买卖等事件只改了内部状态，界面上没有统一出口。
- 满血喝红瓶、背包满、任务未达成这类"操作被拒绝"的情况静默失败。
- 战斗界面与探索界面的提示各自为政，位置、字号、存活时间不一致。

## 2. 目标

1. 建立**唯一的文字反馈出口**：任何系统只需 `EventBus.emit('ui:notice', {msg})`，不必知道画在哪。
2. 覆盖 9 类现有事件发送方（技能 / 陷阱 / 密室宝箱金币 / 密室宝箱道具 / 普通宝箱金币 / 普通宝箱道具 / 开局引导 / 任务完成 / 商店），一条不漏。
3. 失败必须给原因（"生命已满""MP 不足""金币不足"），不许点了没反应。
4. 不改变任何战斗数值、掉落、商店价格、存档结构。

配套：`preflight/verify_d14.html`（525 行）、两张证据截图 `preflight/selfcheck/shots/D14-notice-1024x640.png` / `D14-notice-1280x800.png`。

## 4. 契约

- `Game.Notice` 对外只暴露 `push(msg)` 与 `MAX`；绘制由主循环统一调用，调用方不持有时间或坐标。
- 队列满时**挤掉最旧的一条**，不无限增长；同一条消息在存活期内**不重复入队**。
- 文本长度超出可用宽度时按面板宽度截断，不换行、不溢出屏幕。
- 该层**纯展示**：不改任何状态、不推进回合、不触发事件。

## 5. 验证（`preflight/verify_d14.html`）

- `A0`：`ui:notice` 有订阅者、`MAX === 3`、`push` 存在。
- `A1`：生命周期——上限截断、同文案去重、去重仍进历史、过期移除。
- `A2_1` ~ `A2_9`：9 类发送方逐条断言文案（MP 不足 / 踩到陷阱 / 宝箱金币 / 宝箱道具 / 开局 / 任务完成 / 商店金币）。
- `A3`：9 个发送方全部能渲染（`allPresent === 9`）。
- `B1` 起：端到端回放——满血喝红瓶必须被拒绝且背包数量不变（`Modal._confirm → Inventory.use → Modal._report → ui:notice` 全链路）。

## 6. 遗留

- 当时没有任务卡（本卡即为补记），也没有把"提示条"写进独立的界面验收清单；后续 D-28/D-29 的背包信息层与本层无耦合。
- 提示条的最大条数 3、截断策略至今未改，仍以 `js/systems/notice.js` 的 `MAX` 为准。
