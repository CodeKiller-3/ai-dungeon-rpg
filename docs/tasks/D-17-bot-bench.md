# D-17 bot 跑局压测台

## 一、定位（本卡只造尺子）

基线 `379d880`（回归 58/58、静态 32 PASS / 1 WARN / 0 FAIL）。此前所有"改完变好没有"都靠读后感，缺一把能量化"现在多难、多长、能不能通"的尺子。本卡只新增测量工具：

- **不改任何游戏逻辑与数值**（`js/` 零改动，只读引用）。
- bot 必须走**与真人相同的输入入口**（`KeyboardEvent` → `js/core/input.js` → `_updateExplore` / `_updateBattle`），一次输入一个动作，遵守一步一格与 120ms 走格节流、战斗输入锁。
- 策略固定、无随机决策（随机源整体替换为 `mulberry32(seed)`）。
- 不设"难度必须落在某区间"的判定——**只记录，不判题**。

## 三、怎么保证"不是作弊跑局"

| 手段 | 实现 |
|---|---|
| 真实按键 | `kd/ku` = `window.dispatchEvent(new KeyboardEvent('keydown'|'keyup', {code}))`；走 `Input` 的 `keys` + `dirEdge`（D-12 边沿语义），**不直接改 `Player.x/y`** |
| 一步一格 | 移动 = 按一次方向键 + 推进一帧；走格节流 `MOVE_INTERVAL=120ms` 由主循环自己管，bot 只按 120ms 节奏重按 |
| 回合节奏 | 战斗 = 按 `Digit1`（平砍）/ `Digit6`（护盾）；等 `Battle.isInputLocked()` 解除再按下一手，不绕过 `lock=150ms` |
| 桩：位移必须在主循环内 | 包 `Motion.setStep`，`who==='player'` 时计数；`inUpdate`（由 `_updateExplore/_updateBattle` 的包装维护）为假时记 `movesOutside` |
| 桩：出招必须在 `_updateBattle` 内 | 包 `Battle.playerAction`，同上记 `pa / paOutside` |
| **负例：不发按键就一格都不许动** | `Bot.tickFrames(180)` 空转 180 帧：位移 0、出招 0、位置不变（`B1_noInputNoAction`） |
| 时钟 | `performance.now` 整体替换为虚拟时钟（`vNow`），死亡消散 700ms 等"墙钟计时"也变成可复现量 |
| 随机 | `Math.random = mulberry32(seed)`，地图/怪物/陷阱分布全部由种子决定 |

**唯一"不算真人"的地方**：`Render.draw*` 被替换为空函数（纯提速，不参与逻辑），以及 bot 的寻路 BFS 直接读 `Map.getGrid()`（见 §八 缺口 1）。

## 四、策略（可解释、无随机）

按优先级：

1. **有模态框开着** → `Esc` 关闭（真人也会先关面板）。
2. **`hp ≤ 45%` 且背包有回血药** → `B` 开背包 → 选第一瓶回血药 → `Enter`（走背包 UI，不调 `Inventory.use`）。
3. **有更优武器/护甲**（`effect.atk/def` 更高）→ 背包里装备。
4. **优先探索未探索格**（BFS 取最近未探索格）。
5. **探索完本层** → 优先下楼（BFS 取最近 `tile===2`）。
6. **`hp < 60%` 时绕开怪物格**（"遇强敌先回血"的可执行退化版）；被怪贴脸则由 AI 触发战斗。
7. 战斗：平砍；`hp ≤ 25% && mp ≥ 10` 且本场未套盾 → 先套盾。

楼梯规则（踩了会真换层的楼梯**不当通路**，只当目标）：`tile 3` 仅在 `floor===1` 时可走、`tile 2` 仅在 `floor===5` 时可走——因为 `changeFloor` 越界返回 `null`，这两处踩上去等于普通地板。

## 五、50 局实测（种子 1001–1050，单局上限 2500 步）

### 5.1 结论面

| 指标 | 值 |
|---|---|
| 通关率 | **0 / 50 = 0%** |
| 死亡 | 46 / 50（92%） |
| 卡关（非死亡、走满上限） | 4 / 50（8%） |
| 死在第几层 | 第 2 层 30、第 3 层 9、第 4 层 7（第 1 层 0、第 5 层 0） |
| 死因 | 被怪打死 46 / 46（陷阱致死 0）；其中 34 局死亡时背包里**没有一瓶回血药** |
| 结局等级 | Lv1 30 局、Lv2 20 局（从未到 Lv3） |

### 5.2 时长

| 指标 | 值 |
|---|---|
| 单局步数 | 均值 632.8 步 |
| 模拟时长（120ms/步） | 均值 **75.94s**、中位 **55.56s**、最短 28.68s、最长 300s（卡关局走满 2500 步） |
| 实测墙钟 | 193ms/局（50 局 9.7s，渲染空转 + 虚拟时钟） |

**规模建议**：按 193ms/局，1000 局约 3.2 分钟、5000 局约 16 分钟，本机可承受；瓶颈不是墙钟而是"卡关局会走满 2500 步"，若把上限提到 6000，均值会明显上升。**本卡按卡面要求跑满 50 局，未缩规模。**

### 5.3 曲线（每层结束时均值）

| 层 | 到达局数 | 停留回合 | 金币 | 装备等级 | 血量 |
|---|---|---|---|---|---|
| 1 | 50（100%） | 125.98 | 30.04 | 0.90 | 58.64 |
| 2 | 50（100%） | 163.80 | 59.62 | 1.08 | 31.74 |
| 3 | 18（36%） | 313.50 | 118.17 | 2.00 | 17.67 |
| 4 | 7（14%） | 56.86 | 134.57 | 1.71 | 0 |

- 金币曲线单调（30 → 60 → 118 → 135），但**第 3 层停留回合翻倍、血量掉到 17.67**，是明显的断崖。
- 第 4 层 `avgHp=0` 是因为 7 局全部死在该层（结局层记录的是死亡瞬间血量）；装备 1.71 低于第 3 层的 2.00，是幸存者偏差（活到第 4 层的样本更穷）。
- 装备等级 = 身上装备的 `atk/def` 之和（不是件数）；单局平均换装 0.42 次、喝药 0.88 次、踩陷阱 4.3 次、击杀 4.48 只。

### 5.4 「击杀 5 只哥布林」与 0.12%

| 项 | 值 |
|---|---|
| 完成局数 | **0 / 50（0%）** |
| 累计哥布林击杀 | 31 只（均值 0.62 只/局） |
| 单局哥布林击杀分布 | 0 只 ×26、1 只 ×18、2 只 ×5、3 只 ×1（**最多 3 只**） |
| 对照声称值 | 0.12%（`claimedRate`） |

**如实报告：我的实测是 0/50，与 0.12% 不矛盾，但也证不出它。**
- 50 局的期望完成数是 0.06 次，观察到 0 完全正常；按"三倍法则"我只能给上界 ≤6%（3/50）。
- 机制证据比这个上界更有信息量：**单局哥布林击杀最多 3 只**，62% 的局 ≤1 只。要凑够 5 只，bot 必须活得更久、且恰好反复遇到哥布林（哥布林集中在低层，而 92% 的局死在第 2~4 层）。
- 因此 0.12% 这个数字**在本 bot 的生存画像下无法检验**：它若是真人数据，人口不同（真人会买药、会逃跑、会刷级）；它若是纯概率估算，我的分布说明"单局 5 只"需要长尾，量级上并不离谱。**我不迁就它，也不否定它，只交自己的数。**

## 六、卡关点

### 6.1 4/50 局的"必卡层"（真人也过不去）

- 现象：`outcome=stuck`，走满 2500 步仍在同一层，`noDir` 刷满。
- 诊断（`stuckReason`）：**上行梯封住唯一走廊**，4 局全部命中；`stuckSpawnInPocket=true`。
- 机理：`js/systems/map.js` 的 `placeStairs()` 在**每一层**都同时放上行梯（tile 3）和下行梯（tile 2）；`findOpen()` 只要求"是地板且离出生点够远"，不检查它是否落在**唯一通路上**。一旦上行梯卡在宽度 1 的走廊里，踩上去就 `changeFloor`，而 `main.js` 的 `resetPlayer()` 是把玩家**传送到目标层出生点**（不是门口）——于是被它隔开的区域（含本层下行梯）永远走不到，走下去也只会回到同侧的出生点。
- 这不是 bot 的策略缺陷：`stuckSpawnInPocket=true` 表示出生点本身就在被封住的那一侧，真人换层传送后仍回到原地。**只记录，未修**（本卡不改 `js/`）。
- 触发率：4/50 局 = 8%；按层看是第 2 层 2 局（种子 1014、1036）、第 3 层 2 局（1028、1041）。

### 6.2 不是"必死"，是"耗死"（第 2 层）

30/46 的死亡发生在第 2 层。第 2 层到达率 100%、平均 163.8 步，`avgHp` 从 58.64 掉到 31.74；匹配"第 2 层怪强度上台阶、而 bot 在第 1 层只攒到 30 金币、药 0.88 瓶"。这属于**难度曲线问题而非机制死锁**，本卡只记录数值，不判"是否合理"。

## 七、顺带记录的两个既有缺陷（只记录，不修）

1. **`js/systems/ai.js:126` A* 首节点坐标转置导致越界**
   - `nextStep()` 用 `new window.Graph(data)` 建图，bgraph 的 `Graph` 把输入当 `[x][y]`，而这里喂的是 `[y][x]`；`astar.search` 返回的 `path[0].x/.y` 因此是转置坐标，回到 `grid[next.y][next.x]` 即越界。
   - 实测：50 局共 **230 帧**抛 `Cannot read properties of undefined (reading '1')`（`grid=19x29 player=27,4 floor=3`）。
   - 影响面：`tick()` 里这一步在 `try/catch` 之外，异常会把**同一帧剩余的巡逻怪**跳过；`nextStep` 自己的 `try` 只包住 A*。所以怪物会间歇性"卡住不动"，玩家因此少挨几次追击。本 bot 的 try/catch 只统计次数，不改变任何游戏状态。
2. **`placeStairs()` 在第 1 层也放上行梯**：`changeFloor(-1)` 返回 `null`，踩上去等于普通地板（bot 的策略已按此处理）。不是 bug，但和"第 1 层没有上行梯"的直觉不符，容易让玩家以为踩空。

## 八、缺口

### 8.1 bot 与真人的差距（它不会做的判断）

1. **全图寻路 = 全知**：BFS 直接读 `Map.getGrid()` 与楼梯坐标，知道未探索区域在哪、楼梯在哪。真人只有 `FOV` 视野与已探索记忆，会走冤枉路、会靠猜。**这使得"停留回合数"偏乐观**。
2. **不进商店**：`E` 商店从未打开，不买药、不补货、不卖装备。34/46 的"死亡时无药"有相当部分源于此——真人会在下楼前把 30 金币换成药。
3. **不逃跑**：D-15 的"后退一格 + 6 tick 喘息"从未使用；打不过就硬打到死。
4. **只会平砍 + 低血套盾**：不用火球/冲刺（不评估 MP 收益）、不算 CD、不换目标。
5. **不主动刷级**：只在 `hp<60%` 时绕怪，没有"先去打小怪升级再进下一层"的行为；`遇强敌先升级` 在实现上退化为"绕开"。
6. **不接任务/不对话**：`T` NPC、`M` 任务面板从未打开；任务完成情况读的是系统状态，不是"玩家去交了任务"。
7. **不会等**：真实玩家会停下来观察巡逻路线、卡视野；bot 每 120ms 必做一个动作，遇怪节奏比真人密。
8. **不会用宝箱做决策**：宝箱是踩上去自动拾取（`main.js:509`），bot 只是"顺路踩到"，不专门去吃。

### 8.2 这些指标不能证明什么

1. **不能证明"手感/观感"**：120ms 一步、回合 180ms 的体感、战斗特效应不应该留，bot 一律无感。
2. **不能证明真人通关率**：bot 0/50 是"这个策略 + 这套规则"的通过率，不是人的通过率。策略换一条（例如先买药）结果会明显不同。
3. **不能证明"难度不合理"**：卡面明确不设阈值。0% 通关只是"当前 bot 过不去"，反向也不成立——把 bot 调强到 100% 也不代表游戏太简单。
4. **不能证明数值平衡**：bot 的装备/金币曲线是"这个策略下的最优踩点"，真人会更差。
5. **不能定位"哪一只怪太强"**：只记死因大类，没有逐怪 DPS 归因；`lastMonster` 只记录最后一次遭遇的怪，死亡那一击未必是它。
6. **不能替代真机**：`performance.now` 被虚拟化、`Render` 空转，所有时长都是"逻辑时长"，不是真实帧率下的表现。
