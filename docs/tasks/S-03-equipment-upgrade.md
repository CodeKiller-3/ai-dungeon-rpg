# S-03 装备强化（+1~+5）

## 目标

给「成长」环补一条可感知路径：装备不再一落地数值就定型，玩家可以把金币投进已装备的物品，每级 +10% 基础攻击/防御（向上取整），上限 +5。数值全部经 `Inventory.recalcEquip()` 汇总，战斗、HUD、存档自动继承。

| 文件 | 改动 |

- `SHOP_STOCK` / `SHOP_ROTATION` 五行内容不改（核心货架均价 40.7/92.2/236.7/259.4/441.9 是既有验收口径）。

## 已知取舍与风险

1. **卷轴目标规则是确定性的，不是玩家自选**：升「当前装备中等级较低者」。理由：不改弹窗交互（背包/商店两套 UI 都要重做选择器），且两件装备会交替成长，不会出现"只强武器、护甲永远 0"。代价：想专升某一件时，需要先卸下另一件。
2. **商店只卖 1 张/层，掉落侧未接**：规划写的"每层 1~2 张（宝箱/怪掉）"中的掉落分支落在 `map.js` / `monsters.js`，不在本卡改动面内，故本卡只做商店货位。供给量因此偏少（5 层共 5 张 + 已存档余量），但保证「能买到、能感知」，不构成经济通胀。
3. **强化不失败、不降级**：本卡口径为「只成功不失败」，与"攒资源变强"一致；失败毁装会让 80 金币的卷轴变成赌博，与 v1 的确定性数值风格冲突。
4. **旧档兼容**：`upg` 只加不删；读档时缺失补 `{}`，且 `recalcEquip()` 在 `upg` 赋值之后调用，旧档不会出现"有装备无强化"的错值。
5. **`upgrade()` 内部 99 哨兵**：未装备一侧记为 99，用于"只装一件"时正确选中已装备那件；两件均 +5 时会返回"已全部强化至 +5"。
