# D-19 战斗内用药

基线 `d424edd`（回归 60/60、静态 32 PASS / 1 WARN / 0 FAIL）。D-18 的数据里有一条硬事实：**16/50 局死亡时背包里还有回血药，但用不出去**——`_updateBattle` 没有用药指令。本卡补这个动作，不动任何数值。

## 一、结论面

| 指标 | D-18 | D-19 |
|---|---|---|
| 通关 | 0/50 | 0/50 |
| 卡死 / A\* 异常帧 | 0 / 0 | 0 / 0 |
| 死亡时背包无药 | 34/50 | **50/50**（带药死亡 16 → **0**） |
| 战斗内用药次数 | ——（不可用） | **45 次 / 34 局**（0 次 16 局、1 次 23 局、2 次 11 局） |
| 战斗外用药次数 | 77 | 36（共 81 ≈ 与 D-18 的 77 同量级） |
| 死层 | F2 32 / F3 14 / F4 1 | F2 35 / F3 14 / F4 1（F3 到达 18 → 15） |
| 平均步数 / 逻辑时长 | 512.94 / 61.55s | 502.06 / 60.25s（中位 56.40s） |
| F2 结束时血量 | 30.80 | **25.44** |
| 商店购买 / 花费 | 26 件 / 1950 | 24 件 / 1630 |

**结论**：功能正确落地，但**生存没有变好，反而略差**（F2 死亡 32→35）。这不是实现错误，是"用药占一个回合"的必然代价：喝药那一手怪物照常反击，净收益 = 回复量 − 这一击；而同样一瓶药在战斗外喝是零代价。bot 在 `hp≤45%` 时就喝，常常"喝一口—挨一下—再喝一口"，把两瓶药的收益吃掉大半。**这条改动把"带药暴毙"的荒谬消掉了，但它不是难度杠杆。**

## 三、按键为什么不是 4

卡面写"4 键在战斗内空闲，优先用它"。**实际不是**：M8-1 把 `4/5/6` 绑定为火球/冲刺/护盾，`verify_m8_1` 的 t9 专门断言了这三条命令。按卡面改 4 会直接废掉火球，属回归。

因此取同一命名序列的下一个空闲数字键 **`7`**（`Digit7` + `Numpad7`），并在 `verify_d19` 用 `A2_key4StillCastsSkill` 把"4 仍然是火球"钉死（MP 50→38、怪物掉血、药剂未被消耗）。这是本卡唯一对卡面的偏离，属规格变更，已在此说明。

## 四、边界判定（卡面要求自行决定的部分）

### 4.1 哪些能用

判定只读 `items.js` 既有字段，不新造分类：

```
type === 'consumable' && scroll !== true && (effect.hp > 0 || effect.mp > 0)
```

- **治疗药、魔法药都能用**：两者都是"花一个回合换资源"，与战斗语义一致。
- **卷轴不能用**：`scroll:true` 的物品走 `Inventory.use` 的强化分支（S-03），作用对象是**装备**、不是当前战斗状态；战斗内允许它等于把养成动作塞进回合里，且会绕开"战斗中不能打开背包"的既有边界。
- **装备不能用**：`type !== 'consumable'`，本来就没有"使用"语义。

### 4.2 多瓶同类怎么选

先补 HP，HP 满了才补 MP；同类里：

1. **够补满缺口且回复量最小**的那瓶（缺口 20 就喝 30，不拿 150 的药补）；
2. **没有一瓶够补满 → 用回复量最大的**（先活下来，而不是连喝三瓶小药）。

`verify_d19` 的 `F1_pickSmallestSufficient` 用两组数把这条钉住（缺口 20 → 小瓶、缺口 90 → 大瓶）。

### 4.3 单场次数上限

**不设上限**。每次用药占一个完整回合并触发怪物反击，代价已经内建；再加上限会让"药多但血少"的局变得不可解释。

## 五、时间轴兼容（D-16）

- 用药走与 `attack/defend` 完全相同的 `turnRec` + `scheduleMonster(t0)`：`seg1=100ms` 玩家段、`seg2=80ms` 怪物段、`total=180ms`、`lock=150ms`。**没有第二套 pending、没有第二个 timer。**
- 唯一的加固：`monsterTurn` 开头补一条 `monster-attack` 事件。原来只有 `monster-hit`（真实掉血才记），遇到"护盾吃满/0 伤害"就证明不了"怪物反击发生过"。这条只是观测，不改数值与顺序。
- 拒绝路径（满血/没药/卷轴）**在回合起拍之前**返回：不推进 `roundNo`、不上锁、不消耗、不排怪物段——按错键不该算一次行动。

## 九、缺口

### 9.1 这条改动对平衡的实际影响

- 45 次战斗中用药，覆盖 34/50 局；F2 死亡 32→35、F3 到达 18→15、F2 结束血量 30.80→25.44。**净影响为轻微负向**。
- 机制解释：用药的那一手怪物照常反击（`C1` 证明），所以一次用药的真实收益是"回复量 − 怪物一击"。bot 用 30 的小药在 45% 血线喝，经常净赚 10~20 HP；两瓶连喝则被两次反击吃掉一半。战斗外喝药没有这个代价，所以"把药留到战斗外用"在这个 bot 身上反而更优。
- **这不构成"应该给战斗用药加数值补偿"的理由**：本卡不动数值；若后续要让内用药有意义，方向是"药水回复量 vs 怪物单回合伤害"的比例，而不是给用药免费。

### 9.2 "真人用药时机"为什么仍然测不到

1. **bot 的阈值是固定 45%**，真人会看"这一击会不会打死我""怪还剩多少血""这瓶药值不值得现在喝"；这些判断没有进入 bot。
2. 战斗内用药的收益高度依赖**怪物这一手的伤害**（是否狂暴、是否吐息、是否被盾吃）。bot 不做"下一击伤害"的预判，只能事后反应。
3. **不会用蓝瓶换技能窗口**：bot 只在 HP 满、MP 不满时才可能喝蓝，而真人会"先喝蓝再连放火球"。
4. 不会评估"这瓶药留给 Boss 更好"——bot 没有跨场资源规划。
5. 因此"45 次内用药"只能说明**动作可用、路径正确**，不能说明真人在同样局面会喝、也不能说明这个机制改善了通关率。

### 9.3 其它

- 第 4 层仅 1 局到达，样本不足以说明 F4 的任何变化。
- 用药的 `+HP` 视觉反馈最初用 `Feedback.spawn`，实测坐标落在战斗 HUD 上（`playerPos()` 返回的是探索坐标），已移除，只保留提示条与战报。战斗内"回复飘字"仍缺。
