# C-02 商店刷新相位与轮换池

- 卡片编号：C-02
- 定位：机制完整性修复（不是功能扩展）——现状"确定性但可背"：轮换池每层 3 项、每次开张滑 1 位、第 4 次开张回到起点；`restart()` 又不重置 `tick`，新局第一眼货架会延续上一局相位。
- 目标：确定但不可背，同时完全可复现（无 `Math.random`）。

## 一、玩家/读者可见行为

1. 新局（首局启动、死亡重开、通关后重开三条路径）第一次打开商店，货架一定是首相位，不再延续上一局的开张次数。
2. 同层连续开张不再 3 次一循环：每层轮换池扩到 5 项，周期变成 5 次开张，且不会背出固定三步序列。
3. 展示条数完全不变：核心货架 7/9/9/8/8，合计 10/12/12/11/11（核心 + 2 轮换位 + 1 卷轴），面板 12 行上限不溢出。
4. F4/F5 轮换池不再出现低价消耗品（原 F5 的 `potion_large` 已移出），改为与同层核心装备同档位的候选，逐层更强的观感不掉。
5. 买价仍严格高于卖价，刷新货架依旧无法刷金。

## 四、断言表

| 编号 | 断言 | 判定 |
|---|---|---|
| C2-1 | `resetOnRestart`：F1 连开 3 次改变相位后 `restart()`，首次开张回到首相位；同一 `restart()` 连做两次结果一致 | 验证页 |
| C2-2 | `noDoubleAdvance`：`restart()` 只归零不推进；归零后首次 `Modal.open('shop')` 恰好推进 1 位 | 验证页 |
| C2-3 | `poolSize`：各层池长 ≥4；池内每项在 `ITEMS` 存在、行内无重复、`price > sell` | 验证页 |
| C2-4 | `cycleLen`：同层连续开张序列周期 = 池长（不再是 3），相邻两次至少变化 1 个轮换位 | 验证页 |
| C2-5 | `countsUnchanged`：核心条数 7/9/9/8/8，合计 10/12/12/11/11 且 ≤ `MAX_VISIBLE`(12) | 验证页 |
| C2-6 | `stableWithinOpen`：同层同一次开张多次取货架一致；换层归零后回访可复现 | 验证页 |
| C2-7 | `noArbitrage`：全物品 `price > sell`；`plate_armor_epic` 实买实卖 −800/+400 | 验证页 |
| C2-8 | `tierCoherence`：F4/F5 轮换池每项为装备类且 `price ≥` 该层核心装备最低价 | 验证页 |

C2-8 判定口径：取该层 `SHOP_STOCK` 中 `type !== 'consumable'` 条目的最低 `price` 作为「该层核心最低档」；F4 = 240（`chain_mail_rare`），F5 = 300（`sword_dragon_rare`）。轮换池每项必须是 `weapon`/`armor` 且价格不低于该值——用价格区间判定档位，避免再引入一套品质枚举。

## 六、取舍与已知缺口

1. 轮换池从 3 扩到 5，周期从 3 变 5，但"可背"只是从 3 步拉长到 5 步，仍可被硬记；彻底不可背需要更大的池或二阶混合，本卡按规划端口径只做必要扩容。
2. F1~F3 轮换池仍保留 1 个低价消耗品（`potion_mana`）用于补给多样性，仅 F4/F5 强制装备档位；若后续认为 F3 也不该出现，可另开卡。
3. `resetPhase()` 只服务"新局"语义；换层归零继续由 `syncFloor` 负责，两者重叠时以"不重复推进 tick"为准（`resetPhase` 不含 `tick++`）。
4. 本卡不改 `verify_s01_shop` / `verify_p2_2` 的既有断言；它们按原口径继续跑，只作为"展示条数未变"的交叉证据。
