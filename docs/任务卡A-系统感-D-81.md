## 0 目标与非目标

**目标**
- 把“系统”变成世界观的一部分：它只对宿主说话，只报真实数据，只在真实节点出现。
- 让“救援/死亡”从“守夜人帮忙”变成“系统协议介入”，机制和数值完全不变。
- 给 M 面板加第 4 页「系统」：一个只读聚合层，显示本局成长、救援记录、精英武器、图鉴、环境。

**非目标**
- 不做新的成长系统、第二货币、战力值、胜率、系统等级、天赋树。
- 不做同伴/队伍/召唤物。
- 不改商店、NPC 任务、精英掉落、Boss、普通怪。
- 不为了“系统感”加感叹号、加“强化”裸词、加未实现功能词（D-20 C2/D1/E1）。

## 3 独立系统面板：要不要做

### 3.1 推荐：不做独立入口，M 第 4 页就是面板

- 理由：M 已经是“任务/怪物/物品”的档案层，第 4 页「系统」是它的自然延伸；不新增按键、不新增 HELP、不新增 modal kind，验证面最小。
- 玩家路径：`M` → `Tab` ×3 → 「系统」。一次学会，之后不需要记新键。
- 这满足“系统是世界观的一部分”：它不是外挂窗口，而是地牢档案的一部分。

### 3.2 如果一定要独立入口：用暂停菜单，不要用 V

**推荐备选：暂停菜单**
- `Esc` 打开暂停 → 新增一项“系统面板” → `Enter` 打开 `Modal.open('quests')` 后 `Modal._setPage(3)` → `Esc` 关闭回游戏。
- 键位：仍然是 `Esc`/`↑↓`/`Enter`，不新增 `Render.KEYMAP.explore` 条目；不改 HELP。
- 代价：暂停菜单多一项，`verify_d51` 只测“暂停真停/能回”，不测菜单项数；但需要人工走查 320 窄屏的 5 项菜单高度。
- 这是“独立入口”里成本最低的方案。

**不推荐：V 键**
- `KeyV` 目前未被占用（全 `js/` 无 `KeyV`），但 D-20 A1 会做“代码按键 ↔ HTML 键位表”的双向审计：新增 KeyV 后，必须同时改 `Render.KEYMAP.explore`、`index.html` 的按键表、回放行为，否则 A1 的 `extra` 会失败。
- 这不是“放宽断言”，是**口径失效**：D-20 的审计规则仍然成立，只是要新增一条被审计的键。执行端必须同步改验证页，不能把 A1 删掉。
- 如果再加 HELP 条目，`verify_d48` D 组的 `HELP.length === 8` 也会失效，需要同步改 id 列表。
- 结论：V 键的收益（少按一次 Tab）小于验证面成本，不做。

### 3.3 独立面板开/关/显示

- 开：暂停菜单选中“系统面板” → `Enter`。
- 关：`Esc` 关闭 modal，回到 explore（不是回暂停）；与现有 modal 的关闭语义一致。
- 显示：与 M 第 4 页完全相同的行；不复制一套数据逻辑，直接调用 `buildSystemRows()`。
- 如果做这个入口，验收加一条：打开/关闭后 `Player` 深比较不变、`Math.random` 计数不变、存档不写。
