# D-32 目录归位决定（阶段 B1 做，B2 永久不做）

- 日期：2026-11-12
- 基线：`7f3c6a2`（D-31 后回归 73/73）
- 结论：**只做 B1（搬过程产物）；B2（搬 `js/`、`preflight/verify_*.html`）永久不做。**

## 一、B1 做了什么

| 原位置 | 现位置 | 处理 |
|---|---|---|
| 根目录 4 份过程报告（自检 / 修复 / 诊断 / 对标自检） | `docs/process/` | 每份前置一行「来源说明」，**正文逐字节保留** |
| `preflight/` 根下的 `shots_resize/`（12 张 PNG） | `preflight/artifacts/shots_resize/` | 整体搬迁，文件名 / 字节数 / 哈希均不变 |

搬家前的哈希与字节数落在 `preflight/selfcheck/d32-before.json`，搬家台账落在 `preflight/selfcheck/d32-move-manifest.json`；`preflight/verify_d32.html` 用同一套哈希逐份复核「内容未变」。

## 二、哪些**没有**搬，为什么

| 文件 | 留在根目录的理由 |
|---|---|
| `PLAN.md` / `README.md` / `CHANGELOG.md` / `THIRD-PARTY-NOTICES.md` | 发布面文档，是陌生人进仓库的第一入口，也是 `verify_d31.html` 的断言输入 |
| `规划-对标补齐.md` | **被 5 个验证页用 `readDoc('../规划-对标补齐.md')` 读取**：`verify_d07`、`verify_c03b`、`verify_c04`、`verify_c05`、`verify_d02`。搬走即 5 页同时红 |
| 全部 `preflight/verify_*.html` | `run-all.ps1` 在 `preflight/` 上做**非递归** glob（`Get-ChildItem -Filter 'verify_*.html'`），并把 `page-baseline.json` 当页数期望值。页面一旦挪进子目录，批跑立刻 `TOTAL=0` → `GUARD_EMPTY_SET` → 退出码 2。这是 D-22 建的防假绿底线，搬它就是拆防线 |

结论：**凡是被断言读取的「过程报告」一律不搬**。B1 的候选里没有一份被断言读取，所以 4 份报告全部可搬；`规划-对标补齐.md` 虽然长得也像过程文档，但它是断言输入，原地不动。

## 三、B2 为什么永久不做

D-31 实测（不是估算）：

1. **验证页侧**：73 个验证页里 **67 个**用 `../js/...` 引用脚本，合计 **1375 处**。把 `js/` 挪进子目录，等于逐页改 1375 处相对路径，且每改一处都可能写错一个字符——而验证页本身是「判据」，判据改错不会报错，只会静默变绿。
2. **工具侧**：硬编码 `preflight/` 路径的工具 **≥11 个**：`run-all.ps1`（17 处）、`selfcheck.js`（3）、`d21_audit.js`（3）、`d21_fix.js`（3），以及 `verify_d22` / `verify_d26` / `verify_d31` / `verify_d15b` / `verify_c05`、`d13_harness`、`perf_d12`。
3. **文档侧**：66 份文档引用 `preflight/` 路径。
4. **风险排序**：B2 要先动 `run-all.ps1` 的扫描方式与页数基线——也就是动防线本身；收益只有「目录看起来更整齐」，不改任何玩法、数值、可玩性。

**收益 / 风险比不成立，故永久不做。** 若将来真需要，必须先建「页面清单 + 路径单一来源」的机制，让路径只写在一处，而不是 1375 处。

## 四、复现

```
powershell -ExecutionPolicy Bypass -File preflight/selfcheck/run-all.ps1 -Budget 3500
node preflight/selfcheck/selfcheck.js
```

两命令在归位前后都必须 `FAIL=0`、`GUARD=OK`——归位是纯路径操作，任何一页读不到文件都会在这里红，这正是本卡最关键的回归点。
