## 一、结论

**项目可以正常运行。** headless Edge 实跑 `index.html`：进程退出码 0、无 JS 报错（`JS_ERRORS=0`），仅有 3 条 AudioContext autoplay 警告（浏览器策略，属预期）。21 个验证页最终 **21/21 PASS**。

**最严重问题（已修复）：启动时用默认新档覆盖磁盘旧档。**
`Main.init` 中 `Map.generate()` 先触发 `map:floorChanged` → `Save.save()`，把默认新档写盘，随后 `Save.load()` 读回的仍是这份新档，导致"读档永远读不到进度"。

**本轮试玩新 bug（已修复）：按 S 出现商店。**
不是地图生成了商店实体，而是 `S` 同时被绑定为"商店"热键且排在移动之前，按下即弹出商店面板并吞掉向下移动。全仓库 `map.js` 无任何 shop 相关代码，商店是模态 UI + 静态货架数据，不存在"地图刷商店"的生成函数。

**修复数量：应用问题 5 处 + 测试夹具 1 处。**

## 二、S 键"生成商店"问题（本轮新增）

### 2.1 定位与原因

| 环节 | 位置 | 结论 |
| --- | --- | --- |
| 按键绑定 | `js/core/input.js:37` | `KeyS` 是 WASD 的"向下移动" |
| 探索输入分发 | `js/core/main.js:279-288`（修复前为 `KeyS` 分支） | 动作键判断在移动之前并 `return`，`KeyS` → `Modal.open('shop')`，因此按 S 只弹商店、不移动 |
| 商店实体生成 | `js/systems/map.js`（全文） | **无 `shop` 相关代码**（grep 0 命中），`generate()` 只做迷宫、楼梯、怪物、巡逻、细节/装饰 |
| 商店 UI | `js/systems/modal.js`（`kind='shop'`） | 商店是弹窗，货架来自 `js/systems/shop.js` 的静态 `SHOP_STOCK` |

结论：属于**键位冲突**，不是事件监听未阻止默认行为，也不是生成逻辑挂错；用户观感是"凭空出现一个商店"，实际是弹窗面板。

### 2.2 诊断页复现（旧版 vs 修复版）

同一诊断页先加载 HEAD 旧版 `main.js`，再加载修复版，模拟连续按 S 三次并对比地图/实体状态：


要点：

- 旧版按 3 次 S → 弹商店 3 次、向下移动 0 格；怪物 5→5、装饰 13→13、货架 2→2、地图引用未变（`gridSame:true`），**不会随按键次数累积商店实体**；

- 修复版按 E 正常打开商店（`stock:2`），购买成功（扣 10 金币、背包 +1、图鉴登记 +1），并正确写档（`gold:9989, inv:1`）。

### 2.3 改动位置

- `js/core/main.js:280-282`：商店热键 `KeyS` → `KeyE`，S 保留给向下移动：

```js
if (k['KeyB']) { delete k['KeyB']; Game.Modal.open('inventory'); return; }
/* 修复：S 是 WASD 的"向下移动"，不能再同时作为商店热键（否则按 S 会弹出商店面板）。
 * 商店改用 E 打开；S 保留给移动，其余按键语义不变。 */
if (k['KeyE']) { delete k['KeyE']; Game.Modal.open('shop'); return; }
if (k['KeyM']) { delete k['KeyM']; Game.Modal.open('quests'); return; }
```

- 同步文案：`js/core/render.js`（引导层与旧版面板）、`js/data/dialogue.js`（NPC 台词）、`README.md` 操作表；
- 弹窗内 `↑↓/KeyS` 选择下一项的语义保留（`js/systems/modal.js:154`），商店交互与存档逻辑未改。
