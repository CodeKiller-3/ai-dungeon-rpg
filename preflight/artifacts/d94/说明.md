## 9. P2 五层横置背景重排 + 实体基线修复（2026-11-16，HEAD=b1e0a99 之上）

### 9.1 为什么不是「平移旧背景」

纵置五景都以 `CX` 为轴：石厅拱门、王座+台阶、墓穴棺台、营地帐篷都正对敌人。横置的中心是
两个人的决斗空场，原地标会正好落在 201–291 与 706–850 两个精灵包围盒之间——既挡 P5 特效，
又把画面读成「一张背景前面站了两个人」。所以是**重排**，不是平移：

| 规则 | 落法 |
| --- | --- |
| 中央不留单点物件 | 五层都没有居中门/王座/篝火/拱门；中央只留空走道（F5 地毯）、远端暗（F1/F2 径向暗、F3 深缝）、或两侧对称构件（F1 双拱） |
| 左右各有重量、不镜像 | F1 左窄拱/右宽拱；F2 左帐篷+篝火/右木栅+木箱；F3 左岩柱/右塌拱+两侧熔岩；F4 左双细柱/右粗柱+倾斜棺盖；F5 左拱+垂旗/右王座+台座 |
| 光源在两侧 | 火把 0.09W/0.91W、篝火 0.075W、熔岩缝 0–0.14W 与 0.86–1W、烛台 0.065W/0.945W、火盆 0.075W/0.885W |
| 实体基线 | 四人（玩家/杂兵/Boss/龙）脚底一律 `round(0.766H)`；接触阴影改 `hContactShadow`（贴地扁椭圆，rx ≤ 46） |

`backWallY` 按比例（1024×640 实数）：F1 0.656→420、F2 0.641→410、F3 0.625→400、
F4 0.672→430、F5 0.648→415；960×540 得 354/346/338/363/350。地平线**保持 0.766H**
（960×540=414、1024×640=490），未改成两档同值。

### 12.5 第 2 轮两个红页取证：预存在抖动，不属本卡改动

两页都在单页复跑中大量通过（d89 9/10、d90 11/12），失败样本与通过样本的完整 DOM 都留了取证：
`probe-verify_d89-1.txt`（FAIL）/ `probe-verify_d89-2.txt`（PASS）、
`probe-verify_d90-8.txt`（FAIL）/ `probe-verify_d90-1.txt`（PASS），复跑器 `probe_page.ps1`。
根因都在**验证页自身的时钟/随机地图口径**：

- **`verify_d89` E1_bodyDisplacement**：页面用 `B._setClock` + `Fx._setClock` 把战斗时钟冻在 T，
  但纵置绘制里 `_attackOffset(state.playerActionAt, 320, -1)` 取的是 `performance.now()`
  （[render.js L2415-L2422](file:///d:/桌面/工作/人工智能大作业/js/core/render.js#L2415-L2422)）。
  当页面 boot 发生在导航后 <320ms 时，`performance.now() − 0` 落进前摇窗口，
  玩家多出一段 "+5px 后拉"，实测 off = **12/12/12/11/9/6/5**（应 7/7/7/5–7/2–5/0–2/0）。
  该函数在 P0 基线 `b1e0a99` 里就是 `performance.now()`；P5 只加了可选第 4 参且纵置不传
  （`git show b1e0a99:js/core/render.js`），故**不是 P2–P5 引入**。
- **`verify_d90` C_targetBrackets**：判据要求"楼梯 2–4 格内 16 个候选格至少一处既可行走又看得见楼梯"。
  地图是程序化随机生成，偶发没有这样的格 → `n:0`（`stair:{13,12}, exploredN:53`）。
  本卡未动地图/视野/目标框。

结论：两页的偶发红是**测试装置自身的非确定性**，按"不删页、不放宽阈值"的口径原样保留；
建议另开一张卡修测试装置的时钟注入与地图种子，不并入本卡。
