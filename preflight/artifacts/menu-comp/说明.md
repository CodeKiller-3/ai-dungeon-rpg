## 0. 公共口径

- 画布就是视口：1024×640 与 500×700 各自按逻辑像素 1:1 绘制，**窄屏不是宽屏缩放截图**。
- 只用 `assets/sprites/` 现有 PNG；所有精灵按整数倍绘制，`imageSmoothingEnabled=false`。
- 光、门板、台阶、压条为 Canvas 纯绘制（径向渐变/矩形），不是新图片；不新增数值、不碰 `sysviz.js` 与 HUD 读数带，不改 `main.js` 菜单分支、不新增按键、不改存档。
- 菜单统一画五项（开始新游戏 / 继续游戏 / 玩法说明 / 设置 / 关于），取「无档」态：默认高亮「开始新游戏」，「继续游戏」置灰并标「暂无存档」。
- 进度条统一文案 `Lv.1 → 第 5 层`；第五格用 1× 龙（或 1× 独眼酋长）作为终点符号。
- 骑士统一 `knight_m_idle_anim_f0` 原生 24×42，**2× = 48×84**，落屏脚底对齐地面线。
- 三稿标题都用系统中文黑体（`Microsoft YaHei` 回退），没有新建位图字；若接入要换成像素字，那是另一套字体资源，不计入 sprite 素材。

复现：浏览器直接打开
`preflight/_menu_comp.html?c=A&w=1024&h=640`（B/C 同理；窄屏 `w=500&h=700`），
用 1024×640 或 500×700 的视口、DSF=1 截屏即可。

## 我的推荐：A，并借 B 的一线光

理由按优先级：

1. **首屏首先是决策页。** A 的右侧暗栏在 1024 与 500 两个尺寸都能把五项菜单和 `Lv.1 → 第 5 层` 放在固定位置，文字对比度不依赖地板亮度；B 的菜单压在亮地面上，窄屏还会盖住门洞下半；C 的菜单面板则把唯一的光缝挡掉。
2. **A 的信息结构最完整。** 门、暗井、台阶、骑士、火把在同一张图里形成「入口 → 向下 → 我在门口」的因果，玩家不需要读文案就知道该按「开始新游戏」；B 读得到「有光」，但读不到「往下」；C 读得到气氛，读不到「五层」。
3. **A 与现有渲染结构最接近。** 当前菜单本来就是「一份 `_menuSpec()` + 一个绘制入口」，A 只是在同一画布上先画场景再画栏，`main.js` 菜单分支可以完全不动；B/C 需要新的全屏场景层和更复杂的文本/遮罩排版。
4. **A 的短板可以用 B 的长处补。** 在 A 的双扇门中缝加一条 2px 暖光（不改变布局，只加一条渐变线），既保留暗栏的可读性，又借到 B「门后有光」的叙事。C 的火把光晕可以只作为 A 的局部光源参考，不建议整屏照搬。

**结论：** 三选一选 A；如果允许做第四版，做「A 的版式 + B 的门缝光 + C 的火把光晕」的合并稿，而不是在 B/C 里二选一。
